# 微信小程序服务器部署、备案与异地内测手册

> 适用项目：`D:\stem-app`（uni-app + Node.js/Express + PostgreSQL）  
> 核验日期：2026-08-25（中国大陆，腾讯云主路线）  
> 目标：先让异地同事使用“体验版”审核，再完成备案、合规检查和正式发布。

本文按当前仓库的真实情况编写，不是通用模板。腾讯云、微信公众平台的控制台菜单偶尔会改名；如果页面名称与本文略有不同，以控制台当时显示和文末官方链接为准。

## 一、先看结论

推荐路线是：

1. 先确定统一的备案主体；
2. 在腾讯云购买中国大陆轻量应用服务器、注册域名，并立即提交网站 ICP 备案；
3. 备案等待期间完成服务器安装、生产环境配置和合规整改，但不要用未备案域名公开提供服务；
4. ICP 备案通过后，配置 `api.<你的域名>`、HTTPS 和微信“request 合法域名”；
5. 上传体验版，把同事加为体验成员。此后同事无论在哪个网络都能审核；
6. 根据反馈修正，再完成小程序备案、隐私指引、AI 合规、公测检查和微信审核；
7. 审核通过后手动发布正式版。

正式链路应当是：

```text
同事/老师的微信
      │ HTTPS
      ▼
https://api.example.com/v1
      │
      ▼
Nginx :443 ──反向代理──> Node/Express :3000（仅本机可访问）
                              │
                              ├── PostgreSQL（同机，内测阶段）
                              ├── DeepSeek 官方 API
                              ├── MiniMax 官方 API（如启用配图）
                              └── 微信登录与内容安全接口
```

不要把 `3000`、`5432` 端口直接暴露到公网；不要把 AppSecret、模型 API Key 或数据库密码写进前端、Git 或截图。

如果今天就要让异地同事先看界面，可以把仓库中的 `prototype/` 文件夹压缩后发给对方，对方双击 `prototype/index.html` 即可。它使用内置数据快照，不需要服务器，也不会接触真实资料；但它只能用于界面和流程评议，不能证明微信登录、网络域名、内容安全或真实 AI 链路可用。正式功能审核仍应等备案 HTTPS 后使用体验版。微信虽允许开发工具或手机“开发调试”临时跳过域名校验，但这会掩盖生产域名、TLS 和构建配置错误，不应作为异地验收方案；依据见微信官方[网络与服务器域名要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)的“跳过域名校验”说明。

## 针对“朋友公司主体 + 外部开发者”的补充

如果小程序由朋友的公司作为主体、你负责技术开发，最稳妥的安排不是让朋友把账号密码和证件都发给你，而是：公司保留主体、主账号和最终发布权，把你的微信和腾讯云账号添加为有范围限制的协作成员。你仍然可以用自己的微信扫码登录公众平台和开发者工具。

### 1. 扫码登录不等于拥有权限

朋友公司的小程序管理员先执行：

```text
微信公众平台 → 用户身份/成员管理 → 添加项目成员
```

添加你的微信号，并至少授予：

- 登录；
- 开发者权限；
- 体验者权限；
- 开发管理（上传后的版本管理、提审等，按双方约定）；
- 开发设置（AppID/AppSecret、服务器域名等）；
- 腾讯云管理/云开发管理（如果后台提供该权限项）。

“数据分析”仅在你确实需要排查线上指标时授予；支付、广告、暂停服务、成员管理等权限不应为了省事全部打开。项目成员可以用自己的微信扫码登录，无需借用朋友的微信；管理员仍由公司人员持有。微信的协同模型区分项目成员和体验成员，并允许管理员逐项分配开发、登录、开发管理和开发设置权限，参见[小程序协同工作说明](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)。如果该官方页面路径调整，以公众平台“成员管理”实时权限项为准。

朋友不要把以下内容直接发给你：微信账号密码、微信登录二维码、腾讯云主账号密码、法人的微信密码。身份验证需要朋友或法定代表人操作时，由本人在官方页面扫码、人脸核验或收短信。

### 2. 你需要朋友提供的信息和材料

分成“可以给开发者的普通资料”和“应由本人在平台填写的敏感资料”。

可以通过公司邮件或项目文档提供给你：

| 资料 | 用途 |
|---|---|
| 公司营业执照上的完整名称、统一社会信用代码、注册地址 | 核对主体、备案和隐私政策名称 |
| 法定代表人姓名 | 核对主体；通常不需要把身份证照片长期交给开发者 |
| 小程序 AppID、当前名称、主体、认证状态、小程序备案状态和备案号 | 核对代码、账号和上线门槛 |
| 公司批准使用该小程序名称、Logo、域名和服务内容的书面确认 | 防止日后发生品牌和职责争议 |
| 域名、注册商/DNS 服务商、到期日、实名认证主体 | 判断域名能否使用 |
| 域名现有 ICP 备案号、备案主体、接入服务商 | 判断是否需要腾讯云接入备案 |
| 公司公开的隐私/投诉联系人和邮箱 | 写入隐私指引和用户协议 |
| 公司同意使用的 AI 服务商、云服务商及数据范围 | 确定隐私披露和采购责任 |

应由朋友、法定代表人或公司备案负责人直接在官方平台填写/核验，而不是在微信聊天中长期转发给你：

- 营业执照高清原件图；
- 法定代表人、主体负责人或小程序负责人身份证正反面；
- 本人手机号、短信验证码；
- 人脸核验；
- 盖公章的负责人授权书、承诺书；
- 对公账户资料（仅在认证流程当时确实要求时）；
- 公司主账号密码和主账号 SecretKey。

你可以把页面填到需要确认的前一步，然后共享屏幕让本人核验；也可以由公司指定员工全程负责备案，你只提供 AppID、域名、IP/云环境和技术说明。

### 3. 朋友必须亲自或以公司身份完成的工作

| 工作 | 谁完成 | 说明 |
|---|---|---|
| 把你的微信添加为小程序项目成员并授权 | 当前小程序管理员 | 这是你用自己的微信扫码登录的前提 |
| 确认公司允许以其名义运营、收集教师数据和提供 AI 功能 | 公司负责人 | 公司是对外责任主体，不能只做“借号” |
| 小程序认证、主体核验、管理员变更等公司验证 | 管理员/法定代表人 | 需要扫码、人脸或企业材料时必须配合 |
| 小程序备案的主体与负责人确认 | 公司备案负责人/法定代表人 | 你可以代填技术信息，但不要未经书面授权把自己填成备案负责人 |
| 域名所有权、ICP 备案和接入备案确认 | 公司域名/备案负责人 | 域名实名和备案主体应与公司一致 |
| DNS 验证和 API 子域名记录 | 公司域名管理员，或给你最小 DNS 权限 | 不需要给你域名注册商主密码 |
| 腾讯云主账号实名认证和生产资源付款 | 公司 | 推荐生产云资源归公司账号 |
| 把你添加为腾讯云 CAM 子账号/协作者 | 腾讯云主账号管理员 | 只授权目标 CloudBase 环境和必要资源 |
| 审批隐私政策、用户协议、AI 模型公示 | 公司负责人/法务或伦理负责人 | 文案代表公司作出承诺 |
| 最终发布或书面授权你发布 | 公司小程序管理员 | 建议首版由公司人员做最后一次发布确认 |

不同省份对“非法定代表人担任备案负责人”的要求不同，平台可能要求授权书、公章、本人核验或直接要求法定代表人担任。以备案页面针对公司注册地实时给出的材料为准。

### 4. AppSecret 和各类密钥怎么交接

推荐做法：

1. 你获得“开发设置”权限后，在公众平台生成 AppSecret；
2. 当场把它写入生产环境的加密环境变量或腾讯云密钥管理；
3. 公司指定一名管理员在公司的密码管理器中留存备份；
4. 不在聊天、邮件正文、Git、前端代码或截图中传播；
5. 项目结束时由公司重置 AppSecret、模型 API Key 和你的云 API 密钥。

DeepSeek、MiniMax 等模型账号也建议以公司名义注册和充值。若内测暂用你的个人模型账号，要有书面同意，并在正式上线前切换到公司控制的账号。

### 5. 已有域名需要朋友确认的四件事

让朋友从域名/备案控制台给出以下结果，不只是口头说“有域名”：

```text
域名：________________________
域名实名持有人：______________
ICP备案号与主体：_____________
当前接入服务商：______________
```

判断：

- 实名持有人和 ICP 主体都是朋友公司，且备案已接入腾讯云：可直接规划 `api.<公司域名>`；
- 域名已备案，但接入商是阿里云等其他服务商，而 API 要放在腾讯云：通常还需办理腾讯云“接入备案”，原接入不必因此注销；
- 域名实名在朋友个人、另一家公司或备案已失效：不要直接使用，先变更实名/备案或换公司域名；
- 根域名已完成有效备案：通常其 `api.` 子域名无需单独再办一份网站备案，但实际接入腾讯云仍要满足腾讯云接入核验。

腾讯云说明，域名从其他接入商迁到腾讯云服务时需要办理接入备案，见[接入备案指引](https://cloud.tencent.com/document/api/243/37403)。

### 6. `cloud1-d2gq6r8wb670ae313` 不是一台服务器

这个格式是 CloudBase 环境 ID。环境是资源和计费隔离单位，可能包含云托管、数据库、云存储、云函数等，但仅有环境 ID 不能证明这些资源已经开通。官方定义见[CloudBase 环境说明](https://cloud.tencent.com/document/product/876/46895)。

在继续部署前，登录 [CloudBase 控制台](https://tcb.cloud.tencent.com/dev)，记录：

```text
腾讯云主账号 UIN：____________
主账号实名主体：_______________
环境 ID：cloud1-d2gq6r8wb670ae313
环境来源：微信开发者工具创建 / 腾讯云侧创建
关联小程序 AppID：____________
地域：_________________________
套餐与到期日：_________________
云托管：已开通 / 未开通
PostgreSQL：已开通 / 未开通
云存储：已开通 / 未开通
HTTP 访问服务默认域名：_________
```

必须核对两组一致性：

1. 关联 AppID 与 `frontend/src/manifest.json` 中的 AppID一致；
2. 生产环境的腾讯云主账号实名主体是朋友公司。

如果环境买在你的个人腾讯云账号下：可以暂时作为不含真实数据的开发测试环境，但不建议作为公司正式生产环境。CloudBase 官方说明环境不支持跨账号迁移；正确做法通常是在公司实名认证的腾讯云主账号下新建生产环境，再把代码和非敏感配置重新部署过去。参见[CloudBase 环境相关问题](https://cloud.tencent.com/document/faq/876/18438)。

公司无需把腾讯云主账号交给你。让主账号在 CAM 中把你的腾讯云账号添加为“协作者”或微信子用户，再按环境授予最小权限。腾讯云也明确建议不要用主账号做日常操作，参见[CloudBase 权限管理](https://cloud.tencent.com/document/product/876/47055)和[新建协作者](https://cloud.tencent.com/document/product/598/36618)。TCB 预设策略权限较宽，能按环境写自定义策略时优先按环境授权。

### 7. 这个环境能否直接承载当前项目

当前代码不能仅填环境 ID 就上线：

- 后端是完整的 Express 常驻服务，需要部署到 CloudBase 云托管容器；
- 仓库当前没有 Dockerfile 或 CloudBase 部署配置；
- 数据层使用 PostgreSQL 和 21 份 PostgreSQL 迁移，不能直接切到 CloudBase 文档数据库或 MySQL；
- 当前本地图片存盘方式不适合 Serverless 容器，必须改用云存储/COS；
- 前端当前使用 `uni.request`，若要使用微信云托管免域名的私有协议，需要把请求适配层改为 `wx.cloud.callContainer`。

有两条可选路线：

| 路线 | 优点 | 需要做的改造 |
|---|---|---|
| 微信云托管私有调用 | 小程序调用云托管时可不配置自有 API 域名，减少服务器和域名环节 | 环境必须与该小程序正确关联；增加容器配置；改请求层为 `wx.cloud.callContainer`；开通 PostgreSQL 和云存储 |
| CloudBase 公网 HTTPS API | 保留现有 `uni.request` 和 `/v1` 接口形状，H5/其他客户端也能调用 | 云托管容器 + PostgreSQL + 云存储；绑定已备案的公司自定义域名、SSL 和 HTTP 路由 |

微信小程序专用、希望少维护域名时，第一条更省后续运维；计划继续支持 H5 时，第二条更通用。微信云托管私有调用的官方说明见[小程序访问云托管](https://docs.cloudbase.net/run/develop/access/mini)；CloudBase 公网默认域名仅适合测试，生产需绑定备案自定义域名，见[HTTP 访问服务](https://cloud.tencent.com/document/product/876/130728)。

在确认环境归属和关联 AppID 之前，不要继续购买 Lighthouse，也不要开始迁移真实数据。

## 二、当前项目的上线阻塞项

在购买云资源前先知道这些事实，能避免“服务器买好了但体验版仍不能用”。

| 项目 | 当前仓库状态 | 必须怎么处理 |
|---|---|---|
| 小程序 AppID | `frontend/src/manifest.json` 已有 AppID | 核对它与微信公众平台中的目标小程序完全一致 |
| 后端微信配置 | 本地 `.env` 仍是占位 AppID/Secret | 在线上服务器填真实 AppID 和 AppSecret |
| 前端生产 API | `frontend/.env.production` 仍是局域网 HTTP IP | 构建前覆盖为备案后的 HTTPS API 域名 |
| 假登录 | 前后端当前均启用 | 线上必须 `NODE_ENV=production`、`DEV_FAKE_LOGIN=false`、`VITE_DEV_FAKE_LOGIN=false` |
| 微信内容安全 | 当前关闭，且尚未完成真机验证 | 线上必须启用并完整实测输入、AI 输出及修改资料等路径 |
| 图片存储 | `imageStore.js` 的 COS 上传仍是 TODO | 异地内测可在单机服务器用本地磁盘；正式上线前接 COS，或暂时关闭配图 |
| 图片模型 | 当前本地环境含 12ai 中转模型 | 正式上线不要依赖来源/备案不清楚的中转；优先直连已备案的大陆模型服务商 |
| 隐私说明 | 页面写有“不把数据给任何第三方” | 这与数据会发送给微信内容安全、DeepSeek、图片模型及云服务商的事实不一致，提审前必须重写 |
| AI 标识 | 当前未发现完整的显式/隐式标识实现 | 提审前给文本和图片加显著 AI 标识；下载文件还要核验隐式元数据标识 |
| Node.js | 旧文档指定 Node 20 | Node 20 已于 2026-03-24 EOL，线上改用 Node 24 LTS |

其中前四项不完成，异地体验版大概率会直接显示网络或登录错误；后四项不完成，不应公开发布。

## 三、阶段 0：先确定主体，暂时不要付款

备案最常见的返工原因不是技术，而是主体不一致。先在微信公众平台查看：

```text
微信公众平台 → 设置与开发/设置 → 基本设置 → 主体信息
```

然后确定下列信息由同一个主体持有：

- 微信小程序主体；
- 腾讯云账号实名认证主体；
- 域名实名认证主体；
- ICP 备案主体；
- 实际提供服务、写在隐私政策里的运营者。

腾讯云当前要求域名所有者、备案主体及账号实名信息保持一致；域名实名信息提交后还要等待工信部数据同步。详见腾讯云的[备案主体一致性说明](https://cloud.tencent.com/document/product/243/53792)和[备案域名准备要求](https://cloud.tencent.com/document/product/243/18905)。

选择建议：

| 情况 | 建议 |
|---|---|
| 只是本人长期维护、明确不商业化且当前小程序就是个人主体 | 可以继续个人主体，但要先在微信当前开放类目里确认功能可发布 |
| 这是学校、课题组、公司或合作园项目，会长期收集教师身份与研究数据 | 优先使用实际负责运营的单位主体，并取得单位授权 |
| 当前 AppID 是个人主体，但准备改为单位运营 | 先解决小程序主体迁移/重新注册，再买域名和备案；不要先用个人名义备案后再返工 |

本项目是教师工作工具，不直接给儿童授课。按当前功能推断，“工具 → 办公”通常比“教育培训”更贴近实际，但这只是项目判断，不是平台预审结论。提交时必须打开微信最新的[小程序开放服务类目](https://developers.weixin.qq.com/miniprogram/product/material.html)，以主体可选范围、功能实质和平台客服答复为准；不要只因为产品名称含“幼儿园”就盲选教育类目。

完成标准：把以下内容写在自己的上线记录中。

```text
小程序主体：________________
腾讯云实名主体：____________
域名持有人：________________
ICP备案主体：_______________
服务类目（待平台确认）：____
```

五项不一致时先停下处理主体问题。

## 四、阶段 1：购买腾讯云资源和域名

### 1. 注册并实名认证腾讯云账号

主体必须使用上一阶段确定的个人或单位。开启登录保护和多因素认证；主账号只用于管理，不要把主账号密码交给同事。

### 2. 购买轻量应用服务器

进入“轻量应用服务器 Lighthouse → 新建”，建议：

- 地域：中国大陆，选靠近主要体验者的北京、上海、广州、成都或南京；
- 镜像：Ubuntu 24.04 LTS 系统镜像；
- 规格：内测从 2 核 4 GB、60 GB 系统盘起；
- 公网：保留固定公网 IPv4；
- 时长：至少 3 个月，且备案期间剩余有效期不少于 1 个月；
- 登录：优先 SSH 密钥，保存好私钥；
- 快照：开启或定期手动创建。

腾讯云当前规定，用 Lighthouse 申请备案需购买中国大陆实例、包年包月累计至少 3 个月。参见[备案云资源要求](https://cloud.tencent.com/document/product/243/18908/)和[轻量服务器 Linux 快速入门](https://cloud.tencent.com/document/product/1207/44548)。

内测阶段采用“单台 Lighthouse + 本机 PostgreSQL”是最低复杂度方案。开始存储真实教师数据后，应至少做异机备份；用户量或数据价值上升时，再迁移到同地域的托管 PostgreSQL。不要在没有备份的情况下把唯一数据库放在一块系统盘上。

### 3. 配置云防火墙

只开放：

| 端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | 你当前的固定公网 IP；无法固定时只在维护期间临时开放 | SSH |
| TCP 80 | `0.0.0.0/0` | 证书签发和 HTTP 跳转 |
| TCP 443 | `0.0.0.0/0` | 小程序 HTTPS API |

不要开放 `3000` 和 `5432`。检查方法以腾讯云[轻量应用服务器防火墙文档](https://cloud.tencent.com/document/product/1207)为准。

### 4. 注册域名并完成实名认证

建议在同一个腾讯云账号注册一个简短的 `.com` 或 `.cn` 域名，并预留：

```text
example.com       项目介绍、ICP备案号和隐私联系方式
www.example.com   可选，跳转到主域名
api.example.com   小程序 API
```

先创建并通过“域名信息模板”实名审核，再注册域名。域名所有者必须与备案主体一致。腾讯云说明模板和命名审核一般需要 1—3 个工作日；域名实名通过后，腾讯云注册域名需满 3 个自然日才能提交备案。参见[域名注册与实名认证](https://cloud.tencent.com/document/product/242/39039)和[备案限制说明](https://cloud.tencent.com/document/product/243/18911)。

完成标准：已经记录服务器公网 IP，域名控制台显示实名认证通过，服务器订单满足备案时长。

## 五、阶段 2：完成网站/域名 ICP 备案

这里办理的是让大陆服务器和域名合法提供互联网服务的“网站 ICP 备案”，不是微信小程序自身的备案。后者要在微信公众平台另办。

### 1. 备案前准备

准备：

- 个人身份证，或单位证件、法定代表人/负责人证件；
- 已实名认证并同步满 3 天的域名；
- 符合要求的 Lighthouse；
- 真实通信地址、手机、邮箱；
- 项目名称、用途和服务说明；
- 如所在省管局要求，准备授权书或前置审批文件。

材料随省份和主体类型不同，以腾讯云当时给出的[备案所需材料](https://cloud.tencent.com/document/product/243/18914)和“各省管局要求”为准。

### 2. 提交备案

进入腾讯云“ICP 备案 → 开始备案”，选择：

- 首次备案：主体和域名都从未备案；
- 新增网站：主体已有备案，本域名/网站是新的；
- 接入备案：域名已在其他接入商备案，现在迁到腾讯云。

本项目建议按“网站”备案主域名 `example.com`，服务内容如实写成面向幼儿园教师的教案辅助工具/项目介绍，不要写成新闻、论坛、在线培训或医疗服务。填写名称必须与页面实际内容一致。

提交后一般会经历：腾讯云初审 → 信息核验 → 工信部短信核验 → 省通信管理局审核。收到工信部短信后需在 24 小时内完成核验。腾讯云说明管局审核时限通常不超过 20 个工作日，但各省实际时间不同。完整步骤见[腾讯云快速备案指引](https://cloud.tencent.com/document/product/243/39038)。

### 3. 备案等待期间可以做什么

可以：

- 只通过 SSH 安装服务器；
- 在服务器本机用 `curl http://127.0.0.1:3000/healthz` 测试；
- 准备 Nginx 配置、隐私政策、体验名单和审核材料；
- 完成代码测试。

不要：

- 把未备案域名解析到大陆服务器并公开提供服务；
- 在备案首页放与备案描述不一致的内容；
- 为了抢时间使用虚假主体、虚假用途或他人的备案号。

### 4. 备案通过后

保存：

```text
ICP备案号：________________
通过日期：_________________
备案主体：_________________
备案域名：_________________
```

在 `example.com` 的公开介绍页底部展示备案号，并链接到[工信部备案管理系统](https://beian.miit.gov.cn/)。只有 API、没有面向用户网页的情形是否需要公安联网备案，各地执行可能不同；腾讯云当前说明“仅提供 API、没有用户网页内容”可暂不办理，但正式开放网页或 APP 后应在 30 日内核实办理。可参见公安部的[《计算机信息网络国际联网安全保护管理办法》](https://ispl.mps.gov.cn/ispl/jsp/bulletin/BulletinView.jsp?bulletinID=0b76853f-f169-4bfc-a53f-49fe7fc91da8)及腾讯云[公安联网备案指引](https://cloud.tencent.com/document/product/243/19142)。

## 六、阶段 3：部署后端

以下命令以腾讯云 Ubuntu 24.04、默认用户 `ubuntu` 为例。把示例域名和密码换成自己的值；不要把尖括号原样复制。

### 1. 登录并更新系统

在本机 PowerShell：

```powershell
ssh ubuntu@<服务器公网IP>
```

进入服务器后：

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt install -y git nginx postgresql postgresql-contrib snapd
sudo timedatectl set-timezone Asia/Shanghai
```

### 2. 安装 Node.js 24 LTS

Node.js 官方在 2026-08 将 v24 列为 LTS，而 v20 已停止维护；线上不要继续使用 v20。先在 [Node.js 官方下载页](https://nodejs.org/en/download)核对当日命令，再安装官方页面提供的 nvm 和 Node 24：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.6/install.sh | bash
. "$HOME/.nvm/nvm.sh"
nvm install 24
nvm alias default 24
node -v
npm -v
```

`node -v` 应显示 `v24.x.x`。Node 各版本状态见[官方发布周期](https://nodejs.org/en/about/previous-releases)。

### 3. 创建数据库

先生成一个只含十六进制字符的数据库密码，避免连接串转义问题：

```bash
openssl rand -hex 24
```

复制输出，进入 PostgreSQL：

```bash
sudo -u postgres psql
```

在 `psql` 中执行，替换密码：

```sql
CREATE USER stem_app WITH PASSWORD '<刚生成的数据库密码>';
CREATE DATABASE stem_app OWNER stem_app;
\q
```

数据库只监听本机，不要给云防火墙或系统防火墙开放 5432。

### 4. 拉取代码

当前仓库有 GitHub 远程地址，可以在服务器上部署已提交的代码：

```bash
sudo mkdir -p /srv/stem-app
sudo chown ubuntu:ubuntu /srv/stem-app
git clone https://github.com/linem7/stem-app.git /srv/stem-app
cd /srv/stem-app/backend
npm ci --omit=dev
```

注意：服务器只能获得已经提交、推送到 GitHub 的版本。本机工作区当前若还有未提交改动，必须先确认、提交和推送正确版本；不要把本地 `.env`、数据库备份或真实教师数据提交进仓库。

### 5. 建立线上 `.env`

```bash
cd /srv/stem-app/backend
cp .env.example .env
chmod 600 .env
nano .env
```

关键值按下表填写：

| 变量 | 线上值 |
|---|---|
| `DATABASE_URL` | `postgres://stem_app:<数据库密码>@127.0.0.1:5432/stem_app` |
| `DATABASE_SSL` | `false`（同机数据库） |
| `JWT_SECRET` | 用 `openssl rand -hex 48` 生成，至少 32 字符 |
| `WECHAT_APPID` | 与 `manifest.json`、微信公众平台一致的真 AppID |
| `WECHAT_SECRET` | 微信公众平台生成的真 AppSecret |
| `CONTENT_CHECK_ENABLED` | `true` |
| `DEEPSEEK_API_KEY` | DeepSeek 官方 API Key；首次启动会播种进数据库 |
| `ADMIN_PASSWORD` | 独立的 16 位以上强密码 |
| `NODE_ENV` | `production` |
| `DEV_FAKE_LOGIN` | `false` |
| `PORT` | `3000` |
| `PUBLIC_BASE_URL` | `https://api.example.com` |
| `TASK_CONCURRENCY` | `2` |

图片功能分两阶段处理：

- 异地小规模内测：可以只用这一台服务器的 `.local-images`，但要做磁盘备份；
- 正式上线：必须完成 `backend/src/services/imageStore.js` 中尚未实现的 COS 上传，否则不要填写 `OBJECT_STORAGE_*`，填写后当前代码会直接报“云端图片存储还在接入中”。如果暂不实现 COS，就把图片模型全部关闭，让正式版不提供配图。

如启用图片模型，建议新环境只配 MiniMax 官方大陆 API，并设 `IMAGE_PROVIDER=minimax`。不要把当前的 `cdn.12ai.org` 中转配置带到正式环境。模型配置首次播种进数据库后，后续以管理后台“模型管理”里的值为准，而不是 `.env`。

### 6. 迁移数据库并启动

```bash
cd /srv/stem-app/backend
npm run migrate
npm install -g pm2@latest
pm2 start src/server.js --name stem-api --time
pm2 save
pm2 startup
```

`pm2 startup` 会输出一条带 `sudo` 的命令；复制执行那一条，然后再次执行：

```bash
pm2 save
```

PM2 的官方流程也是 `pm2 startup` 后运行其输出命令，再 `pm2 save`，参见[PM2 启动脚本说明](https://pm2.keymetrics.io/docs/usage/startup/)。本项目只能运行一个 Node 进程，不要使用 PM2 cluster：任务队列、限流和微信 token 缓存都是进程内状态。

检查：

```bash
curl http://127.0.0.1:3000/healthz
pm2 status
pm2 logs stem-api --lines 100
```

期望健康检查返回 `ok:true`、`db:"up"`。

## 七、阶段 4：DNS、Nginx 和 HTTPS

此阶段在 ICP 备案通过后执行。

### 1. 添加 DNS 解析

在腾讯云 DNSPod 为主域名添加：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `api` | A | Lighthouse 公网 IPv4 |
| `@` | A | Lighthouse 公网 IPv4 |
| `www` | A | Lighthouse 公网 IPv4 |

DNSPod 的当前操作方法见[添加 A 记录](https://cloud.tencent.com/document/product/302/3449)。在本机验证：

```powershell
Resolve-DnsName api.example.com
```

返回的 IP 应与服务器公网 IP 一致。

### 2. 配置 Nginx 反向代理

服务器执行：

```bash
sudo nano /etc/nginx/sites-available/stem-api
```

先写 HTTP 配置：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name api.example.com;

    client_max_body_size 10m;

    # 管理后台不经公网开放；需要时走 SSH 隧道。
    location ^~ /admin {
        return 404;
    }

    location = /healthz {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location ^~ /v1/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 210s;
    }

    # 仅用于单机内测图片；接入 COS 后删除此段。
    location ^~ /local-images/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        return 404;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/stem-api /etc/nginx/sites-enabled/stem-api
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

如果 `default` 不存在，忽略该条提示即可。

主域名还要有一个真实可访问的说明页。先创建目录和页面：

```bash
sudo mkdir -p /var/www/stem-landing
sudo chown ubuntu:ubuntu /var/www/stem-landing
nano /var/www/stem-landing/index.html
```

至少写入以下信息，并替换占位内容：

```html
<!doctype html>
<html lang="zh-CN">
<head><meta charset="utf-8"><title>幼儿园 STEAM 教案助手</title></head>
<body>
  <h1>幼儿园 STEAM 教案助手</h1>
  <p>为幼儿园教师提供 STEAM 教案辅助生成与整理服务。</p>
  <p>运营者：你的个人姓名或单位全称</p>
  <p>联系邮箱：你的联系邮箱</p>
  <p><a href="https://beian.miit.gov.cn/">你的 ICP 备案号</a></p>
</body>
</html>
```

再创建站点配置：

```bash
sudo nano /etc/nginx/sites-available/stem-site
```

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;
    root /var/www/stem-landing;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/stem-site /etc/nginx/sites-enabled/stem-site
sudo nginx -t
sudo systemctl reload nginx
```

页面里的运营主体必须与备案信息一致，ICP备案号必须换成真实值。不要在这里公开管理后台、AppSecret、测试兑换码或内部联系方式。

### 3. 申请 HTTPS 证书

可以使用腾讯云 SSL 证书，也可以使用自动续期的 Certbot。以下采用 Certbot 官方推荐的 snap 安装方式：

```bash
sudo snap install --classic certbot
sudo ln -s /snap/bin/certbot /usr/local/bin/certbot
sudo certbot --nginx -d api.example.com
sudo certbot --nginx -d example.com -d www.example.com
sudo certbot renew --dry-run
```

官方步骤见[Certbot 的 Nginx 安装指引](https://certbot.eff.org/instructions?os=snap&ws=nginx)。如果使用腾讯云免费证书，要注意当前免费证书有效期为 90 天，并提前安排续签；参见[腾讯云免费 SSL 证书说明](https://cloud.tencent.com/document/product/400/89868)。

### 4. 外部验收

在自己的 Windows 电脑执行：

```powershell
curl.exe -i https://api.example.com/healthz
curl.exe -I http://api.example.com/healthz
curl.exe -I https://example.com/
```

检查：

- HTTPS 返回 200，JSON 中 `ok:true`、`db:"up"`；
- HTTP 自动跳到 HTTPS；
- 主域名说明页返回 200，运营者与ICP备案号正确；
- 浏览器证书域名正确、证书链完整、未过期；
- `https://api.example.com/admin` 从公网返回 404；
- 云防火墙中 3000 和 5432 未开放。

微信官方要求服务器域名使用 HTTPS、不能使用公网 IP 或 `localhost`、必须 ICP 备案，证书链完整且 TLS 至少支持 1.2。参见微信官方[网络与服务器域名要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

## 八、阶段 5：配置微信服务器域名和真实登录

WECHAT_APPID=真实值

项目已经调用微信文本内容安全接口，但此前没有真实 AppSecret 完整跑通，所以不能只看开关为 `true`。微信官方接口说明见[小程序安全/内容安全接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/)。

3. 用真机“预览”走一遍完整流程；
4. 点击右上角“上传”；
5. 版本号用语义化形式，例如 `0.1.0`；
6. 备注写清本次功能，例如“异地内测：真实微信登录、教案生成、改稿、教案库”。

### 4. 设置体验版并添加同事

在微信公众平台：

1. “管理 → 成员管理”中把同事的微信号加为“体验成员”；
2. 如果同事还要上传代码，再单独加为项目成员并只授予必要权限；
3. “管理 → 版本管理 → 开发版本”，把刚上传版本“选为体验版”；
4. 把体验版二维码发给同事；
5. 同事须使用被添加的同一个微信号扫码。

体验成员不需要与你在同一局域网，因为所有请求已经走公网 HTTPS。管理员默认有体验权限；体验成员只负责试用，不必给开发权限。微信的体验成员能力可参考官方成员管理接口说明：[绑定体验成员](https://developers.weixin.qq.com/doc/oplatform/openApi/miniprogram-management/member-management/api_bindtester.html)。如果官方页面调整，以微信公众平台“成员管理”的实时上限和提示为准。

### 5. 给同事准备业务权限

这个项目不是任何微信用户打开就能进入；真实登录后仍要“兑换码 + 名单位置”激活。管理员需先准备：

1. 用 SSH 隧道访问管理后台：

   ```powershell
   ssh -L 8080:127.0.0.1:3000 ubuntu@<服务器公网IP>
   ```

2. 保持窗口打开，在浏览器访问 `http://127.0.0.1:8080/admin`；
3. 后台“园所”创建“内部测试园”；
4. 后台“名单”导入同事的测试身份；
5. 后台“兑换码”生成一次性内测码，并给足测试额度；
6. 将体验二维码、兑换码和反馈表发给同事。

测试时只用虚构教案和测试身份，不输入任何儿童姓名、照片、观察记录或真实敏感信息。

## 十一、常见故障定位

| 现象 | 优先检查 |
|---|---|
| 开发者工具正常，体验版提示网络断开 | 构建产物是否仍烧入局域网 IP；微信 request 合法域名是否配置；证书链是否完整 |
| 开启开发调试才正常 | 正在绕过合法域名/TLS 校验，说明域名或证书仍未真正配置好 |
| 真机登录失败 | AppID、AppSecret、上传包 AppID 是否属于同一个小程序；服务器是否重启加载新 `.env` |
| 登录后停在待激活页 | 这是正常业务闸门；检查兑换码、园所和名单是否已准备 |
| 内容安全接口失败 | `CONTENT_CHECK_ENABLED`、access token、AppSecret、用户近期登录得到的 openid 和微信接口返回码 |
| 生成一直等待 | `pm2 logs stem-api`、模型余额、API Key、队列状态、Nginx 超时 |
| 图片生成后看不到 | 当前是否仍用本地磁盘；`PUBLIC_BASE_URL` 是否为 HTTPS；`/local-images` 是否可访问 |
| 配了 COS 后反而报错 | 当前 `imageStore.js` 的云上传仍是 TODO；先撤销 `OBJECT_STORAGE_*` 或完成代码实现 |
| 管理后台公网返回 404 | 这是预期安全行为；用 SSH 隧道访问 |
| 同事扫二维码提示无权限 | 添加的微信号是否正确、是否为体验成员、二维码是否对应当前体验版 |

## 十二、正式提审前的合规闸门

这一节不能用“先上线再补”处理。

### 1. 小程序备案

小程序属于 APP 备案管理范围，但微信小程序备案要通过微信公众平台办理，不在腾讯云的 APP 备案入口重复提交。进入微信公众平台的“小程序备案/去备案”，按页面提交主体、负责人、小程序、域名和前置审批等材料。

工信部明确：境内提供互联网信息服务的小程序应履行备案手续；参见[工信部关于开展移动互联网应用程序备案工作的通知](https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm)。腾讯云也明确说明微信小程序应到微信公众平台备案，参见[APP 备案常见问题](https://cloud.tencent.com/document/faq/243/97691)。

### 2. 微信隐私保护指引

在微信公众平台：

```text
设置 → 服务内容声明 → 用户隐私保护指引
```

按实际处理活动填写，而不是只复制小程序内的自写协议。微信官方说明，现网版本可在该入口完善，提审版本也会在提交代码审核时核对隐私接口与声明是否一致。见[用户隐私保护指引填写说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)。

本项目至少应披露：

- 运营主体和联系/投诉方式；
- 微信 OpenID、教师姓名、园所、班级、岗位；
- 对话、教案、配图、反馈、使用记录和必要日志；
- 每类数据的用途、保存位置、保存期限；
- 查询、更正、删除、注销路径；
- 数据会由腾讯云托管；
- 用户输入和 AI 输出会发送给微信内容安全接口；
- 生成请求会发送给 DeepSeek，启用配图时会发送给 MiniMax；
- 不收集儿童姓名、照片、观察记录和发展评估，并在输入框旁继续提醒；
- 数据是否用于研究、如何去标识化、退出研究的影响，以及伦理审批信息（如适用）。

当前页面的“不把你的数据给……任何第三方”与上述处理事实冲突，必须改成准确、具体、用户看得懂的表述。涉及真实研究参与者时，还应由所在机构的伦理/法务负责人复核，不要把本手册当作法律意见。

### 3. 生成式 AI 合规与标识

本项目向用户提供文本和图片生成能力，属于面向境内用户的生成式 AI 应用。正式版至少完成：

- 在“关于/协议/模型信息”页面显著展示实际使用的模型名称和备案号；
- 每份教案显示“AI 生成，仅供教师备课参考，请结合幼儿实际情况核验”；
- 每张 AI 配图在预览与导出时显示“AI 生成”；
- 按现行强制标准核验下载图片及导出文件的隐式元数据标识，不能假定模型供应商返回的字节已经合规；
- 不允许用户删除、遮挡或伪造法定标识；
- 保留投诉举报入口、处理流程和必要的安全日志；
- 确认所调用模型仍在国家网信办最新备案/登记清单中。

国家网信办要求已上线的生成式 AI 应用在显著位置或产品详情页注明所使用模型名称及备案号，见[生成式人工智能服务备案公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)；《人工智能生成合成内容标识办法》及配套强制标准已自 2025-09-01 施行，见[官方发布说明](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)。

DeepSeek 官方当前公示 `Deepseek Chat` 生成式 AI 服务备案号为 `Beijing-DeepseekChat-202404280016`，算法备案号为 `网信算备110108970550101240011号`，但提审前仍应在其[官方模型公示页](https://cdn.deepseek.com/policies/zh-CN/model-algorithm-disclosure.html)再次核对。MiniMax 的具体模型和备案号也要在供应商官方页面及国家网信办最新清单中核对后再写入产品，不能只凭本地配置名称推断。

是否需要以本项目主体另行履行生成式 AI/算法备案或安全评估，取决于服务方式、公众开放范围及是否具有舆论属性或社会动员能力。内测不等于自动豁免，公开发布前应向属地网信部门或专业合规人员书面确认。《生成式人工智能服务管理暂行办法》明确了面向境内公众提供服务、输入记录保护、投诉机制及相应备案义务，见[官方全文](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。

### 4. 服务类目和功能完整性

- 服务类目必须与实际功能一致；
- 名称、头像、简介、截图和介绍完整；
- 不出现“测试版”“功能开发中”等无法使用的核心入口；
- 模型余额和服务器容量足以让审核员完成全流程；
- 所有核心功能需要登录/兑换码时，提审备注必须提供有效测试路径。

### 5. 给微信审核员准备专用入口

提前创建：

- 一个“微信审核测试园”；
- 一条不含真实个人信息的测试名单；
- 一个有效的一次性兑换码；
- 足够完成至少 3 次教案和 1 次改稿的额度；
- 30—60 秒的完整操作录屏链接（如提审页面允许提供）。

提审备注示例：

```text
本小程序为幼儿园教师的 STEAM 教案辅助工具。
首次进入会自动使用微信登录，然后进入兑换码激活页。
审核兑换码：XXXXXXXX（有效至 YYYY-MM-DD，剩余额度 10 次）
操作路径：首页输入活动想法 → 回答 4 个问题 → 生成教案 → “改一改”。
生成通常需要 15—30 秒，用户可离开页面后再返回查看。
测试数据均为虚构，不涉及儿童个人信息。
```

兑换码必须在提交前亲自用另一个微信号验证，但不要提前消耗到失效。

## 十四、上线后的最低运维动作

### 日常检查

```bash
pm2 status
pm2 logs stem-api --lines 100
df -h
curl -fsS https://api.example.com/healthz
```

### 更新代码

选择低使用时段：

```bash
cd /srv/stem-app
git fetch origin
git pull --ff-only
cd backend
npm ci --omit=dev
npm run migrate
pm2 restart stem-api --update-env
curl -fsS http://127.0.0.1:3000/healthz
```

每次更新前先备份数据库。不要在服务器上直接改业务代码，否则下一次 `git pull` 容易冲突，也无法追溯上线版本。

### 备份底线

- PostgreSQL：每天一次完整备份，保留至少 7 个日版本和 4 个周版本；
- 图片：接入 COS 后启用版本控制/生命周期，并备份必要索引；
- 备份必须存到另一项云存储或另一台机器，不能只留在同一系统盘；
- 每月至少做一次“从备份恢复到临时数据库”的演练；
- 备份含教师身份、对话和模型密钥时必须限制权限并加密。

第一次上线就先建立备份目录并手动备份一次：

```bash
sudo install -d -m 700 -o postgres -g postgres /var/lib/postgresql/stem-backups
sudo -u postgres pg_dump -Fc -f "/var/lib/postgresql/stem-backups/stem_app_$(date +%Y%m%d_%H%M%S).dump" stem_app
sudo -u postgres ls -lh /var/lib/postgresql/stem-backups
```

定时任务和异地加密上传应在上线当周完成。只看到 `.dump` 文件还不算验证成功；用其中一份做临时恢复测试：

```bash
sudo -u postgres createdb stem_restore_test
sudo -u postgres pg_restore -d stem_restore_test /var/lib/postgresql/stem-backups/<选择一份.dump>
sudo -u postgres psql -d stem_restore_test -c "SELECT COUNT(*) FROM teachers;"
sudo -u postgres dropdb stem_restore_test
```

`stem_restore_test` 必须是专门创建的临时库，绝不能把恢复测试指向生产库 `stem_app`。

### 监控和告警

至少配置：

- HTTPS 健康检查失败；
- CPU、内存、磁盘使用率；
- PM2 进程反复重启；
- PostgreSQL 连接失败；
- DeepSeek/MiniMax 余额与调用错误；
- TLS 证书到期；
- 单用户异常高频生成和内容安全失败。
