# 幼儿园 STEAM 教案助手

帮中国大陆幼儿园老师写 STEAM 教案的微信小程序。老师说一句话（"我想做个浮与沉的活动"），
AI 分三轮引导提问（**一共只问 5 题**）、每题附可点选的推荐答案，最后生成一份结构完整、**真正适合这个年龄班**的教案。觉得哪里不对，说一句就能让它重写。

非商用，作者带着 Claude 独立开发。

---

## 先看这个：可点击原型

打开 [`prototype/index.html`](prototype/index.html)（双击就行，没有任何依赖）。

能真的打字、选 A/B/C/D、一题题走完三轮、看着教案生成出来，再对着成稿说「哪里不对」让它重写。
**屏幕里的问题、推荐答案、三份教案正文和那一轮改稿，都是后端接 DeepSeek 真实跑出来的**，不是占位文案。

建议这么走一遍：

1. 首页输入想法 → 第 1 题**选小班** → 5 题走完 → 看生成过程 → 看成稿
2. 在成稿页点**「哪里不对？改一改」**，提一句意见，看它再问你三个**新**问题然后整份重写
3. 用左侧导航跳回引导，第 1 题**改选中班或大班**，对比同一套代码给三个班写出的东西差多少

对比时重点看这几行：

| | 小班 | 中班 | 大班 |
|---|---|---|---|
| 时长选项 | 只有 15 / 20 / 25 分钟 | 25 / 30 / 35 | 30 / 40 / 45 |
| 教学环节 | 3 个 | 4 个 | 4 个 |
| 学习指标 | 2 条 | 3 条 | 4 条 |
| STEAM 的 E（工程） | 虚线框「刻意不做」+ 一句理由 | 改进手影造型 | 完整的调整–测试–改进循环 |

**最后一行是这个产品的核心。** 小班的 STEAM 不必五域齐全，规则是宁可诚实标注缺席，
不要为了显得完整而硬凑——那会写出「统计浮沉数量并绘制条形图」这种 3–4 岁根本做不到的活动。

原型不连后端（静态页面，后端在作者本机），所有交互走内置的真实数据快照。
没做的功能（配图出图、导出 Word）都如实标注，不假装完整。

## 本地把后端跑起来

需要 Node 20+ 和 PostgreSQL 14+。

```bash
cd backend
npm install

# 建库（PostgreSQL 装好之后）
createdb -U postgres stem_app

# 配环境变量
cp .env.example .env
#   DATABASE_URL   本地形如 postgres://postgres:你的密码@localhost:5432/stem_app
#   JWT_SECRET     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
#   DEEPSEEK_API_KEY  platform.deepseek.com 申请，要先充一点余额
#   WECHAT_APPID / WECHAT_SECRET  还没申请就填占位值，配合 DEV_FAKE_LOGIN=true

npm run migrate     # 建表，幂等，可以重复跑
npm start
```

启动时会自检：缺哪个环境变量、去哪申请，都用中文列出来，不抛英文栈。

### 跑一遍完整链路

```bash
npm run smoke 小班      # 或 中班 / 大班
SEED="我想做个影子的活动" TEACHER=dev:mid001 npm run smoke 中班

# 重新生成原型用的数据快照（三个班 + 一轮改稿）
node scripts/export-prototype-data.mjs
```

假登录 → 开会话 → 答完 5 题 → 生成教案 → 打印年龄班硬校验结果。
改完提示词之后重跑它，就能看出教案质量有没有变化。

**这个脚本验证的不是代码能跑，而是 AI 生成的教案是否真的适龄可用**——那是整个产品最大的未知数。

## 年龄班规则是怎么真正生效的

那本台湾 STEAM 教材的案例默认孩子会言语预测、会读量杯刻度、能小组分工，这是中大班的能力。
3–4 岁小班做不到。光把规则写进提示词不够——提示词是概率约束，不是保证。所以做了三层：

1. **只注入当前年龄班的规则**。三个班一起给，模型会挑最丰富的那套，这是给小班写出大班活动的根因
2. **时长选项由代码从参数表算**，不问模型。选小班，界面上根本不出现 45 分钟这个选项
3. **生成后代码硬校验**（`enforceAgeBand`）。小班出现量杯读数、预测环节、统计图表、小组分工、
   缺误食风险 → 记入 `quality_self.age_band_violations`；超时长直接收敛回上限

第三层用故意踩满红线的样本反向测过，8 条全抓得到。所以真实生成时报「零违规」是真结果，
不是校验器在空转——这个区别很重要，因为字段名对不上时两者看起来一模一样。

## 技术选型

| | 选了什么 | 为什么 |
|---|---|---|
| 平台 | 微信小程序 | 老师在微信里，装 APP 的转化率太低。需 ICP 备案 |
| 文本模型 | DeepSeek | 用户在大陆，OpenAI 的 IP 不通 |
| 图片模型 | MiniMax image-01 | 同上。原定豆包，因为它要手写火山引擎签名机制 V4，调不通没法排查；MiniMax 一个 Bearer token 就能 curl 验证 |
| 后端 | Node 20 + Express + 原生 JS | 不用 TypeScript、不用 ORM、不用 Docker、不上微服务 |
| 数据库 | PostgreSQL + `pg` + 手写 SQL | 查询就十几条，SQL 直接可读，出问题能整句复制到 psql 里跑 |
| 知识库 | 只做框架提炼，**不做全文 RAG** | 规避版权，原书 PDF 不入库 |

完整理由见 [`docs/adr/ADR-001-technology-stack.md`](docs/adr/ADR-001-technology-stack.md)。

## 现在做到哪了

**能跑的**

- 后端最小链路全通：假登录 → 开会话 → 答完 5 题 → 异步生成 → 轮询 → 取成稿
- 改一改：对成稿提意见 → AI 提 3 个**新**问题（不重复问过的）→ 整份重写、version+1
- 六张表建好，迁移幂等
- 年龄班差异化经实测验证真实生效（见上表）
- 记忆自动提取与合并，单人最多 10 条
- 可点击原型

**还没做的**

- 前端 uni-app 一行没写
- MiniMax 已接通，但账户余额不足，**实际出图没验证过**（链路其余部分都通了）
- 导出 docx、云对象存储（没配时图片存本地，只在单机成立）
- 微信内容安全 `msgSecCheck` 因为没有真 AppID，**一次都没真正调通过**（本地靠开关绕过）
- ICP 备案、各平台账号

**待验证的假设**

- 小班的时长上限和循环次数是按发展常识推的，**需要真实小班老师复核**
- 引导砍到 5 题后，AI 自己定的那六项（材料/流程/提问/安全/评估/延伸）质量是否够用
- 教案质量目前只有 3 个样本（三个班各一），需要更大范围内测

## 几条不能破的线

- API key 只在服务端，任何情况不下发到小程序
- 老师输入和 AI 输出都要过微信 `msgSecCheck`，小程序有 UGC 不做内容安全审核过不了
- **不存幼儿的任何信息**，也不存老师手机号和真实姓名
- 每答一题即落库——老师在幼儿园随时被叫走，进度不能丢
- 生成要 15–30 秒，必须异步且**能离开**，不能要求盯着屏幕等
- 改接口先改 `docs/design/api-spec.md`，改配色只改 `docs/design/design-tokens.md`
