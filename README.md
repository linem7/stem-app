# 幼儿园 STEAM 教案助手

帮中国大陆幼儿园老师写 STEAM 教案的**手机网页应用**。老师说一句话（"我想做个浮与沉的活动"），
AI **一屏问 4 个问题**、每题附可点选的推荐答案，最后生成一份结构完整、**真正适合这个年龄班**的教案。觉得哪里不对，说一句就能让它重写。

非商用，作者带着 Claude 独立开发，同时是一个研究项目。

> 2026-08-30 从微信小程序转向 web 端，理由是甩掉「借企业主体」。
> 决定与全部代价见 [`docs/adr/ADR-002-pivot-to-web.md`](docs/adr/ADR-002-pivot-to-web.md)。

## 先看这个：可点击原型

打开 [`prototype/index.html`](prototype/index.html)（双击就行，没有任何依赖）。

能真的打字、选 A/B/C/D、一屏答完 4 题、看着教案生成出来，再对着成稿说「哪里不对」让它重写。
**屏幕里的问题、推荐答案、三份教案正文和那一轮改稿，都是后端接 DeepSeek 真实跑出来的**，不是占位文案。

建议这么走一遍：

1. 首页输入想法 → 一屏 4 题**选小班**答完 → 看生成过程 → 看成稿
2. 在成稿页点**「哪里不对？改一改」**，提一句意见，看它再问你三个**新**问题然后整份重写
3. 用左侧导航跳回引导，**改选中班或大班**，重点看第 3 题「打算在哪里做」—— 场地选项会整套换掉

对比时重点看这几行：

| | 小班 | 中班 | 大班 |
|---|---|---|---|
| 时长（不问，由年龄班定） | 20 分钟 | 25 分钟 | 30 分钟 |
| 教学环节 | 3 个 | 4 个 | 4 个 |
| 学习指标 | 2 条 | 3 条 | 4 条 |
| STEAM 的 E（工程） | 虚线框「刻意不做」+ 一句理由 | 让影子变长变短的方法 | 设计并改进高塔结构 |
| 场地选项（同一主题） | 教室科学区角 / 走廊 / 户外玩水区 | 教室区角（光线可控）/ 走廊 / 户外空地 | 教室区角 / 走廊大厅 / **户外操场（风大，挑战稳定性）** |

**最后一行是这个产品的核心。** 小班的 STEAM 不必五域齐全，规则是宁可诚实标注缺席，
不要为了显得完整而硬凑——那会写出「统计浮沉数量并绘制条形图」这种 3–4 岁根本做不到的活动。

⚠️ 原型是**讲设计方向用的，不是第二个实现**，界面细节不跟每一轮开发同步。
它不连后端（静态页面），所有交互走内置的真实数据快照。

## 本地跑起来

需要 Node 20+ 和 PostgreSQL 14+。

**双击两个 bat 就行**（Windows）：

| | 起什么 | 开哪 |
|---|---|---|
| `admin.bat` | 后端 | 管理后台 `/admin`，本地账号 `admin` / `123456` |
| `teacher.bat` | 前端（后端不在 3000 会自己起） | 教师端 |

窗口就是服务本体，关掉窗口 = 关掉服务。**改了后端代码要重启**（没开 `--watch`，它会在生成过程中重启把内存里的任务队列杀掉）。

第一次要先建库配环境变量：

```bash
cd backend
npm install                      # 必须在本地硬盘跑，虚拟盘会报 EBADF

createdb -U postgres stem_app
cp .env.example .env
#   DATABASE_URL   本地形如 postgres://postgres:你的密码@localhost:5432/stem_app
#   JWT_SECRET     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
#   DEEPSEEK_API_KEY  platform.deepseek.com 申请，要先充一点余额
#   WECHAT_APPID / WECHAT_SECRET  已作废，填两个占位值就行（见下）

npm run migrate                  # 建表，幂等，可以重复跑
```

启动时会自检：缺哪个环境变量、去哪申请，都用中文列出来，不抛英文栈。

> ⚠️ **`WECHAT_APPID` / `WECHAT_SECRET` 是遗留变量，不要真去注册小程序。**
> 微信那条路整条作废了，但 `services/wechat.js` 还被 9 个 route 文件 import 着、
> 启动自检也还拦着这两个变量，所以现在**必须填**，填 `wx_placeholder` 之类即可。
> 拆干净是待办里「去 `wechat.js`」那一项，跟新身份模型（手机号 + 密码）一起做。

🔴 **浏览器里走教师端主链路，要先有一个已激活的账号**：`cd frontend && npm run dev:account`。
不跑它首页会跳去还没做的 `/redeem`，表现是一个空页面。

### 跑一遍完整链路

```bash
npm run smoke 小班      # 或 中班 / 大班
SEED="我想做个影子的活动" TEACHER=dev:mid001 npm run smoke 中班
```

假登录 → 开会话 → 答完 4 题 → 生成教案 → 打印年龄班硬校验结果。
改完提示词之后重跑它，就能看出教案质量有没有变化。

**这个脚本验证的不是代码能跑，而是 AI 生成的教案是否真的适龄可用**——那是整个产品最大的未知数。

### 回归与代码检查

```bash
npm run lint            # 前后端各一份 eslint 配置，只抓真错不管排版

# 不起服务、不花钱的四个，改代码必跑
npm run test:ageband    # 年龄班硬校验的反向测试
npm run test:commentary # 教案解读的白名单与截断
npm run test:stream     # 流式增量「只增不减」+ epoch/from 游标
npm run test:context    # 问答配对与提示词里的数字

node scripts/cleanup-test-data.mjs        # 预览回归攒下的垃圾数据
node scripts/cleanup-test-data.mjs --yes  # 真删
```

## 教案配图

🔴 **配图是给老师打印出来用的**，不是拿来看的示意图 —— 这条决定了一切。
所以尺寸按打印定（长边 2048，A4 约 250 DPI），不是按屏幕。一份教案最多 3 张。

五种用途，构图完全不同（`services/imagePurpose.js`）：

| 用途 | 构图 |
|---|---|
| 材料图 | 单件占满画面；多样东西排成 A4 竖版的裁切网格 |
| 记录表 | 粗线大格子、格内留白、竖版 |
| 头饰 | 中间图案 + 左右两条长带，**带子要画到画面边缘**才够绕头 |
| 展示图 | 网格分隔 |
| 环创背景 | 四周装饰、**中间大片留白**给孩子贴作品 |

顺带把最难的风险消掉了：这些图里本来就不该有儿童，
**「不要画脸」那条压不住的约束现在根本不需要**。

三家模型可切，后台「模型管理」里设默认：

| | 实测 | 留着的理由 |
|---|---|---|
| **nanobanana**（默认） | **18 秒** | 最快，记录表和头饰都画对了 |
| gpt-image-2（经 12ai 中转） | 70 秒 | **记录表**。MiniMax 画表格试了五次五种错法，而那张图就是印出来给孩子填的 |
| MiniMax image-01 | — | 插画类的扁平矢量更贴这套设计，而且一家挂了还有另一家 |

**提示词的三条实测教训，别凭感觉改回去**：

1. **否定约束必须写在英文风格前缀里**。中文那几条只有 DeepSeek 看得到，图片模型从头到尾没见过 ——
   中文写着「一个字都不许画」，出来的记录表照样印着 BOAT / HEAVY STONE 和一个假签名
2. **文档类图（记录表、材料裁切网格）要关掉 MiniMax 的 `prompt_optimizer`**。插画类开着有提升，保留
3. **只写 centered 不够**，要连着写「不要房间、不要地面、不要墙角、占满画面」。
   第一版画出来是空墙角里躺着一枚很小的磁铁，主体不到十分之一

## 年龄班规则是怎么真正生效的

那本台湾 STEAM 教材的案例默认孩子会言语预测、会读量杯刻度、能小组分工，这是中大班的能力。
3–4 岁小班做不到。光把规则写进提示词不够——提示词是概率约束，不是保证。所以做了三层：

1. **只注入当前年龄班的规则**。三个班一起给，模型会挑最丰富的那套，这是给小班写出大班活动的根因
2. **时长选项由代码从参数表算**，不问模型。选小班，界面上根本不出现 45 分钟这个选项
3. **生成后代码硬校验**（`enforceAgeBand`）。小班出现量杯读数、预测环节、统计图表、小组分工、
   缺误食风险 → 记入 `quality_self.age_band_violations`；超时长直接收敛回上限

第三层用故意踩满红线的样本反向测过（`npm run test:ageband`，34 条）。所以真实生成时报「零违规」是真结果，
不是校验器在空转——这个区别很重要，因为**一个空转的校验和一个严格的校验，正常输入下输出一模一样**。

## 技术选型

| | 选了什么 | 为什么 |
|---|---|---|
| 平台 | **手机浏览器优先的 web 应用** | 甩掉「借企业主体」。不做小程序、不做原生 APP、不做 PWA |
| 前端 | Vue 3 + Vite + vue-router | 不保留 uni-app 只编 H5 —— 留着就要一直带 `rpx`、`pages.json`、条件编译 |
| 后端 | Node 20 + Express + 原生 JS | 不用 TypeScript、不用 ORM、不用 Docker、不上微服务 |
| 数据库 | PostgreSQL + `pg` + 手写 SQL | 查询就十几条，SQL 直接可读，出问题能整句复制到 psql 里跑 |
| 文本模型 | DeepSeek（可在后台换） | 用户在大陆，OpenAI 的 IP 不通 |
| 图片模型 | nanobanana / gpt-image-2 / MiniMax（可在后台换） | 见上一节 |
| 云 | 阿里云（ECS + OSS + 内容安全） | 价格 + 已有账号，不是技术理由 |
| 知识库 | 只做框架提炼，**不做全文 RAG** | 规避版权，原书 PDF 不入库 |

完整理由见 [`docs/adr/`](docs/adr/)：`ADR-001` 技术栈、`ADR-002` 转向 web、`ADR-003` 换阿里云。

## 现在做到哪了

**能跑的**

- 后端业务链路全通：假登录 → 开会话 → 一次拿到 4 题 → 逐题落库 → 异步生成 → 流式轮询 → 取成稿
- 改一改：对成稿提意见 → AI 提 3 个**新**问题（不重复问过的）→ 整份重写、version+1，**可回退**
- **前端主体完成**：首页 + 一条对话流（`/c?id=`）+ 双外壳（宽屏侧边栏 / 窄屏抽屉）+「我的」弹窗 + 使用协议
- 23 张表，21 个迁移文件，幂等
- 年龄班差异化经实测验证真实生效（见上表）
- 记忆自动提取与合并，单人最多 10 条
- **配图端到端跑通**，5 种用途
- 管理后台：园所 / 名单 / 老师 / 兑换码 / 额度台账 / 任务 / 反馈 / 模型管理，两级权限
- 回归脚本：后端 14 个 + 前端 3 个

**还没做的**

- **后端新身份模型**（手机号 + 密码）—— 卡着前端兑换页，也卡着去 `wechat.js`
- **阿里云内容安全**（`TextModerationPlus`）—— 现在这条链路是空的
- **OSS**（图片存本地 `.local-images/`，只在单机成立）
- 导出 docx（现在返回 501）
- 域名 + 个人 ICP 备案 + HTTPS —— **上线闸门**
- 侧边栏的左滑 / 悬停删除

**待验证的假设**

- 🔴 **AI 生成的教案是否真的适龄可用 —— 至今零真实老师复核，这是产品最大的未知数**
- 小班的时长上限和循环次数是按发展常识推的，**需要真实小班老师复核**
- 《指南》指标的条目选得准不准，没有真实老师复核过
- 配图采用率是成本的主要变量，上线后要盯这个数

## 几条不能破的线

- API key 只在服务端，任何情况不下发到浏览器
- 老师输入和 AI 输出都要过内容安全（阿里云 `TextModerationPlus`），**上线前必须接上**
- **不存幼儿的任何信息**。禁的是个体信息：姓名、生日、照片、家长联系方式、
  任何一个孩子的能力评价或行为记录
- 老师的手机号和真实姓名**要存**（手机号在这个系统里只是用户名），但三条铁律：
  **永不下发前端、永不进模型提示词、永不进日志**；**幼儿园管理者看不到任何老师数据**
- 每答一题即落库——老师在幼儿园随时被叫走，进度不能丢
- 生成要 15–30 秒，必须异步且**能离开**，不能要求盯着屏幕等
- 改接口先改 `docs/design/api-spec.md`，改配色只改 `docs/design/design-tokens.md`
