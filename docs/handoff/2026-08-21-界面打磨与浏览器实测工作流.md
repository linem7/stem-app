**③ 🔴 塞完 token 必须 `reload`，不能靠 navigate 到同一个 hash。**
这是个真踩过的坑：`#/pages/me/me` 已经在地址栏里了，再 navigate 一次
**不会刷新页面**（SPA 只换 hash），session 还是塞 token 之前那个未激活的，
于是「明明 `GET /me` 回来 `activated: true`，页面还停在待激活屏」。
用 `reload` + `ignoreCache`。

### H5 仍然仲裁不了的事

这条不能忘，否则会拿 H5 的绿灯当结论：

| 只有微信会出的 | H5 为什么看不见 |
|---|---|
| 点了没反应（handler 缓存 key 撞车） | H5 没有那套 key 机制 |
| 字号三档调了没反应 | H5 没有自定义组件样式隔离 |
| WXML 编译错误（`<block wx:key>` 之类） | H5 不编译 WXML |
| 真机上的字体度量、安全区、胶囊遮挡 | 内核和布局都不是一回事 |

**所以顺序是：H5 里量准 → 编译产物核对 → 他在微信里确认一次。**
这一轮三步都做了。

## 这一轮真踩过的坑

### 1. 🔴 「跟底下的内容左对齐」我理解反了，白改一轮

他第一次说：**「个人档案的位置没有跟其他记忆左对齐」**。

那一列长这样：

```
我的记忆                    写教案时会自动带上
    个人档案                            ›     ← 缩进了 44rpx
01  有个孩子对面粉过敏
02  园里没有投影仪
```

「其他记忆」有两条左边界：**编号列（32px）**和**正文（61.33px）**。
我选了后者 —— 想的是「让档案的文字跟记忆的文字排成一条线」。
但他要的是前者：**编号列定义了这个板块的视觉左边界**，
档案往右让 44rpx 之后看起来就是「缩进的一条」，而它明明是这一列的第一条。

于是我上一轮做的「修复」（把空 `<text>` 占位换成 `padding-left: 44rpx`）
**视觉结果跟原来一模一样**，他看不到任何变化，只能再提一次。

教训两层：

- **他说「对齐」的时候，先问清是跟哪一条边。** 一列带编号的列表有两条左边界，
  而「左对齐」这三个字对两者都成立
- **改完之后我该量一下「改动前后有没有区别」**，而不只是量「现在对不对」。
  padding-left:44rpx 和空元素占位 44rpx 是同一个结果，
  量一次「跟上一版比变了吗」就能当场发现这次改动是空转的

顺带：我为此编的那个成因（「空 `<text>` 在微信里塌成 0 宽」）**没有被证实**，
大概率是错的 —— 它本来就是按 44rpx 缩进渲染的，只是那个缩进不该存在。
**不要把那个说法当成微信的已知行为传下去。**

最终改法：`.mem--pf` 不给 padding，模板里也没有占位元素。
注释里写明了「不许缩进，也别用空 `<text>` 重新造出缩进」。

### 2. `DOMNodeRemoved` 那条报错不是我们的

他贴了一条：

```
[渲染层错误] Listener added for a 'DOMNodeRemoved' mutation event.
Support for this event type has been removed…
(env: Windows,mp,2.02.2608182; lib: 3.17.0)
```

查过：源码里没有任何 `DOMNodeRemoved` / `DOMNodeInserted` / `DOMSubtreeModified`，
两份编译产物里也搜不到。唯一的 `addEventListener` 在 `stores/net.js`，
监听 `online`/`offline`，而且外面套着 `typeof window !== 'undefined'`（微信端不执行）。

它来自微信自己那一层：`DOMNodeRemoved` 是被废弃的 DOM Mutation Event，
Chromium 已移除支持，而开发者工具的渲染层是 Chromium 内核、
微信的组件系统里还留着这个用法。**是一条弃用告知，不是我们的错**，
工具把它归类成「渲染层错误」是它的分类偏严。

判据：它应该在**每个页面**都出现，包括这一轮完全没动过的首页和教案库。
真的只在某一页出现，那这个结论就是错的，得重查。

## 这一轮改了什么

只动了一个文件：`frontend/src/pages/me/me.vue`。

| 改动 | 实测 |
|---|---|
| 「个人档案」跟编号列左边缘对齐（去掉 44rpx 缩进） | 32px vs 32px，差 **0** |
| 那一行变成**开关**：点开、再点收起 | 连点三次：展开 → 收起 → 展开 |
| 箭头跟着转（收起朝右、展开朝下） | `rotate(90deg)` |
| 删掉展开区里的「取消」 | 死样式 `.pf__c` / `.pf__c-t` 一起清了 |
| 收起 ＝ 放弃改动，不留残留 | 改成大班 → 收起 → 再打开，回到中班 |

⚠️ **箭头旋转是我加的，他没提。** 理由：展开区里没有「取消」了，
收起全靠再点那一行 —— 箭头方向是唯一告诉她「这东西能收起来」的东西。
他要是不喜欢，删一个 class 的事。

`onProfileTap` 必须是 toggle 而不是「只负责打开」：写成后者的话
她点第二下没反应，而唯一的出路是把表单填完。
