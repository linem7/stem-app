## 已定死的决策（不要重新讨论，除非用户主动提）

### 平台与部署

- **平台**：手机浏览器优先的 web 应用。**不做小程序、不做原生 APP、不做 PWA**（现阶段）
- **前端**：Vue 3 + Vite + vue-router。**不保留 uni-app 只编 H5** ——
  留着 uni 就要一直带着 `rpx`、`pages.json`、条件编译和一整套只为小程序存在的知识负担
- 🔴 **尺寸单位：`rpx ÷ 2 → px`，正文列套 `max-width` 居中**（2026-08-30 用户定）。
  宽度、卡片、列表照样弹性，**只有字号和间距是固定的**。
  只有一个断点 `900px`，它切的是**外壳**（侧边栏 / 抽屉），正文一个字都不换 ——
  见下面「界面与信息架构」那节。
  **不做「根字号跟视口宽走」那套等比缩放** —— 它会跟**字号三档可调**打架
  （大屏上的「标准」可能比小屏上的「特大」还大，那三个档就不再代表固定的东西），
  还会盖掉用户自己在浏览器里调过的字号。
  代价：320px 的小手机上略挤 —— 真挤到不能用就在那一档加媒体查询局部收间距，
  **不要把整套改回等比缩放**
- **后端**：Node.js 20 + Express + **原生 JavaScript（ESM）**。不用 TypeScript、不用 ORM、
  不上微服务和消息队列
- **数据库**：PostgreSQL，`pg` 驱动 + 手写 SQL
- **服务器**：阿里云（ECS 或轻量应用服务器，按买到的优惠定）+ **服务器上自装 PostgreSQL**
  + **OSS 存图**；管理后台 `/admin` 同域名同端口。
  🔴 2026-09-01 从腾讯云换过来，理由是**价格 + 已有账号**，不是技术理由（`ADR-003`）。
  凭证用 **RAM 用户 AccessKey**，不用云账号（主账号）的 —— 后者有全部权限且没法收窄。
  🔴 **备案服务码要四条同时成立**：包年包月（按量付费不行）、**≥3 个月**、有公网带宽、
  中国大陆地域。**买一个月的促销机器办不了备案**，续费到满 3 个月即可。
  🔴 **服务器 / OSS / 内容安全 / 备案，四样必须在同一个阿里云账号里**（作者的个人实名账号）。
  跨账号办不了备案：个人认证账号无法把服务码授权给别的账号，要企业认证 ——
  那等于把 ADR-002 甩掉的「借企业主体」请回来。
  ⚠️ 2026-09-01 踩过：RAM 用户建在 A 账号，服务器却买在 B 账号，那一轮全作废。
  **建 RAM 用户之前先确认服务器在哪个账号**
- **公网 IP HTTPS 已完成（2026-09-22）**：用户授权并放行安全组 443，现入口为 `https://115.29.167.18/`。
  HTTP 业务请求 308 跳转 HTTPS，图片基址已切换；Let's Encrypt 正式 IP 证书与每六小时自动续期已启用，续期演练成功。
  旧说法“IP 无法申请 HTTPS／需要报名预览”已过时。HTTPS 不替代备案；用户本轮要求广东备案指引，尚未提交备案或购买域名。
  详见 `docs/handoff/2026-09-22-IP-HTTPS与备案.md`。
- **知识库**：只做框架提炼，**不做全文 RAG**（规避版权）。原书 PDF 不入库
- **语言**：全程简体中文，大陆幼教用语。原书是繁体，输出必须本地化

### 身份与账号（2026-08-30 重定 · **2026-09-20 已实现**）

> 下面这套已经写进代码了。**换设备只用手机号 + 密码，兑换码只在第一次用。**
> 实现落在：迁移 `022_teacher_identity.sql`、`routes/auth.js`（登录）、
> `routes/activate.js`（激活 + 拉名单，**公开路由**）、
> 前端 `pages/login/`、`pages/redeem/`、「我的」里的续兑。
> 🔴 顺带作废：**换绑**（没有 openid 就没有「换微信」这回事）。
> 代码还在，没删，等一起收。
> ⚠️ `requireActivated` **只死了一半** —— 前半段（`!activated_at`）走不到了，
> 但后半段（`!agreed_at`）是协议那道闸门的服务端实现，还活着。

```
第一次       输兑换码 → 从名单里选自己是哪一位 → 设手机号 + 密码 → 发额度
日常         token 免登录（30 天，**每次打开自动续期**）
换设备/清缓存 手机号 + 密码
忘密码/号打错 找作者人工处理
```

⚠️ **这段曾经是错的**（2026-09-21 核实并修）：原来写「180 天，每次打开自动续期」，
而**两句都不成立** —— token 是 30 天，也**不自动续期**。
所以那时她第 31 天会忽然被踢到 `/redeem`，而**她完全没做错什么**。

**现在真的续了**（用户要求「每次打开续期」）：

- 挂在 `GET /me` 上 —— **前端每次打开网站都会调它**，正好是「她还在用」那个信号
- **剩余不足一半才换**（`shouldRenew`）。不是每次都换 ——
  她随便点几下就换一个没意义（`signToken` 里没随机数，同一秒签出来的完全一样）
- ⚠️ 加个 `/auth/renew` 那条路是错的：**要她主动调，就可能永远不被调**，
  而那正是要解决的问题。挂在 `GET /me` 上是「顺手」，她不用知道
- ⚠️ **续期时要带对 `token_version`** —— 注销或改密码会把它 +1
  （那是「把旧 token 全作废」的机制），带错版本会**立刻把她踢掉**

- **手机号在这个系统里只是用户名。** 不用于联系、不进 AI 提示词、不下发到页面、不进日志
- 🔴 **手机号输两遍核对。** 11 位打错一位是常事，而后果特别隐蔽 ——
  她下次登录输的是**正确的号**、库里存的是**打错的号**，进不去，
  且她完全不知道哪里出了问题
- **不发短信验证码。** 理由是资质不是成本：腾讯云自 2025-09-18 起
  **不再支持个人自用资质**，个人只能走「他用资质」并要签名归属公司出具授权委托书、
  加盖双方公章 —— 那等于把「借企业主体」原样请回来
- **密码存 scrypt 哈希**，复用 `services/admins.js` 里管理员那套
- **激活那一屏只问手机号和密码。** 园所、班级、岗位、姓氏在「从名单里选自己」那步已经有了
- 🔴 **「重置登录密码」「修改账号手机号」只有超管能做，并且进 `admin_logs`。**
  一般管理员现在看不到对话正文，而**能重置密码 = 能登进她的账号 = 绕过那道限制**
- **登录页要有一行「登录不了？」** 点开显示联系方式。放在「我的」里没用 ——
  她正是进不去的时候才需要它
- **伦理审查批号不设为上线闸门**（2026-08-30 用户定），改成收集前的知情同意告知。
  代价如实记在 ADR-002 里：知情同意和伦理批号是两件事，而批号**事后补不上**

### 三层身份，别混

| 说的是 | 字段 | 含义 |
|---|---|---|
| **人** | `teacher_roster.teacher_ref` | 换班也不变。追这位老师按它归组 |
| **位置** | `teacher_roster.id` | 人 × 园 × 班 × 岗位，就是 `class_teacher_id` |
| **账号** | `teachers.id` | 她登录进来的那个东西 |

- 她换班了走岗位调整：新开一行、沿用同一个 `teacher_ref`、旧那一行标 `moved` **留着不删**
  （研究要用它区分「她在小一班那半年」和「她在中二班这半年」）
- 她注销之后**位置放回「待激活」** —— 位置是园所的，不是她的
- ⚠️ **拉名单必须先有一个有效的码**（`POST /auth/roster/options` 会先校验）。
  不设这道门，任何人打开网页就能看到一整个园的老师名单。**姓名只给姓氏**
- 🔴 **校验失败绝不能消耗那个码。** 顺序必须是「先全部校验，再全部落库」——
  她进不来时只会说一句「用不了」，没有别的线索
- **要认下来的代价**：从列表里选是一个**表单字段，不是钥匙**。可以接受，
  因为同事之间冒领没有收益，而真会发生的「手滑选错同班另一位」是**可查可改**的

### 兑换码与额度

- **额度不存 `balance` 字段**，用「台账 Σ 发放 − 事实表数消耗」算，避免两份事实对不上
- 额度闸门装在三处：开会话、改稿、配图
- **兑换码的职责只有两件**：证明**「你有资格进来」**+ 发额度。**它不是登录钥匙** ——
  所以整批交给园所仍然成立（园长拿一叠码只能激活新账号，进不了已激活老师的账号）
  - 🔴 2026-09-21 语义**扩了**：原来写的是「证明你是**这批人**里的」，
    现在码**不限定园所、也不限定批次**（`ADR-004`）。扩的是门后面的白名单，
    **门没动** —— 没有码的人什么都做不了。别读成「码作废了」或者「谁都能进」
- **两种码**：**匿名码**（批量建 N 个，默认 20 教案 / 10 配图，导出 CSV 灌问卷星）和
  **绑定码**（单个建，可指定园所）
  - ⚠️ 2026-09-21 之后「绑定码」那个园所值**不再用来限制她能查到谁的名单**，
    它只剩跟进意义（「这个园发了几个、兑了几个」）。**自填进来的人追不了这个数**
    —— 他们从来没在名单上（`ADR-004` 认下的代价）
- 匿名码的代价：**「问卷答卷 ↔ 账号」的对应关系不在我们库里**，在问卷星那边
- 🔴 **白名单是两级地区 + 四级下拉**（省 → 市 → 园 → 班/岗位/人），
  底下常驻一个**「不在名单之内」**（她不审核、自己填，`teachers.entry_source = 'self'`）
  - **地区必须下拉选，服务端也校验**（要出现在 `kindergartens` 的 DISTINCT 里）。
    自由填会脏成「北京 / 北京市 / 北京朝阳」，而研究要按地区分组 —— **脏了补不回来**
- **完善信息（出生年份/学历/教龄/任教年级）送 10 教案 + 5 配图**，只能领一次
  - 🔴 判据是 `quota_grants` 里 `reason='完善信息'` **那条记录**，
    **不是**「四个字段填全了没有」—— 她填完再改一次学历，后者仍然成立、会再领一次
  - 它是**独立接口** `POST /me/profile`，跟 `PATCH /me` 分开
    （后者也能改这几项，但**不发额度**；合并 = 反复改档案反复领）
- **建码的「说明」上限 20 字**，`grantReason` 一个纯函数守两条路
  （`POST /codes` 和 `POST /codes/batch`）——「两条路只守一条」这个项目踩过
- **注销 = 留壳去身份**：删对话教案配图记忆和手机号，留 `teachers.id`（拒绝再次登录）、
  额度台账、已提交的建议评价。真删行会让她再登录变成全新账号，等于「删完还能接着用」

### 模型管理

- **文本和配图都在管理后台「模型管理」里**（一张 `ai_models` 表，`kind` 分 text / image）。
  文本默认 DeepSeek，配图默认 `nanobanana`
- **加一家不用改代码**：后台填**三样** —— 接口地址、API key、模型 id。
  配图三种接口格式（`openai_images` / `gemini` / `minimax`）；
  文本四种（`deepseek` / `glm` / `qwen` / `openai_chat` 通用兜底）。
  只有冒出新格式才需要写适配器（`modelRegistry.js`）
- **接口格式不让人选，靠推断**（`guessFormat`）。🔴 **先看模型 id，再看地址**：
  `nanobanana` 是 gemini 原生格式却走 12ai 中转，而同一个中转下的 `gpt-image-2` 是
  `openai_images` —— 靠地址分不开，靠模型 id 一眼分开。都认不出退通用档，**绝不猜**
  - 🔴 改模型时**认不出来就保持原格式不覆盖**：把 nanobanana 降级成通用档 =
    配图立刻画不出来且不报错。列表里「识别为」那一列必须显示 —— 认错了只有它看得出来
- **代号（key）从模型 id 派生**，撞了加后缀：同一个模型 id 配两次是真实场景
  （两个中转商、两把额度不同的 key）
- **文本模型的「思考模式」「联网」是真实生效的调用参数，不是标签**。
  deepseek 思考 = `thinking:{type:"enabled"}`（**它的 chat 接口没有联网参数**，开关置灰）；
  glm 联网 = `tools:[{type:"web_search"}]`；qwen = `enable_thinking`/`enable_search`。
  该格式不支持的开关**界面置灰 + 服务端拒**，两条路都守
  - 🔴 **开了思考就不发 `response_format: json_object`**（官方思考示例全是 text），
    解析靠 `tryParseJSON` 兜底
  - 🔴🔴 **「关掉开关」必须显式发出去，不能「不发参数」。** DeepSeek V4 系列
    **思考模式默认打开、effort 默认 high**。「开关开了才发 enabled，关了就什么都不发」
    = 走默认值 = **一直在最高档思考**。修完全程 77 秒 → 16 秒。
    **「开关真实生效」不能只测「开」那一侧**
  - 🔴 **开关只作用于声明了 `applyToggles` 的调用**（生成教案、教案解读、后台模型测试）。
    2026-08-23 真踩过：管理员在后台开了思考，整条链路全挂 —— 思考 token 计入 max_tokens，
    「每题一句回应」只给 120 全被思考吃掉、正文为空。管理员开思考的本意是「教案写得更好」，
    不是「每句寒暄都思考」。**新加的调用点默认拿不到开关，这是安全的那一边**
  - **思考是锦上添花，不许挡出稿**（`textChat.js` 两道保底）：开思考的调用给 max_tokens
    加 8192 余量；仍被吃穿就**自动关思考重试**，JSON 解析不出来也降级重打一次
  - **要 JSON 而 `finish_reason=length` 时加倍预算重试**（封顶 16384）。
    教训：**换模型不该让人去改代码里的一个数字** —— 用户换成 `deepseek-v4-flash` 之后
    教案每次都生成失败，因为写完整教案要 4000 以上输出而 `maxTokens` 正好是 4000
- 🔴 **最后一个启用的文本模型不许删、不许停用**（后台路由硬拦）。
  「没文本模型不启动」×「加模型唯一入口是后台」= 死锁
- **老师完全不碰模型**（2026-08-18 用户定）。加模型、改模型、**设为默认**全在管理后台。
  用哪家是技术判断（谁把记录表画对了、谁快、谁便宜），老师没有判断依据，选错了还会怪自己。
  「设为默认」存 `app_settings` 表，**改完立刻生效，不用重启**
- **`GET /models` 的 defaults 直接问 `pickModel`**，不再自己读 setting 拼取值顺序 ——
  同一条规则写两份，两份就会对不上
- **记账用 `NUMERIC(12,4)` 不用整数分**：单次文本调用约 0.1 分，整数分逐行 round 后全是 0

### 配图

🔴 **配图是给老师打印出来用的**（2026-08-17 用户定），不是拿来看的示意图 —— 这条决定了一切。
顺带把最难的风险消掉了：这些图里本来就不该有儿童，**「不要画脸」那条压不住的约束现在根本不需要**
（⚠️ 唯一的例外是**故事图**，见下）。

#### 🔴 「推荐」是**方案卡片**：一条 = 一张纸（2026-09-21 用户定）

用户的原话，我第一次理解错了，值得留原文：

> 我说的 3 项指的是一个完整的提示词，而不是一张图里有多少个材料。我的想法是针对一个教案
> 可能要绘制不同的内容，但是内容太多，一个内容一张纸很不划算，因此提供推荐提示词
> 让教师可以把可能想要的内容都打印到一张纸上

所以 `content_json.illustrable` 里每条是 `{title, what, why}`，
`what` 是**一张纸上的完整内容**（分几个区、每区什么、什么规格），写到「别人照着能画出来」。
模型**尽量给 3 条** —— 那是「**同一份内容的几种贴法**」，不是三张不同的图：
最省纸的组合 / 拆开各占一张 / 只要其中一样。

- **点卡片会把 `what` 填进「自己写」那个输入框**（用户 2026-09-21 要的）——
  卡片负责起头、输入框负责让她改。所以**输入框优先于卡片**（`draw()` 里那个取值顺序）
- 点另一张 = 换过去，输入框跟着换；再点同一张 = 取消，**输入框不清空**（她可能改了一半）
- ⚠️ 改字**不清卡片的选择** —— 原来会清，而那会让「点一张、改两个字」这个最自然的动作
  把高亮弄没，看起来像「选择丢了」

🔴 **记录表必须独占一张纸，不许跟任何东西凑**（用户定：「只要出现记录表，就应该只有一张图」）。
因为它跟别的东西**本来就冲突**：记录表要「格子里必须是空的、格子要大、线要粗」
（3-4 岁握笔不稳），而材料图要「每格画满一样」、头饰要「带子画到画面边缘」——
**两种构图挤半张纸，两样都做不好**，而记录表格子不对就是废纸。

- **两头都守**（提示词 + 代码），因为同一条提示词里还有「尽量给 3 条」，两个要求会打架 ——
  而**把记录表挤掉那次事故正是「提示词说了、模型没听」**
- 代码那道在 `normalizePlan`：`what` 里出现「记录表」**且**还提到别的可画的东西 → 切掉别的部分
- ⚠️ **切完还要把「上下两个区」那类话术削掉** —— 第一版没削，留着它会让模型又画成上下两半，
  **等于这道防线白做**

#### 「实体材料」的防线：改了三版才对

用户报过一条「直尺刻度示意图」—— **她需要的是去买一把真尺子，不是看一张画出来的尺子**。

| 版本 | 判据 | 结果 |
|---|---|---|
| ① | 白名单（记录表/头饰/图卡/网格…） | ❌ **误杀好方案**：模型写的是「一张 A4 纸，分上下两区。上半区是表格」，一个白名单词都没有 → 两条好方案被静默丢掉（教案 11 的「0 条」） |
| ② | 黑名单 + 长度 ≤14 字 | ❌ 那条实体材料 17 个字，又漏了 |
| ③ | **黑名单命中 且 全条没有「纸/张/区/格/表」** | ✅ 六条测试全对 |

**教训：白名单永远列不全**（模型的说法是开放的），**要拦的东西才有界**。**长度不是判据。**

#### 七种用途（`backend/src/services/imagePurpose.js`）

| 用途 | key | 构图 |
|---|---|---|
| **材料图** | `material` | 单件占满画面 |
| **记录表** | `worksheet` | 粗线大格子、格内留白、竖版 |
| **头饰** | `headwear` | 中间图案 + 左右两条长带，**带子要画到画面边缘**才够绕头 |
| **环创** | `backdrop` | 四周装饰、**中间大片留白**给孩子贴作品 |
| **故事图** | `story` | **一幅连贯的场景**，像绘本里的一页 |
| **一张纸** | `plan` | **什么都不预设**，构图完全交还给描述 |
| ~~展示图~~ | `display` | ~~网格分隔~~ **界面上删了**（用户：「它跟材料图是一类的」），但定义留着 —— 库里还有历史图，删了它们那一栏的标签会掉成兜底的「配图」 |

- 🔴 **`plan` 是「方案卡片」那条路专用的**，2026-09-21 加的。原来有方案时也走她选的
  「材料图」，而材料图的规则写死 `one single object drawn large and centered` ——
  **我们给的构图指令跟她写的描述直接打架**，用户报的那张图里记录表那半张被彻底挤掉。
  根因不是模型不听话，是**我们给了两套矛盾的指令**
- **故事图**画的正是「孩子们在做这个活动」，所以规则里明确要求
  **「背影、侧影、或只画手」** —— 画了脸就等于在画面里造了一个**不存在的孩子**

#### 别的没变

- **老师一句话里说了好几样，画在同一张纸上**，不拆成几张 —— 一份教案总共才 3 张配额。
  （`countSubjects` + `purposeSpec(purpose, count)`）
  - ⚠️ **`countSubjects` 现在不认分号**（2026-09-21 改）：分号是**句读**不是并列。
    用户那段描述用分号分隔句子，被切成 9 段，后端以为要排 9 样 → 3×3 网格
  - ⚠️ **「方案卡片」那条路不走 `countSubjects`**（前端发 `plan: true`）——
    那段描述是**散文不是列举**，数它几样没有意义
  - **头饰**上下排开，封顶 4 条
  - **材料图**排成 A4 竖版的**裁切网格**（2026-08-25 用户定）：列少行多，
    6 样 = 2 列 × 3 行，格间留白 + 细裁切线。除不尽时多出来的格子留空，
    不为凑整排成 1 列 5 行（每格会扁到剪出来不成样子）
  - 🔴 它跟记录表一样**关掉 MiniMax 的 `prompt_optimizer`** ——「网格裁切纸」这个套路
    在训练数据里几乎全是识字卡（每格底下一个单词），润色器会把那些标签补回来
- **一份教案最多 3 张。** 尺寸按打印定：长边 2048（A4 约 250 DPI），不是按屏幕
- **打印用那三类默认黑白**（省墨、孩子能涂色），但界面上有开关能切彩色。
  ⚠️ **黑白不再由 `kind` 写死** —— 拆成了两件事：颜色归她选，而
  「印出来给孩子用」还是「画给人看」那句话仍归 `kind`（它们真的会不一致）

**配图提示词的三条实测教训，别凭感觉改回去**：

1. **否定约束必须写在英文风格前缀里**。中文那几条只有 DeepSeek 看得到，图片模型
   从头到尾没见过那段中文 —— 中文写着「一个字都不许画」，出来的记录表照样印着
   BOAT / HEAVY STONE 和一个假签名
2. **文档类图要关掉 MiniMax 的 `prompt_optimizer`**。插画类（材料图、背景墙）开着有提升，保留
3. **只写 centered 不够**，要连着写「不要房间、不要地面、不要墙角、占满画面」。
   第一版画出来是空墙角里躺着一枚很小的磁铁，主体不到十分之一

#### 🔴 图片不再上对象存储（2026-09-21 用户定）

~~OSS 对象存储~~ → **直接存服务器硬盘**（`backend/.local-images/`）+ **生成时压缩**。

- **压缩在哪**：`imageStore.uploadImage` —— 它是**所有图的唯一落地点**（配图生成、
  后台模型测试两条路都走它），在那儿压一次两条路都受益
- **参数**：长边 2048、JPEG 质量 82（打印类 90），用 `sharp`（底层 libvips）
- **效果**：2400 长边 1.68 MB → **69 KB（省 96%）**。
  🔴 这么夸张是因为**这些图是 AI 生成的扁平插画**（大面积纯色、硬边、没噪点），
  JPEG 对这类图的压缩率远高于照片 —— **我按照片的经验估 70%，估错了**
- ⚠️ **打印类那档（90）是猜的** —— 记录表是粗黑线硬边，压缩痕迹最容易露，
  而它印出来是给孩子填的。**等真生成一张记录表打出来看**，不行就调
- 🔴 **改文件必须同时改库里的元数据**（`bytes` / `width` / `height`）。
  我一处栽了两次：① 脚本只改 `bytes`，忘了宽高也变了 ② `images.js` 写库用的是
  **模型要求的**尺寸，而压缩后**实际尺寸变了**。
  那两个数不是装饰：导出 docx 时按它们算缩放比例（`lessonDocx.js` 的 `fitBox`），
  记错了会把记录表按错比例压扁

**为什么默认是 `gpt-flare`**（gpt-image-2.5-flare，2026-09-21 换的）：

- 用户选的，文档说它「兼顾画质与速度」，延迟比 2 代约减半
- **质量档保持 `high` 不变** —— 只换模型不换质量，质量变化才归因得清
- ⚠️ flare 合法质量是 `low/medium/high/xhigh/max/auto`，而 `gpt-image-2` **没有** `xhigh`/`max` ——
  **换回 2 代时忘了改质量档会 400**
- ⚠️ **尺寸约束**（12ai 的要求）：两边 16 的倍数、长短边比 ≤3:1、总像素 655,360–8,294,400。
  `imagePurpose.js` 里那九个尺寸全部合法，**加新尺寸时要重新核**

- `gpt`：**gpt-image-2 留着不删**，它的价值是「**记录表第一次就画对了**」——
  万一 flare 画表格不如它，改默认回去就行，不用碰代码。
  MiniMax 画表格试了五次五种错法，而那张图的用途就是印出来给孩子填，格子不对就是废纸；
  gpt-image-2 第一次就给了干净的 3×4、粗黑线、零文字
- `minimax`：image-01 留着不删。插画类它的扁平矢量更贴这套设计，而且一家挂了还有另一家
- 走 12ai 不等于破了「不用 OpenAI」那条：**用户在大陆，直连 OpenAI 的 IP 不通**
- 实测教训见 `backend/src/services/gptImage.js` 的文件头：路径别照抄文档（会变成 `/v1/v1/`）、
  尺寸不限于文档列的三档（1536×2048 照收）、只用 `b64_json`（`url` 指向第三方，寿命未知）

### 界面与信息架构

- **首页只是一个对话框**，不放任何历史入口。过往教案无论完成与否全部进教案库
- 🔴 **引导 / 生成 / 成稿 / 改一改是同一条流**（2026-08-31 用户定，**推翻了四个独立页面**）。
  一个地址 `/c?id=`（**会话 id，不是教案 id**），从上往下就是整个过程：
  她说的那句 → 4 道题 → 正在写 → 教案 container → 她提的意见 → 三道追问 → 新一版
  - **教案是流里一个有边界的 container**（`s-plan.vue`）。两千多字，没有边框就跟上下文
    糊成一片，看不出「这一整块是一份教案」。配图和导出在它自己的底栏里
  - **引导 4 题和改稿 3 题是同一个组件**（`s-quiz.vue`）。小程序时代两页各写了一遍，
    改一处得记得改两处。它只管画，**答案状态和落库归调用方** ——
    引导是每答一题即落库，改稿是三题一次交，两种持久化捆一起就要加 mode 开关
  - 🔴 **流底下长出新东西必须把页面滚过去。** 改稿的追问长在一份两千多字的教案**底下**，
    而她还停在教案顶上 —— 屏幕上什么都没变，看起来就是「点了没反应」

    不挡住就会被拽到底（实测 scrollY 2121，教案顶在视口上方 1947px）。

  - 🔴 **`GET /versions` 只回元数据不回正文**，所以摆不出「两版正文一前一后」。
    当前那版画完整 container，其余每版占一行，点它是回退（不新增版本、不花额度、可来回切）
  - ⚠️ **重新打开一份已完成的教案时，后端不再回那 4 道题**，「你答的」摘要会是空的。
    空了就整块不出现 —— 只留一个标签底下什么都没有，看起来像加载失败
  - 🔴 **底部那条收起来时只有一个「哪里不对？我来改」**（2026-08-31 用户定）。
    输入框 + 五个常见说法常驻的话，手机上占掉小半屏，而她多数时候是在**读教案** ——
    那半屏是白挡的。实测教案露出的行数 3 → 13。点了才展开，展开后光标直接落在输入框里
- 🔴 **一套内容 + 两个外壳**（2026-08-30 用户定，**推翻了同一天的「底部三项保留」**）。
  两种形态是同一套 DOM，只有 CSS 不一样 —— **不是两套页面**。
  真写两套是十页变二十页，而且两边会慢慢长歪

  | 窄屏（<900px） | 单一焦点列，`max-width: 480px` | 侧边栏变成抽屉，汉堡键开 |

    - 🔴 **筛选是分段控件，不是会换行的胶囊**（2026-08-31 用户定）。
      胶囊按内容宽度排，`全部 11` 加上两位数就把 `已完成 9` 挤到下一行，
      数到 100 份时断行位置又换一个地方 —— **排版跟着数据变**。

      ⚠️ 认下的代价：触控区高 33px，低于 44px 的建议值
    - ⚠️ 状态那排的数字是**不受筛选影响的总数**。筛一下就跟着变小的话，
      她没法用它判断「还有几份没写完」—— 那正是这排数字存在的理由
    - ⚠️ 「筛完一份都没有」和「一份都没写过」是两句不同的话：
      前者给「看全部」（一条回去的路），后者给「写一份」（一条开始的路）
  - **「我的」是屏幕正中间的一个弹窗**（`s-me.vue`，2026-08-31 用户定）：

    断点跟外壳同一个 900px（不另立一个，否则「什么时候变宽」在两处各写一份）
    - ⚠️ 「个人档案」那一行**跟编号列的左边缘对齐，不是跟记忆正文对齐**
      （用户 2026-08-21 定、08-31 又指出一次）：缩进到正文那列会让它看起来像第 0 条记忆的内容
    - 🔴 `GET /me/quota` 回的是 `{ quota: {text, image}, grants, free_revisions }` ——

  - 🔴 **抽屉不能靠「从左边缘右滑」打开。** iOS Safari 把那个手势占用成「后退」，

  - **宽屏上正文不拉满**：一份教案两千多字，一行超过 40 个汉字眼睛会串行。

  - ⚠️ 认下来的代价：汉堡在**左上角**，右手拿手机时那是拇指最够不到的角，
    而且进教案库从一下变两下。用户 2026-08-30 知情后仍选了它（要跟宽屏一致）
- **顶栏不放返回箭头**（2026-08-30 用户定）：浏览器自带后退键和右滑返回，重复了。
  顶栏左边那个汉堡**不是返回**，它开的是侧边栏
  - 🔴 由此推出：**生成完跳成稿、激活完进首页、改稿完回成稿，三处必须 `router.replace`
    而不是 `push`** —— 否则后退会把她带回「生成中」「已经用掉的激活页」，而且不报错

  - ⚠️ 从别人发的链接直接打开某一页时**没有历史记录**，后退会离开整个网站。

- ✅ **`/redeem` 和 `/login` 都有「已登录就直接去首页」那道判断**，**从 `eb0e351` 起就有**。

  - 所以把 `/redeem` 当唯一入口发给老师是**成立**的：已登录的进去看不到激活页，

  - ⚠️ **这一条是写来止损的**：2026-09-21 我在对话里反复说「`/redeem` 还差一个已登录判断」，
    而**一次都没查过那个文件** —— 它一直是好的。**凭印象重复一件事，比不知道更糟**，
    因为对方会信。要提一个「还没做」的项，先 `grep` 一眼

  - 2026-08-17 用户拆掉了两样原属方向 B 的东西：**左侧竖向序号刻度轨**

  - **场地很重要**：户外空地搭跷跷板 vs 教室区角做桌面游戏，活动形态完全是两回事
  - **不问时长**：年龄班一定时长就定了，再问是让老师替代码做算术

### 数据与合规

- **不存幼儿的任何信息。** 这条永远不变。禁的是**个体信息**：姓名、生日、照片、
  家长联系方式、任何一个孩子的能力评价或行为记录。判据：这条数据是关于孩子的，
  还是关于机构/老师的？关于某个孩子的一律不存
- **汇总规模不算个体信息**（2026-08-18 用户确认）：园所档案里的「在园幼儿人数」是一个
  机构规模数字，跟「在园教师人数」同类。**但界线只到这儿**：不许出现按班级、按年龄段、
  按任何维度拆到能定位到人的幼儿数据
- **老师的手机号和姓名要存**，但三条铁律：**永不下发前端、永不进模型提示词、永不进日志**；
  **幼儿园管理者看不到任何老师数据**（这条要在协议里加粗明示 ——
  老师最怕的是园长看到她用 AI 写教案）
- **记忆抽取的合规红线**：不提取姓名、年龄、幼儿表现、家庭情况、**健康与过敏**。
  ⚠️ **没加关键词黑名单**：中文自由文本既会误伤（「材料要防误食过敏源」是合法的）
  又绕得过，加了只会给人「已经防住了」的错觉
- **老师输入和 AI 输出都要过内容安全** —— 走**阿里云内容安全**（`TextModerationPlus`），
  实现是 `services/contentSafety.js`，**操作手册在 `docs/design/content-safety.md`**。
  两个调用点各有对口的 service：老师输入用 `llm_query_moderation`（上限 2000 字），
  AI 输出用 `llm_response_moderation`（上限 5000 字）。
  🔴 **超过字数上限要分段送审，不许静默截断** —— 截断等于后半截没审，而它看起来跟审过一样。
  ✅ 2026-09-01 已开通并实测调通，**个人实名账号可以开**；**2026-09-22 代码接完**。
  🔴 **必须用 POST**（GET 回 `UnsupportedHTTPMethod`），且**权限给了也要单独开通商品**
  （没开通报 `Code=408 · haven't activated the commodity`，跟 RAM 权限无关）
  - 开关与凭据分开：开启后缺凭据会启动失败；超时、业务错误、格式不明均暂停提交，返回可重试的 `CONTENT_CHECK_UNAVAILABLE`（503）。
  - 只有明确无风险结果放行；其他风险标签或 low/medium/high 均拦截。供应商异常原文不入日志。
  - 启用审核时不提前流式显示正文；标题、正文和结构化内容审核后才展示。局部编辑审核合并后的完整内容。
  - ⚠️ **不用官方 SDK**：`@alicloud/green20220302` 拖 7 个以上间接依赖，
    而后端一共 8 个直接依赖。POP 签名（HMAC-SHA1）用 `crypto` 十几行写完
- **API key 只在服务端**，任何情况不下发到浏览器
- **日志不记录对话正文**

## 容易犯的错

**年龄班规则必须真正生效，不能只写在提示词里。** 那本台湾教材的案例默认孩子会言语预测、
会读量杯刻度、能小组分工 —— 这是中大班能力。3–4 岁小班做不到。三层保障
（`backend/src/services/promptBuilder.js`）：

1. 只注入当前年龄班的规则（三个班一起给，模型会挑最丰富的那套，这是给小班写出大班活动的根因）
2. 时长选项由代码从参数表算（选小班界面就没有 45 分钟这个选项）
3. 生成后代码硬校验（小班出现量杯读数/预测/统计图表/缺误食风险 → 记入 `age_band_violations`）

参数表（2026-08-24 定死）：小班 20 分钟 / 3 环节 / 2 指标；中班 25 / 4 / 3；大班 30 / 4 / 4。
**大班 30 分钟仍写四环节**（那一段「换个法子再试」是探究循环的核心）。

**小班的 STEAM 不必五域齐全。** 模型天然倾向凑满五个显得完整，会给小班写出
「统计浮沉数量并绘制条形图」。规则是 S+A 为主、E 可缺席，**宁可诚实标注缺席，不要虚假齐全**。
⚠️ 但这条许可**只给小班** —— 给大班留同样的退路，等于**把违规包装成专业判断**，
老师没有线索去质疑。

**《指南》指标引用的是「某一句典型表现」，不是「目标名」**（2026-08-24 同一天改了两版）。
目标名三个年龄段共用，输出里看不出这条对应哪一档。格式是用户点名要的：
`科学 （一）科学探究 目标1：喜欢接触新事物，经常问一些与新事物有关的问题。`
—— 带完整位置（子领域**保留「（一）」序号**），老师能在原书里精确翻到那一句。

- 年龄段错配自动被剔除：句子只在它那一档的清单里
- 匹配**只认句子、不认目标名** —— 拿目标名匹配等于放过「抄了别档句子」
- 拆句正则只认「行首/空格后的 数字+点」：直接按数字加点拆会把
  「身高：94.9-111.7厘米」拆坏
- ⚠️ 有个目标的典型表现数组有第 4 条，那是**脚注**不是第四档，所以按下标取、别遍历

**「能跑起来的脚本才叫回归」**（2026-08-20 查出来两处）。`smoke.js` 当时**根本跑不起来**，
而 CLAUDE.md 里一直写着「冒烟脚本 npm run smoke」。更糟的是 `enforceAgeBand` 的反向测试
**从来没有脚本** —— 一个空转的校验和一个严格的校验，输出**完全一样**：都是零违规。

**白名单和硬校验是同一类风险：生效和不生效，正常输入下输出一模一样。**
教案解读那道白名单（`normalizeCommentary`）就是这样 —— 区别只在模型哪天多写一个键的时候
出现，而那一天不会有人在看日志。所以写它的时候就得同时写一条「喂它白名单外的东西」的断言。

**报「坏了」之前先确认那东西真的存在。** 2026-08-21 撞到一次：交接文档写着
「档案编辑和成稿编辑**界面上有入口，点了没反应**」，而核过之后那两个入口**根本不存在** ——
API 层的函数写好了，没有任何页面调用它。「有入口但点不动」和「压根没入口」要做的事
完全不同（前者是修，后者是做）。**上一轮的自己也是二手信源。**

**判据要找那种「旧代码不可能产出的特征」。** 用户报「指标没标位置」，而那份教案是
「中班 30 分钟」—— 新代码任何中班教案都不可能超过 25 分钟。比问「你重启了吗」快。

**「开关真实生效」不能只测「开」那一侧。** 默认开启的能力上，「不发参数」和「发 disabled」
是两件完全不同的事。而且一个作用于所有调用的全局开关，验收必须包含「开着它跑一遍冒烟」。

**验证工具本身也要验证。** 三次真实事故：
① 六个回归脚本把端口写死、不读 `API_BASE`，所以「另起一个端口跑回归」那条说明**一直是假的**；
② `versions-test` 里一条断言**在任何人点过一次「设为默认」之后必然红** ——
它测的东西跟它守护的规则**方向相反**；
③ 一条断言写在一个进不去的分支里，第一次跑**全绿，其实一条都没执行**。

**DATE 列会被时区挪掉一天。** pg 默认把 DATE 解析成「本地时区午夜」的 Date，
序列化成 JSON 之后东八区变成**前一天**。`db/pool.js` 给 oid 1082 设了原样解析。
顺带查出**任务的截止日期一直在被改坏**：编辑弹窗把前一天填回输入框，
一保存就真的存成前一天 —— **每打开保存一次退一天**，全程不报错。

**界面上不要写解释性小字。** 这是最常犯的一条（用户提过至少七次）。
写每一句副标题、每一段 note 之前先问一句：**她不看这句话会做错什么吗？** 答不出来就删掉。
「为什么这么设计」属于代码注释和设计文档，**不属于界面** ——
把设计理由印在屏幕上，是拿使用者的注意力替我记笔记。

只有两种小字留得住：

- **边界说明** ——「超管可见全号」这类。不说她会以为是 bug 或数据坏了
- **不可逆动作的后果** —— 注销那两次确认。「不可逆」三个字必须出现在她按下去之前

判断标准不是「这句话对不对」，而是「删掉它，她还能不能把事办成」。能，就删。

**亮色只做底，深色只做字。** 色板里四个亮色明度都在 0.72–0.85，做大面积底配深墨字很好
（7–9:1），但做文字色时只有 1.5–3:1，全部不达标。需要彩色文字时用对应的 `-deep` 档。

**「用 deep 档」本身不等于达标**（2026-08-20 量出来的）。旧 `$mint-deep` `#3E8F5D`
配白字只有 **3.97:1** —— 这条规则写在 design-tokens 里一年，而它保证的那件事从来没成立过。
已压暗到 `#327648`；`$ink-3` 也从 `#7A7368` 压到 `#736D62`。
**色彩规则不能只写成文字 —— 写了一年没被执行的规则等于没有。**

**颜色不做状态的唯一载体。** 黄色在奶油底上先天到不了 3:1，草稿/已完成必须同时有文字。
**选中态也算**：选中胶囊的黄底和未选中的奶油底亮度差只有 **1.51:1**，
也就是说「哪个被选中」几乎全靠色相 —— 而色相正是色觉障碍者拿不到的那一维。
现在选中的胶囊一律多一个打勾。

⚠️ 反过来，**装饰性发丝线故意不满足 3:1**（`$rule-2` 压主底只有 1.39:1）。
3:1 管的是「不看它就读不懂内容」的构件，而卡片是靠白底压奶油底区分的，描边只是收个边。
真把每条描边提到 3:1，这套设计会变成一张硬灰格子。

**字号只有八级，而且必须走令牌。** 收口前有 90 多处硬编码 `font-size`：
25/26/27px 这种一像素的区分纯粹是噪音，还有十几处低于设计文档自己定的 12px 下限。

**生成教案要 15–30 秒，必须异步 + 轮询。** 而且**必须能离开** ——
老师在幼儿园随时被叫走，不能要求盯着屏幕等。

**等待那一屏摊的是正文本身，不是进度文案**（2026-08-25 用户定）。模型流式吐字，
`planStream.readablePrefix` 把半截 JSON 翻成人话，轮询带游标只回新增的那一段。

- 🔴 **只增不减是整套增量协议的地基**（`planStream.js` 文件头两条纪律 + `npm run test:stream`）：
  破了它前端会把两段不相干的文字拼在一起，**HTTP 200、日志干净、教案照样生成成功**。
  两条纪律：**键名没收全一个字都不发**、**结尾绝不 trim**
- 🔴 **epoch 和 from 缺一不可** —— 模型被截断会重打一遍，只有 from 的话
  她会看到两份教案首尾相接。对不上就 `restart:true` + 全量，前端清屏
- 🔴 `stream_options` 里的 `include_usage` **不是可选的**：不带它流式响应一个 token 数都不回，
  而 `model_calls` 那笔账是当场落库的事实。哪家中转不认这个参数会 400，
  所以**加了一道降级**（第一次流式失败就关掉流式重来一次）——
  不降级的表现是「换了模型之后教案再也写不出来」，而错的只是一个显示功能
- **显示要慢放**：放字速度 = 积压量的十二分之一（至少 2 字）——
  定速放字的话模型写得比放得快时，她会在教案早就写完之后还盯着字往外爬
- **`PROGRESS_HINTS` 那四句已删，别照旧稿加回来**

**每答一题即落库。** 老师会被打断，进度不能丢。

**「无网」的判据是两个条件同时成立**：请求没到后端 **且** 系统报告断网 ——
只看前者会把「网络正常、后端连不上」画成无网。**网一回来自动重来一次**。

**别在失败的时候画成空。** 任务页把「拉不到」渲染成「现在没有可以做的事」，
「我的」渲染成 `0/0 次教案`。假话的代价是她不会重试，她会走。

**生成页把失败分成两种**：断网走「接着等」（只重新轮询，后端还在写，不花钱、可自动），
真没写成走「再试一次」（一次真的模型调用）。原来这两条走同一个按钮 =
每次弱网抖一下就白花一次钱重写一遍。

**「还没有人评价过」这句话以前是错的**（2026-08-18 查出来）：库里其实已经有评价，
只是概览那句 SQL 查的键名跟真实值差一个前缀。
**报「没有数据」之前先确认查的是不是对的字段** —— 一个 typo 能让唯一重要的指标
静静地消失，而且看起来完全正常。

⚠️ **HTML 注释写在模板字符串里不能用反引号**，累计踩过八次：后台的视图全是模板字符串，
注释里一个反引号就把字符串截断，报的 `SyntaxError` 指向的行看起来完全正常。
改完 `node --check backend/admin/*.js` 过一遍。

⚠️ **`.bat` 文件必须是 CRLF 换行。** 2026-08-31 踩过：`teacher.bat` 用 Write 工具写出来是 LF，
cmd.exe 逐行解析时把中文注释切错位，报出一串
`'---' is not recognized as an internal or external command` —— 报错指向的内容跟真正的原因
（换行符）毫无关系。`admin.bat` 一直是 CRLF，所以它没事。
改完 `file *.bat` 看一眼有没有 `with CRLF line terminators`。

⚠️ **「改了没生效」先查端口被谁占着**（`netstat -ano` 找 3100），按 PID 杀。
`kill %1` 在新 shell 里杀不到上一个 Bash 调用启动的进程，新进程 EADDRINUSE 静默退出，
**应答的一直是旧代码**。

## 1. 产品是什么

一款帮**中国大陆幼儿园老师**撰写 STEAM 教案的**微信小程序**。老师说一个想法（"我想做个浮与沉的活动"），AI 分 2–3 轮引导提问，每题附可点选的推荐答案卡片，最后生成一份结构完整的教案，可选配图。

底层知识框架来自《臺北市幼兒STEAM教案彙編成果輯》提炼的教学理念、8 条质量标准和教案模板（详见 `framework-extraction.md`）。

## 2. 目标受众与使用场景

- **人**：22–45 岁女性为主的一线幼师，教龄 0–20 年不等。非设计人群、非科技尝鲜人群。日常审美来源是幼儿园环境布置、班级家长群、小红书、微信读书这类界面。
- **场景**：下班前 20 分钟、午休、或晚上在家躺着，**单手握手机**，在嘈杂或疲惫状态下断续使用。可能被打断，回来要能接着上次继续。
- **心理**：写教案是任务、是负担，不是创作享受。所以界面要让人觉得"轻松、不费脑、几下就完事"，**不能让人觉得又在填一张表**。
- **打字意愿极低**——这是最重要的约束。所有引导问题必须优先做成**可点选卡片**，输入框是补充手段而非主要手段。

## 4. 情感基调与气质关键词

> 2026-08-16 用户修订：初版偏冷（墨蓝系）被判定"太科技感、太冷"，方向调整为**明亮温馨、偏女性/童真**。

**明亮、温馨、柔和、有条理、可信赖。**

- ✅ 要的：暖色调、让人放松、像一件贴心的小工具、有一点点童真的柔软
- ❌ 不要的：科技感、赛博、暗色 SaaS、企业级效率工具、冷色调

⚠️ **温暖柔和 ≠ 卡通糖果**。受众是**老师**不是**孩子**。不要吉祥物、不要 emoji 当图标、不要高饱和撞色轰炸、不要彩虹渐变——那是给孩子的产品语言，老师会觉得幼稚且不专业。温度来自**暖底色、柔和主色、适度圆角、留白节奏**，不来自卡通元素。

目标感受：老师觉得"这个工具很舒服很贴心"，而不是"这是给小孩玩的"。

- 画布：**1680 × 1050**，平铺 **5 台手机**（屏 1–5 横向排列，可换行成 3+2）
- 每台手机视口 **390 × 844**（iPhone 14 尺寸，微信小程序主流机型）
- 设备框用 skill 的 `assets/ios_frame.jsx`，**禁止手写灵动岛/状态栏/home indicator**
- 每台手机上方标注屏名（屏 1 首页 / 屏 2 引导对话 …）
- 至少屏 2 做成**可交互**（推荐卡片可点选、选中态可见）
- 截图命令：`npx playwright screenshot file:///path.html out.png --viewport-size=1680,1050`

## 6. 已知约束

- **语言：全简体中文**。原书是繁体，所有文案必须用大陆幼教习惯用语（用"小班/中班/大班"不用"K1/K2/K3"，用"教案"不用"教學方案"）
- **年龄班必须是三档：小班 / 中班 / 大班**，一个都不能少（原书案例偏中大班，但产品必须支持小班）
- 微信小程序语境：顶部有微信胶囊按钮区域（右上角需留出安全区），底部 tab bar 是标准形态
- 可读性硬底线：正文 ≥14px、辅助文字 ≥12px、正文对比度 ≥4.5:1
- 不使用 emoji 作图标
- 不编造 stats 数字做装饰
- 不用真实儿童照片（隐私风险）

## 7. 图片需求判断（Phase 3.5 结论）

**判定：图片非内容必需，本轮不取真图。**

理由：这个产品的内容是**文字教案**，界面的信息主体是文本、卡片和结构。装饰性插画在这里是 slop——去掉它信息无损。温度靠底色、纸感、字体、留白、分隔线做，不靠配图。

例外：屏 3 的"生成配图"按钮位置可留一个**诚实的占位**（灰块 + "配图待生成"），不要画假插画。

## 8. 视觉母题假设（每版必须回答"form 来自内容的哪里"）

这个产品独有的、别的 App 不会有的视觉母题候选：

- **"一轮一轮的提问"** → 可以是层叠的纸、可以是进度刻度、可以是逐段展开的目录
- **"教案的四个环节"**（引起动机→发展活动→综合活动→延伸活动）→ 天然是一条有节奏的时间轴
- **"STEAM 五个字母"** → 五个可标注的维度标记，是这个产品独有的信息结构
- **"探究循环"**（预测→实作→观察→讨论→改进）→ 环形/循环母题
- **"备课本"** → 纸张、横线、手写标注、便签

每版选一个作为 form 的种子，交付时用一句话说明。

## 9. 三版必须互异的地方

三个方向的**布局骨架必须结构性不同**，不许只换色换字体：

| | 方向 A | 方向 B | 方向 C |
|---|---|---|---|
| 首页骨架 | 不等高模块网格 | 由参照案例决定，须区别于 A/C | 单列长流，无卡片容器 |
| 对话屏骨架 | 卡片阵列 | 由参照案例决定 | 纸张/单列文档感 |
| 容器语言 | 卡片有明确边界 | 由参照案例决定 | 分隔线驱动，弱容器 |

## 10. 真实文案（三版共用，不许用 Lorem，不许改写）

## 1. 教案引导对话系统提示词（核心）

### 版本：1.0（MVP）

```
你是一位经验丰富的幼儿园STEAM教学设计专家。

你的角色：
- 通过多轮对话，引导幼儿园老师从初步想法逐步完善成一份结构完整、高质量的STEAM教案
- 遵循台北STEAM教案最佳实践框架
- 理解老师的实际约束（年龄班、场地、时间、器材），给出符合现实的建议

你的对话风格：
- 建设性、鼓励性：尊重老师的创意，在此基础上优化
- 轻松友好：用易懂的语言，避免学术术语
- 逐步细化：从大框架→细节，分轮推进
- 提供选项：每个问题都附带2-3个推荐答案，老师可点选或自填

你对教案质量的理解：
- 核心理念：问题必须源自幼儿真实生活或教室情境，而非教师预设
- 探究循环：必须包含"预测→实作→观察→讨论→改进"的多个循环，才能深化学习
- STEAM融合：5个领域（科学、技术、工程、艺术、数学）在同一活动中有机连接，不是简单拼凑
- 师生互动：教案中体现具体的课堂对话，显示幼儿真实思维过程
- 工具与测量：引入标准化工具（量杯、尺、秤）不是一开始就有，而是幼儿在探究中发现需要而主动采用
- 循环性与渐进性：多个实验循环逐步精细化，如10cc/20cc/30cc等变量递进

教案的标准结构（你生成教案时必须包含这些部分）：
1. 基础信息：年龄班、适用时长、所需材料、STEAM标注
2. 教案特色说明：问题来源、幼儿将获得的学习经验（3-5条）
3. 教学流程四环节：
   - 引起动机（现象→好奇→问题）
   - 发展活动（预测→实作→观察）
   - 综合活动（分享→讨论→改进）
   - 延伸活动（迁移或区角深化）
4. STEAM知识概念表（每个领域具体是什么）
5. 幼儿学习指标（2-4个，必须在教学实例中有体现）
6. 教学实例说明（含师生对话 T/C标注，包含失败→改进过程）

【年龄班适配规则 · 强制遵守】（完整依据见 age-band-adaptation.md）

老师确定年龄班后，你必须按该年龄班的发展水平调整教案，不得套用统一模板。

小班（3-4岁）：
- 时长 15-20 分钟，最多不超过 25 分钟
- 探究循环 1-2 个，不要求幼儿做预测，改为"先玩→发现→再玩一次"
- 教学流程只做 3 个环节，不做 4 环节
- 测量只用非标准单位（用手比、用积木叠、目测比多少），禁止出现量杯读数、称重克数
- 记录只用贴纸、盖章、涂色，不写字不画细节
- STEAM 不必五域齐全：S 和 A 为主，M 以"多/少、大/小"出现，T 是"会用某个工具"，E 可以缺席
  ——宁可如实标注某个领域未涉及，也不要为了凑齐而写出小班做不到的环节
- 学习指标只选 1-2 个
- 师生对话中，幼儿的回应应是单词、短句或动作，不要写出带因果推理的完整句子
- 安全事项必须包含误食风险（材料尺寸需大于幼儿口腔）

中班（4-5岁）：
- 时长 25-30 分钟；循环 2-3 个；4 环节完整
- 可做二选一预测；非标准单位为主，可引入标准工具做整数比较
- 记录用简笔画、勾选表；STEAM 四域较完整，E 以"改一改让它更好"出现
- 学习指标 2-3 个

大班（5-6岁）：
- 时长 30-40 分钟；循环 3 个以上；4 环节完整
- 预测需带理由；可读简单刻度并记录数字
- 记录用符号、数字、表格；STEAM 五域齐全且相互关联
- 学习指标 3-4 个；可设计跨多次活动的长线探究

生成教案后自检：这份教案里有没有该年龄班孩子做不到的动作？
特别检查：预测、读数、书写、小组分工、集体讨论、长时间专注——这几项最容易超出小班能力。

【语言规范 · 强制遵守】
- 全程使用简体中文，采用中国大陆幼教习惯用语
- 用"小班/中班/大班"，不用"K1/K2/K3"或"幼幼班"
- 用"教案"不用"教學方案"，用"活动"不用"活動"
- 底层框架源自台湾教材，但所有输出必须完成用语本地化，不得出现繁体字或台湾特有表述

你对推荐答案的设计原则：
- 推荐答案应该反映老师的历史教学习惯和约束条件（从他的个人档案和记忆库中吸收）
- 推荐答案要多样化，不强制标准答案；老师可以自填
- 如果老师已多次提过某个约束（如"没投影仪"），不需要每次都问，可以假设它并跳过

用户档案和记忆注入（以下信息已在前文给出，融入你的对话）：

### 对话管理策略

**轮数和提问数**（MVP简化版，后续可改成状态机）：
- 第1轮：基础信息（3-4题）→ 推荐答案以卡片形式呈现
  - Q1: 目标年龄班（推荐：[小班] [中班] [大班] 或 [与我档案一致]）
  - Q2: 教学重点是什么（推荐：[理解科学原理] [体验现象] [学习技能] 等，根据主题）
  - Q3: 活动时长（推荐答案随 Q1 年龄班变化：小班 → [15分钟] [20分钟] [25分钟]；中班 → [25分钟] [30分钟] [35分钟]；大班 → [30分钟] [40分钟] [45分钟]）

  - Q7: 关键提问设计（推荐：[开放预测的问题] [观察追问] [问题求解] 等6种类型中的例子）
  - Q8: 安全事项（推荐：[预防摔伤] [工具安全] [卫生事项] 等，必答）

- 第3轮（可选）：优化细化（2-3题，用户可跳过）

- 用户在任何阶段可点击"我已经想好了，直接生成教案"跳过后续轮次

## 5. 迭代与优化记录

### MVP（当前实现，2026-08-16 更新）

原计划「纯 prompt 驱动，AI 自行决定问几题」**已废弃，直接做成了状态机**。

**为什么改**：api-spec 要求教案库显示稳定的进度（「进行到第 1 轮第 2 题，还剩 1 题」）并支持断点续写。模型自由决定问几题的话，进度条没有分母，断点也无从记录。所以原计划的 Phase 2 被提前到了 MVP。

实际实现（`backend/src/services/guideFlow.js`）：
- 11 题三轮固定骨架，轮数与题号由后端控制
- **题干与推荐答案由模型生成**（保留个性化），但年龄班相关的选项（如时长）由代码从参数表直接算出，不经过模型
- 每答一题即落库，模型调用失败时降级为兜底选项继续走，不阻断老师
- 全量记忆注入（无向量检索），记忆上限 60 条

**年龄班规则的三层保障**（`promptBuilder.js` + `lessonGenerator.js`）：
1. **只注入当前年龄班的规则**——三个班的规则一起给，模型会挑最丰富的那套，这是给小班写出大班活动的根因
2. **时长选项由代码算**——选了小班，界面上根本不存在 45 分钟这个选项
3. **生成后代码硬校验**——超时长自动改回上限；小班出现量杯读数、统计图表、预测环节、小组分工，或缺少误食风险提示，全部记入 `quality_self.age_band_violations`
