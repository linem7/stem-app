## 会绊倒你的四件事

### 1. `rpx → px`：**已定，除以 2，页面套最大宽度**（2026-08-30 用户定）

uni 的 `rpx` 基准是 750（750rpx = 屏幕宽），所以旧代码里所有尺寸都是「375pt 设计稿 × 2」。

**做法**：`rpx ÷ 2 → px`，页面套一个 `max-width` 居中。

```css
.btn  { height: 44px; font-size: 15px; }   /* 原 88rpx / 30rpx */
.page { max-width: 480px; margin: 0 auto; }
```

**宽度、卡片、列表照样弹性**（撑满可用宽度、用 flex/grid），**只有字号和间距是固定的**。
1440px 的屏幕上就是中间一条 480px、两边留白。

**没走「根字号跟视口宽走」那条（rpx ÷ 20 → rem）**，两个理由：

1. 它会跟**字号三档可调**（标准/大/特大，正文 15/17/20px）打架 —— 字号也跟着屏宽走的话，
   大屏上的「标准」可能比小屏上的「特大」还大，那三个档就不再代表固定的东西
2. 它会盖掉用户自己在浏览器里调过的字号（视力不好的人常调）

⚠️ 认下来的代价：**320px 宽的小手机上会略挤**。真挤到不能用时，
在那一档加媒体查询局部收间距，**不要把整套改回等比缩放**。

### 2. 顶栏的返回箭头删掉，靠浏览器后退（2026-08-30 用户定）

小程序里 `navigationStyle: custom`，**`s-topbar` 的「←」是唯一的返回入口**。
浏览器自带后退键和右滑返回，这两样重复了，所以**「←」整个删掉**。

`s-tabbar`（首页 / 教案库 / 我的）**保留** —— 浏览器没有等价物。

🔴 **删了「←」之后，三处必须用 `router.replace` 而不是 `push`**，否则后退会把她带到
一个不该回去的地方，而且**不报错**：

| 场景 | 不处理会怎样 |
|---|---|
| 生成完自动跳成稿页 | 按后退回到「生成中」那一屏，而那次生成早就完了 —— 她会以为卡住了 |
| 激活成功后进首页 | 按后退回到激活页，而码已经用掉了 |
| 改稿完成后回成稿页 | 按后退回到「正在重写」 |

⚠️ 还有一种**没有历史记录**的情况：她从别人发的链接直接打开某个页面，
这时按后退会**离开整个网站**。所以那类页面上仍然要有一个明确的「回首页」出口 ——
删掉的是顶栏那个通用「←」，不是所有出口。

### 3. 教案库的左滑删除在桌面浏览器上不存在

手势是自己算的（先判方向再接管，滑动后压掉尾随 tap）。触屏上照搬得动，
**但桌面要给等价入口**（悬停出现删除键或右键菜单）。
二次确认那一步不能省 —— 删教案不可逆，这是 08-25 推翻「点了就删」之后定的。

### 4. 流式撰写的增量协议一个字都不能改

后端 `planStream.js` 和 `taskQueue.js` 已经跑通并有 33 条回归（`npm run test:stream`）。
前端那一侧要重接，两条纪律必须保住：

- 🔴 **`epoch` 和 `from` 缺一不可。** 模型被截断会重打一遍，只有 `from` 的话
  她会看到两份教案首尾相接 —— 而 **HTTP 200、日志干净、教案照样生成成功**
- **显示要慢放**：放字速度 = 积压量的十二分之一（至少 2 字）。定速放字的话，
  模型写得比放得快时她会在教案早写完之后还盯着字往外爬
