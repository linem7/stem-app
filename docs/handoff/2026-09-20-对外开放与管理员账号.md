## 一、这一轮真正查清的事实

### 1. 服务器上跑的代码就是当前工作区的代码，不用重新部署

这一轮一开始的请求是「帮我部署上去」。查下来发现 `/opt/stem-app`（2026-09-01 部署的那份）
和当前工作区**逐字节相同** —— 验证方法是：

```bash
diff --strip-trailing-cr -rq /opt/stem-app /root/workspace/stem-app \
  -x node_modules -x .git -x .local-images -x dist
```

**零差异。** `/opt/stem-app` 是 `git archive` 解开的，`autocrlf` 让服务器上那份是 CRLF，
所以直接 `diff -rq` 会满屏报「differ」，**必须加 `--strip-trailing-cr`** ——
不加会误判成「服务器上是旧代码」，然后白白重传一遍 44MB。

**下次别再重新摸一遍**：判「服务器上是不是最新代码」的正确命令就是上面那条。

### 4. 🔴 `PUBLIC_BASE_URL` 是个真 bug，已修

`services/imageStore.js` 的 `buildImageUrl()` 用 `config.publicBaseUrl` 拼配图地址，
而这个值是 `http://127.0.0.1:3000` 时，返回给老师的配图 URL 是
`http://127.0.0.1:3000/local-images/xxx.jpg` —— **在她手机上指向她自己的手机，图打不开**。

这个 bug 是**症状隐蔽**那一类：后端日志干净、接口 200、数据库里有图，
只有真拿手机看才会发现。**以后改域名/换 IP，第一件事就是改这个变量。**

⚠️ **它现在写的是公网 IP，所以将来上域名 + HTTPS 时必须再改一次**，否则配图还是走 IP。

### 现在的账号

已经提醒过他：想稳妥就进后台改一次自己的密码。

### 怎么做的（顺序要紧）

1. **用项目自己的 `createAdmin()` 建 `lin`**，不手写 INSERT ——
   它会做用户名格式校验、密码长度校验、用户名查重、scrypt 加盐哈希
2. **先验证 `lin` 能登录，再去停用 `admin`** —— 顺序反了就是「两个都进不去」
3. **停用走后台自己的接口** `POST /admin/api/admins/:id/status`（以 `lin` 身份），
   不手写 SQL —— 它会过「不能停用自己」「最后一个超管不能被停用」两道守卫，
   并且**记 `admin_logs`**：

```
admin_id=2  admin_status  admin:admin  {"status": "disabled"}
```

### 🔴 这个表上没有数据库层的保护

`admins` 表只有 `PRIMARY KEY`、`UNIQUE(username)`、一个外键。
`role` 和 `status` 是**自由文本列，没有 CHECK 约束**。

也就是说 **「最后一个超管不能被停用」这条规则只活在代码里**（`routes/admin/admins.js:49`），
一个手写 `UPDATE admins SET status='disabled'` 能把自己锁死，数据库不会拦。
**动 `admins` 表一律走接口。**

### `admin` 那行为什么留着不删

1. `ensureSuperAdmin()` 只在**管理员表为空**时播种，且会**再建一个叫 `admin` 的** ——
   删掉它不解决问题，重启后可能又冒出来
2. 留着是一条后路：`lin` 密码真丢了，那行还在库里，可以救回来
3. 符合这个项目「**留壳去身份**」的一贯做法（注销老师那套同款思路）

## 四、问卷站 —— **没动手，挂着等你明天定**

用户想在**同一台服务器**上再放一个网站：**填写问卷的网站，比较轻量，
也需要一个管理端，但不面向公众、只他自己看**。

我**没有动任何配置**，因为有三件事没定清楚，而且我提的两个方向都会
**当场弄坏现在能用的两个网页**：

### 🔴 先说清楚：不能「改端口」

用户原话是「先改端口为下一个网站的部署提供准备」。**这件事不能做**：

- `stem-app` 占着 3000，nginx 反代指向 `127.0.0.1:3000`
- 把后端挪走而不改 nginx → **教师端和后台当场全挂**
- 把 nginx 的 80 让给新站 → **用户现在就访问不了 stem-app**

**正确做法是新增一个端口给新站，3000 和 80 原样不动。两个站并存。**

### 服务器的余量（实测）

| 资源 | 总量 | 已用 | 余量 |
|---|---|---|---|
| 内存 | **1.6 GiB** | 998 MiB | **400 MiB**，**swap 是 0** |
| CPU | 2 核 | — | 够 |
| 磁盘 | 40 GB | 9.4 GB | **28 GB** |

⚠️ **内存是唯一紧的地方，而且 swap 是 0。**

**我建议加 2GB swap，用户明确说「不用加 swap」，没加。** 如实记下来，
但要写清楚代价：再加一个 Node 服务之后，峰值一来就是 **OOM Killer 随机杀进程**，
而它的表现是「服务突然没了」、`systemctl status` 只显示 killed、**看不出根因**。
**同一台机器上还跑着 PostgreSQL，被 OOM 杀掉会丢未落盘的写入。**

（注：量的时候 `claude` 进程占 18% 内存，那是开发会话本身，会话结束就释放。
真实余量比 400 MiB 宽松一些，但仍是这台机器最紧的资源。）

### nginx 现在的形状决定了新站怎么放

现在只有**一个** server 块：`listen 80 default_server; server_name _;`
—— 它是**兜底站点**，谁的请求都归它。

同一台机器放第二个站，只有两条路，**都要求有域名**：

| 做法 | 怎么区分 | 需要什么 |
|---|---|---|
| **域名（推荐）** | nginx 按 `server_name` 分流 | 两个域名各自解析到 `115.29.167.18` |
| **端口** | 第二个站 `listen 3001` | 不用域名，但要开安全组 3001 |

🔴 **用户现在是裸 IP、没有域名**，所以**第二个站只能靠端口区分**。
而裸 IP 上办不了 HTTP 备案、拿不到 HTTPS 证书（Let's Encrypt 不给 IP 签证书）。

### ⚠️ 「不面向公众」不能靠「不告诉别人地址」

这个 IP 是公网可访问的，扫描器几天内就会找到 3001。
**问卷站如果对外，别人填的表单数据他会收到** —— 那就变成公开收集数据了。

     不能靠路径隐藏
