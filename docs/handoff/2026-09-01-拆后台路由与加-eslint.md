# 交接：拆后台路由 + 加 eslint（2026-09-01）

起因是用户的同事看了仓库，说「看不出框架、一堆 js 文件混在一起、不好维护」，
还建议改用 Django 重写（理由是「调 LLM 用 Python 最友好」）。

结论：**不换 Django，但同事有一部分说对了。** 这一轮把说对的那部分做掉。
决策过程和数字见下面「为什么不换 Django」。

## 一、做了什么

| | 之前 | 之后 |
|---|---|---|
| 后台 API | `src/routes/admin.js` **2736 行 / 50 个路由** | `src/routes/admin/` **11 个文件**，最大 501 行 |
| 代码检查 | 无 | 前后端各一份 `eslint.config.js`，`npm run lint` |

### 拆分后的目录

```
src/routes/admin/
  index.js          Router 组装 + /login + 挂载顺序   (导出 adminRouter, requireAdmin)
  _shared.js        requireAdmin / requireSuper / maskName / maskPhone / sendXlsx
  overview.js  121  概览

  codes.js     390  兑换码

  content.js   182  内容与反馈
  tasks.js     172  任务
  admins.js    215  管理员账号
  models.js    397  模型管理
```

🔴 **`index.js` 里的挂载顺序就是路由匹配顺序，别随手调。** Express 从上往下试，
换了顺序不报错，只会让某个路由再也走不到。

⚠️ **拆的时候发现的一件事**：「批量建码」和「导出 CSV」原来掉在文件**最末尾**、
夹在模型管理后面，跟兑换码那一节隔着一千多行。一个文件长到 2700 行的时候，
「相关的东西放一起」这条会**静默失效** —— 这就是拆它的理由本身。现在合回 `codes.js`。

### 怎么确认「只搬没改」

不是靠看，是**对拍路由表**：把拆分前的版本从 git 取出来，和新版各自把
`adminRouter` 的路由栈打平（路径 + 方法 + 顺序 + 每条挂了几个 handler），逐行 diff。

结果：50 条路由，**48 条完全相同**，只有 `/codes/batch` 和 `/codes/export`
从队尾（49、50）挪到兑换码组里（20、21）—— 正是上面那次有意的合并。
`GET /codes/export [handlers:2]` 说明 `requireSuper` 跟着搬过来了，没掉。

移动是安全的，核过：那两条都是**两段**路径，而前面的 `/codes/:id/void`、
`/codes/batches/:id` 是三段，盖不住它们；26 条之后再没有 `/codes` 开头的路由。

### eslint 的取向：只抓真错，不管排版

**没装 prettier。** 量过：现有代码 96.3% 的行 ≤80 字符、零 tab、
654 个单引号字符串 / 0 个双引号 —— 格式本来就一致。
让 linter 全量重排只会制造一次几千行的无意义 diff，把 `git blame` 洗掉。

同理 vue 用 `flat/essential` 不用 `flat/recommended`：后者一半是排版规则
（每行几个属性、单行标签要不要换行），开了当场 **690 条 warning，一条真错都抓不到**。

现在：**前端 0 problem，后端 0 error / 13 warning**。

## 二、会绊倒你的三件事

### 1. 🔴 `backend/admin/*.js` 的 eslint 配置得分两块写

那四个文件是传统 `<script>`，由 `index.html` 依次引入，**共享同一个全局作用域**
（`app.js` 定义 `render`，`tasks.js` 调它），没有 import/export。

不声明跨文件符号的话报 **110 条 `no-undef`**，全是假错。
但**在定义它的那个文件里声明成 global，报的是 `no-redeclare`**。
所以只能分两块：`app.js` 一块（声明它从别处用的 `modelsView` / `tasksView` /
`findRosterRow`），`models/roster/tasks.js` 一块（声明 app.js 那一套）。

**新加一个跨文件的函数，要把名字加进配置里。**

### 2. 全角空格是正文的一部分

`no-irregular-whitespace` 默认只放过普通字符串。而 U+3000 在这个项目里出现在
注释排版、`normHeader` 的正则 `[\s　]`、提示词模板里 —— 三处都得显式放行，
否则报的是一堆假错。配置里 `skipComments / skipTemplates / skipRegExps` 全开。

### 3. 剩下的 13 条 warning 是**原有的**死代码，我没删

按项目规矩（「找到无关的死代码，报告，不要删」）只报告：

| 文件 | 东西 |
|---|---|
| `admin/app.js` | `PURPOSE_CN`、`convStatusPill`、`RATING_CN`、`ratingPill`、`downloadTemplate`、`SUGGEST_CN` |
| `routes/account.js` | import 了 `AppError`、`ErrorCode` 没用 |
| `routes/images.js` | import 了 `config` 没用 |
| `routes/revise.js` | import 了 `query` 没用 |
| `routes/conversations.js` | `updated` 赋了值没用 |
| `scripts/import-test.mjs` | `createdIds` |
| `scripts/versions-test.mjs` | import 了 `queryOne` 没用 |

要清的话是七个文件各删一两行，零风险，但那是另一件事。

## 三、为什么不换 Django（同事的建议）

同事的论点是「我们会调 LLM，Python 最友好」。**这句话对的是另一类项目。**

Python 真正的优势在训练/微调、embedding + 向量检索、numpy/pandas、
LangChain 生态、本地跑模型。而这个项目：

- **明确不做 RAG**，是规避版权的核心决策（ADR-001）。原书 PDF 永远不入库
- grep 过整个 `backend/src`：**零 embedding、零向量运算、零 tokenizer**。
  唯一命中 `vector` 的两处是配图提示词里的 `Flat vector illustration` —— 那是**画风**
- 对 LLM 只做三件事：发 HTTP POST、解 SSE 流、解 JSON。全是语言中立的。
  用的是 OpenAI **官方维护的** `openai` npm 包，四种文本格式全是 OpenAI 兼容协议

重写的代价：`backend/src` 12,836 行 + `backend/admin` 2,851 行 + 13 个回归脚本 +
**126 条回归断言**（ageband 34 / commentary 30 / stream 33 / context 29）。
那些断言不是覆盖率，是**踩过的坑的化石** —— 「关掉开关必须显式发出去」
（77 秒 → 16 秒）、「键名没收全一个字都不发」（破了它 HTTP 200、日志干净、
教案照样生成成功）、「先看模型 id 再看地址」。重写会把它们静默丢掉。

**同事对的那部分**：Django 的结构确实比 Express 更「普遍认可」，
而且 Django Admin 会直接替掉 `backend/admin/app.js` 那 1968 行模板字符串拼 HTML ——
那是全项目最脏的地方。但打个折：这个后台不是 CRUD-over-models，
发额度、建两种码、模型管理的格式推断、名单 xlsx 导入都是业务逻辑，照样要自己写。

**没动那 1968 行**，理由是它功能已完成、在用，而上线闸门一个都没过。
