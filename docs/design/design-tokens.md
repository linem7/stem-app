## 2. 色彩使用规则

### 规则 1 · 亮色只做底，深色只做字
`--amber` / `--mint` / `--sky` / `--coral` 四个亮色**明度都在 0.72–0.85**，它们：
- ✅ 可以做**大面积底**，配 `--ink` 文字（对比度约 7–9:1）
- ❌ **不可以做文字色**（在奶油底上只有 1.5–3:1）
- 需要彩色文字时，一律用对应的 `-deep` 档

### 规则 2 · 白字必须配 deep 档
按钮若用白字，底色必须用 `--mint-deep` / `--sky-deep` / `--coral-deep` / `--amber-deep`。
`--amber` 和 `--mint` 本体配白字都不达标（分别约 1.9:1 和 2.4:1）。

**推荐做法**：主按钮用 `--amber` 底 + `--ink` 字（约 7.4:1），比白字方案更亮也更清楚。

⚠️ **「用 deep 档」本身不等于达标**（2026-08-20 量出来的）。旧 `--mint-deep` `#3E8F5D`
配白字只有 **3.97:1**，当绿色文字压在 `--mint-soft` 上只有 **3.57:1** —— 这条规则写在文档里
一年，而它保证的那件事从来没成立过。已把 `--mint-deep` 压暗到 `#327648`（白字 5.5:1、
浅绿底上 4.95:1），`--mint-shadow` 跟着压到 `#27593A`。

**教训**：色彩规则不能只写成文字。`npm run test:contrast` 现在逐对算 WCAG 比值，
改任何一个令牌值它会立刻红 —— 这是这条规则第一次真的被执行。

### 规则 3 · 颜色不做状态的唯一载体
「草稿 / 已完成」这类状态，颜色之外**必须同时有文字或图形**。理由：
- 黄色在奶油底上先天到不了 3:1
- 对色觉障碍用户友好

**这条也量过了**：选中态的胶囊（教案库筛选、建议分类、评价三选一、配图用途）
底色从 `--paper-2` 换成 `--amber`，两者的亮度差只有 **1.51:1** —— 远低于 3:1。
也就是说「哪个被选中了」靠的几乎全是**色相**，而色相正是色觉障碍者拿不到的那一维。
原来只有一个字重 600 兜着，太薄。**现在选中的胶囊一律多一个打勾图形**，
跟 `s-option` 用同一个 `iconCheck`。

⚠️ 反过来说，**装饰性发丝线故意不满足 3:1**：`--rule-2` 压在主底上只有 1.39:1。
那 3:1 的门槛管的是「不看它就读不懂内容」的构件，而卡片是靠白底压在奶油底上区分的，
描边只是收个边。真把每条描边提到 3:1，这套设计会变成一张硬灰格子 ——
方向 B 是用户定死的核心资产。所以 `test:contrast` 第 3 节**只查真正承载信息的图形**
（目前只有进度条的已完成段 vs 未完成段，3.8:1）。

### 规则 4 · 功能与色相的固定绑定
| 语义 | 色 |
|---|---|
| 主行动（开始 / 下一题 / 继续） | 暖阳黄 `--amber` |
| 次级行动、已完成、成功 | 薄荷绿 `--mint` / `--mint-deep` |
| 草稿、进行中 | 暖阳黄 `--amber` + 文字标注 |
| 中性提示、信息 | 天空蓝 `--sky-soft` |
| 个人 / 少量强调 | 珊瑚粉 `--coral` |
| 危险 / 删除 | `--coral-deep` |

一个语义只绑一个色，不许混用。

## 4. 字体

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
             "Microsoft YaHei", "Source Han Sans SC", sans-serif;
font-synthesis: none;
```

不使用宋体（Windows 小字发虚，且与明亮气质不符）。层级靠字重（400/500/600/700）与字号建立，大标题加 `-0.012em` 字距收紧。

### 八级梯子

| 令牌 | rpx | px | 字重 | 用途 |
|---|---|---|---|---|
| `--fs-hero` | `46` | 23px | 700 | 首页那句「今天想做个什么活动？」 |
| `--fs-title` | `44` | 22px | 700 | 页面大标题（教案库 / 我的 / 成稿标题 / 协议） |
| `--fs-question` | `40` | 20px | 600 | 焦点问题标题（「哪里不对？说给我听」） |
| `--fs-card` | `34` | 17px | 600 | 卡片标题、抽屉标题、兑换码输入框 |
| `--fs-body` | `30` | 15px | 400 | 正文、输入框、选项、按钮 |
| `--fs-read` | `28` | 14px | 400 | 长段落阅读（教案流程、协议条目、STEAM 标注） |
| `--fs-sub` | `26` | 13px | 400 | 次级说明、小按钮 |
| `--fs-tag` | `24` | 12px | 500 | 标签、徽标 —— **辅助文字下限** |

**下限**：正文 ≥14px，辅助文字 ≥12px，任何文字对比度 ≥4.5:1。

⚠️ **只有这八级，页面里不许出现别的字号**（2026-08-20 收口）。在这之前有 90 多处硬编码
`font-size`：25 / 26 / 27rpx 这种一像素的区分纯粹是噪音，而其中**十几处是 22rpx = 11px，
低于这份文档自己定的 12px 下限** —— 规则写在这儿，代码里从来没被执行过。
`npm run test:tokens` 第 4 条现在扫这个，写 `font-size: 27rpx` 会红。

### 字号档（老师可调）

老师在「我的」底部选三档，正文 15 / 17 / 20px：

| 档 | 倍率 | 正文 | 标签 |
|---|---|---|---|
| 标准 | 1 | 15px | 12px |
| 大 | 1.15 | 17px | 14px |
| 特大 | 1.32 | 20px | 16px |

倍率乘完**落到最近的偶数 rpx**（rpx 转 px 是除以 2，奇数落在半像素上，
各端凑整方式不同，同一段文字在开发者工具和真机上差半个像素，看着像发虚）。

「特大」为什么到 20px 就停：再大一档，教案成稿页的流程段落会长到滚不完，
她要找「第三环节」得翻四屏 —— 那时候字大反而更难用。

**存在本机，不进后端**（`stores/prefs.js`）。代价：换微信或换手机会回到标准档，要再点一次。

### 实现上唯一要小心的地方

字号的唯一源是 `frontend/src/utils/typography.js`，**不在 SCSS 里**。
页面里一律写 `font-size: var(--fs-body)`，由 `s-page` 把八个变量**内联**到根节点上。

为什么必须内联、不能用一个 `.fs-lg` 类：微信自定义组件默认 `styleIsolation: 'isolated'`，
`app.wxss` 里的**类选择器进不了组件内部**（只有标签选择器能穿透，所以 `page {}` 那层可以），
而 `s-page` 的根节点正在组件内部。走类那条路会**静默失效** ——
编译不报错，H5 预览还是对的（H5 没有样式隔离），只有微信里「调到特大什么都没变」。

## 5. 插画规范

用户参考图中首页顶部有一幅扁平风景插画（太阳 / 云 / 小山 / 树 / 房子），采纳。

**做法约束**：
- 纯 inline SVG 手搓，只用**几何形**（圆、弧、三角、圆角矩形）
- 用本色板的黄 / 绿 / 蓝 / 珊瑚，不引入新色
- ❌ 不画人物面孔、不画写实细节、不用 AI 生图
- 出现位置克制：目前只用于首页顶部和空状态

理由：扁平几何风景是可以手工精确绘制的；一旦涉及人物或写实场景，手搓 SVG 必然劣化，那时应该留诚实占位或改用真实素材。

## 6. 落地到小程序

这套令牌应写成一份 `styles/tokens.wxss`（或 uni-app 的 `uni.scss`），全局引入。
组件里**禁止出现裸 hex 值**，一律引用变量——改配色时只改一处。
