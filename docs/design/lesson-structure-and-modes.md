## 一、为什么要改教案结构

现在的结构是照《台湾 STEAM 教材》提炼的，而那本书是**活动实录** ——
它记录的是「活动做完之后回头看，当时是怎么发生的」。所以现在的产出里有两样东西
天然是回顾视角的：

- `features.problem_source`（这个问题为什么源自真实情境）—— 实录里是事后追认
- `reflection`（教学省思：预期与实际的差异）—— **活动还没做，哪来的实际**

而这个小程序要解决的事是**活动开始之前**：老师明天要上，今天要写教案、要备材料。
所以正文必须换成大陆老师真正在写、园里真正在收的那种格式。

**不动的部分**：8 个质量维度、年龄班适配规则、探究循环的要求 ——
那些是教学内容层面的东西，是这个产品的差异化，跟用什么格式呈现无关。
**只换呈现格式，不换教学主张。**

## 二、提案的新结构

分三层。第一层是老师会打印出来交给园里的**教案正文**，
第二层是帮她理解这个活动特征的**标注**，第三层是**教学实例**。

### 第 1 层 · 教案正文（大陆常见格式）

| 板块 | JSON 字段 | 从哪来 | 说明 |
|---|---|---|---|
| 活动名称 | `title` | 不变 | |
| 适用年龄班 · 时长 | `age_group` / `duration_min` | 不变 | |
| **设计意图** | `intent` | 原 `features.problem_source` **改成前瞻语气** | 为什么设计这个活动、想解决孩子什么问题。大陆教案里很标准的一节，正好是 problem_source 的归宿 |
| **活动目标** | `objectives[{dimension, text}]` | 原 `features.learning_experiences` 收敛 | **固定 3 条**，`dimension` 只能是 `认知` / `能力` / `情感`。写成结构化而不是三条字符串，是为了后端能硬校验「三个维度各一条」—— 模型天然会写出三条其实都是认知的目标 |
| **活动重点 · 难点** | `key_points{focus, difficulty}` | **新增** | 大陆格式的标准板块，而且是**前瞻的** —— 她照这个判断上课时盯哪儿 |
| **活动准备** | `preparation{experience[], material[]}` | 原 `materials` 拆开 | 经验准备（孩子之前得有什么经验）/ 物质准备（= 原 `materials`）。**场地布置并进物质准备**，不单开一节 |
| **活动过程** | `flow[{stage, minutes, detail}]` | 不变，**环节名换大陆叫法** | 3 环节：导入 → 展开 → 结束；4 环节：导入 → 展开 → 再探索与改进 → 交流总结 |
| **活动延伸** | `extension` | 不变 | |
| **安全提示** | `safety[]` | 不变 | |

### 第 2 层 · 特征标注（保留，你的要求 b）

| 板块 | 字段 | 说明 |
|---|---|---|
| STEAM 五域标注 | `steam{S,T,E,A,M}` | 完全不变，含「刻意不做」那套虚线框呈现 |
| 《指南》领域指标 | `indicators[]` | 原 `indicators`。它跟活动目标**不是一回事**：目标是这次活动想达到什么，指标是这个活动碰到了《3-6岁儿童学习与发展指南》的哪些发展条目。研究要用它，保留 |

### 第 3 层 · 教学实例（保留，你的要求 c）

`dialogue[{speaker, text}]` 不变，位置仍在最后。

### 明确去掉的

| 去掉 | 为什么 |
|---|---|
| `features` 这个容器 | 两个子字段各自找到了更合适的家（`intent` / `objectives`） |
| `reflection`（教学省思） | 活动还没做，写不出「预期与实际的差异」。**直接删，不做替代** —— 一开始想改成「观察与指导要点」，用户判断那样只是给回顾视角换个名字，教案已经够长 |
| 4 环节里那个「延伸活动」环节 | **现在是重复的**：flow 最后一环叫「延伸活动」，同时还有一个 `extension` 字段。新结构里延伸只出现一次，作为独立板块 |

### 最终的 `content_json` 形状

```json
{
  "title": "…", "age_group": "中班", "duration_min": 30,
  "intent": "设计意图，两三句",
  "objectives": [
    { "dimension": "认知", "text": "…" },
    { "dimension": "能力", "text": "…" },
    { "dimension": "情感", "text": "…" }
  ],
  "key_points": { "focus": "活动重点", "difficulty": "活动难点" },
  "preparation": {
    "experience": ["孩子之前得有的经验"],
    "material": ["材料，写清数量或规格"]
  },
  "flow": [{ "stage": "导入", "minutes": 5, "detail": "…" }],
  "extension": "活动延伸，一段话",
  "safety": ["安全提示"],
  "steam": { "S": "…", "T": "…", "E": "…", "A": "…", "M": "…" },
  "indicators": ["《指南》领域指标"],
  "dialogue": [{ "speaker": "T", "text": "…" }],
  "commentary": { "…": "学习模式才有，第三阶段做" }
}
```

⚠️ **配图挂点会变。** 现在图片的 `section_key` 写的是 `material.N`（下标指向 `materials`），
新结构里那个数组搬到了 `preparation.material`。**旧图的 section_key 不要动**
（图片永不跟着版本走，这是定死的规则），新的写 `preparation.material.N`。
成稿页判断「这样材料画过没有」是按 `label` 比名字、不是按下标，所以那一段逻辑不受影响。

## 四、学习模式

### 命名

- **效率模式** —— 现在这套。说一句话 → 答 4 题 → 拿教案
- **学习模式** —— 同样拿得到教案，但沿途解释「为什么」

**关键约束：学习模式不能让她更晚拿到教案。** 它加的是解释，不是关卡。

### (a) 入口

首页输入框上方一个小胶囊，显示当前模式，点开是一个底部抽屉，两行可选。

```
┌────────────────────────────────┐
│  效率模式 ⌄                     │   ← 输入框上方的小胶囊
├────────────────────────────────┤
│  今天想做个什么活动？            │
│  ┌──────────────────────────┐  │
│  │ 例：我想做个浮与沉的活动   │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘

点胶囊 → 抽屉：
  ○ 效率模式    直接拿到教案
  ● 学习模式    多告诉你为什么这样设计
```

⚠️ **这是「界面上不写解释性小字」那条规则的一个例外**，理由要说清楚：
「学习模式」四个字不自明，不给一句话她只能盲选 —— 这正好过得了那条规则的判据
（她不看这句话会做错什么吗？会，她会随便选一个）。
但**只在抽屉里给这一句**，首页那个胶囊上不许再挂副标题。

**记住上次的选择**（存本机 `stores/prefs.js`，跟字号档一样），
下次开新教案默认还是那个模式。不然每次都要重选一遍。

**存哪**：`conversations` 加一列 `mode VARCHAR(16) NOT NULL DEFAULT 'efficient'`（017 迁移）。
挂在会话上而不是老师身上 —— 她可能这份想快、下一份想学。

### (b) 问题引导：为什么问这个

学习模式下，4 道题各多一句「为什么问这个」。

**这四句是写死的中文，不调模型。** 理由：
- 那 4 道题是固定的（`QUESTION_PLAN`），它们的教学道理**不随主题变化** ——
  「年龄班决定一切深浅」这句话对浮沉和对搭高塔是同一句
- 写死 = 免费、零延迟、质量稳定。调模型每次说的是同一个意思，但会措辞飘、会花钱、会变慢
- **而且这是真正要她带走的东西**：她下次自己写教案时要想的就是这四件事

初稿（你改）：

| 题 | 为什么问这个 |
|---|---|
| 年龄班 | 同一个浮沉活动，小班是「玩，玩出感觉」，大班才是「找原因」。**写教案第一件事永远是先定年龄班** —— 定错了，后面全错 |
| 教学重点 | 一次活动只能有一个重点。想让孩子玩痛快，和想让他弄懂材料的道理，材料和提问是两套 |
| 场地 | 场地不是背景，它决定活动形态。户外空地能搭大的、能跑；教室区角只能做桌面的、要控制人数 |
| 班上的情况 | 人数、材料、有几个老师 —— 这三件事决定分组方式，而分组方式决定这个活动做不做得下来 |

### (c) 教案解读

生成完，每个板块下面可以挂一段「为什么这样设计」。

**技术方案：第二次模型调用，不塞进同一次生成。** 理由：

- 生成教案那次已经是最贵最慢的一次（`maxTokens: 4000`、超时放宽到 3 分钟）。
  再往里塞 1500 字解读，会挤占教案本身的质量
- 分开之后**解读失败不影响出稿** —— 跟现在的 `selfCheck` 同一个模式（try/catch，失败只记日志）
- 解读那次能**看到已经写完的教案**，所以它解释的是真正生成出来的东西，
  而不是在生成的同时预测自己会写什么

**存哪**：`content_json.commentary`，按板块名归位：

```json
"commentary": {
  "objectives": "为什么定这三条目标、为什么不定第四条",
  "preparation": "为什么是这些材料、为什么不用那些",
  "flow": "为什么是这个顺序、为什么不先讲规则",
  "flow_stages": ["第 1 环节为什么这么长", "…"],
  "steam": "为什么 E 这次刻意不做",
  "safety": "为什么这几条是这个年龄班的必查项"
}
```

放在 `content_json` 里而不是单开一张表：它是**跟着版本走的**（改稿之后解读也该跟着变），
而版本历史本来就整份存 `content_json` —— 白送。

⚠️ **`renderMarkdown` 默认不输出 commentary。** 她导出 docx 是为了打印交给园里，
把「为什么这样设计」印在教案上，园长看到的是一份夹着旁白的教案。
要导出解读，得是一个单独的选项。

### (d) 呈现方式（有一个待你定的取舍）

你说的是「穿插在各部分下方」。我照这个做，但有一个代价要说清：

成稿页现在已经很长（STEAM 五域 + 材料 + 流程 + 指标 + 安全 + 对话 + 延伸 + 配图 + 评价）。
每个板块下面再加一段解读，**页面会长一倍**，而她第二次打开这份教案时想找的是
「第三环节我要干什么」—— 得从解读里翻过去。

三个选项：

| 方案 | 好处 | 代价 |
|---|---|---|
| **常驻穿插** | 她一定看得到 | 页面长一倍，用第二次就开始嫌它挡路 |
| **默认折叠**（一行「为什么这样设计 ›」，点开展开） | 页面不变长，想看随时看 | 她可能一次都不点 |
| **按需生成**（点了才调模型要这一段） | 最省钱，而且是她真的好奇的时候才看 —— 那时候学得最牢 | 每次点要等几秒 |

**我建议「默认折叠」+ 生成时一次性产出**：省钱和即时性都拿到，页面也不变长。
但「她可能一次都不点」是真风险 —— 你更了解老师会不会点。

## 五、我另外想到的几种模式（你问的那个问题）

按「不影响她快速拿到教案」这个前提排的。

### 1. 对照模式 —— 我认为价值最高的一个

她先自己写（哪怕只写活动目标和三个环节的名字，三行字），提交后 AI 生成自己的版本，
**并排指出差异 + 说明为什么**：

> 你写了 4 个环节，我写了 3 个 —— 小班上限就是 3 个，孩子的专注时间撑不到第 4 个。
> 你的目标第 2 条「学会记录实验结果」，小班做不到写和画，我改成了「用贴纸标出哪个浮起来」。

**为什么它最有效**：先自己产出、再看到反馈，比直接读一份好教案的学习效果高一个量级
（这是提取练习 + 即时反馈）。而且**完全不影响不想学的人** —— 不选这个模式就走不到这一步。

代价：多一次模型调用；要多一屏（让她写那三行）。

### 2. 留白模式 —— 便宜且黏

正常生成教案，但**故意留一个板块空着**，写「这一节你来写，写完我给你反馈」。
她填完，AI 只点评那一节。

- 第一次留「安全提示」（最容易、错了也看得出来）
- 用熟了留「活动目标」（最难、最能拉开水平）

她还是一分钟就拿到了 90% 的教案，只多做一件小事。成本是一次很小的点评调用。

### 3. 概念卡 —— 几乎零成本

教案里用到某个教学概念（探究循环、非标准单位测量、支架、平行游戏）时，
挂一张两句话的小卡片解释它。**这些卡片是写死的静态内容**，
不调模型、可以慢慢积累，而且跨教案复用 —— 写一次用一百次。

### 4. 活动后复盘 —— 唯一能验证教案好不好的东西

活动做完之后回来答 3 个问题（哪个环节超时了？孩子卡在哪？材料够不够？），
AI 帮她把 `observation` 补成一份真正的活动反思。

**这是我们从那本书里删掉的东西，用对的方式加回来** —— 原来的问题不是「反思没价值」，
是「活动前写反思没价值」。

顺带：这是**唯一能回答「AI 写的教案到底能不能用」这个问题的数据源**
（现在那个指标只有她点一次「直接能用/改改能用/用不了」）。

### 5. 不建议做的

- **同伴对照**（看别的老师怎么设计同一个活动）—— 要语料库，而且一碰就是「老师的教案给别人看」，
  跟协议里那句「你的幼儿园和园长看不到这里的任何东西」直接冲突
- **打分/排名** —— 会让她不敢写

两件事**不要一起做**。教案结构改版会动 `content_json`，而学习模式的解读要挂在
`content_json` 上 —— 结构没定就做解读，等于在流沙上盖房子。

| 阶段 | 内容 | 大概规模 |
|---|---|---|
| ~~**1**~~ | ~~教案结构改版~~ | ✅ 2026-08-20 完成 |
| ~~**2**~~ | ~~学习模式的入口和问题引导~~ | ✅ 2026-08-20 完成 |
| **3** | 教案解读 —— (c)(d)，默认折叠 | 中 |

### 第 2 阶段落地时定下来的

- `conversations.mode`（017 迁移），`efficient` / `learning`，默认 `efficient`
- 那四句「为什么」写在 `backend/src/services/learningMode.js`，**写死的中文**。
  改文案改那一个文件，不用动接口
- **效率模式下 `why` 根本不下发**（不是下发了不显示）
