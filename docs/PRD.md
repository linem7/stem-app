# 产品需求文档 (PRD)

STEM 教案生成平台 - 微信小程序版

---

## 1. 产品概览

### 1.1 产品定义
一款帮助幼儿园老师快速生成高质量 STEM 教案的微信小程序。通过多轮 AI 引导对话和知识库支撑，让教师从简单想法（如"浮与沉"）出发，逐步完善活动设计，最终产出结构化的教案文档和可视化辅图。

### 1.2 核心价值主张
- **老师的痛点**：教案撰写费时（2–3 小时/份），格式规范要求高，新手易疏漏教学目标或安全事项
- **我们的解决方案**：AI 引导 + 质量标准 + 模板，让教案生成时间压缩至 20–30 分钟；提高科学性和安全性
- **商业价值**：为老师、园所提高教学效率；未来可拓展到用户统计、教学质量分析

### 1.3 目标用户
- 幼儿园（中班、大班为主）一线老师，年龄 22–45 岁
- 可能是教学新手（急需指导）或经验老师（想提升教学质量）
- 基本智能手机使用能力，医护、美妆 APP 用户人群相同

### 1.4 成功指标（非功能性需求）
- **易用性**：新手老师首次生成教案不超过 15 分钟（含图片选项）
- **质量**：生成的教案需评审通过率 > 90%（内测 5 位老师评分）
- **采纳率**：内测用户中，至少 3 位愿意在班级实际使用生成的教案
- **系统稳定性**：可用率 > 99.5%；对话超时时间 > 60s

## 2. 核心功能模块

### 2.1 用户系统

#### 2.1.1 注册与认证
- **流程**：微信授权一键登录（获取昵称、头像、openid）
- **档案录入**：首次登录引导填写（任教年龄班、教龄、园所名称、教学偏好）
- **个人设置**：修改档案、删除历史、隐私设置

#### 2.1.2 档案存储
```json
{
  "teacher_id": "xxx",
  "wechat_openid": "xxx",
  "nickname": "李老师",
  "avatar": "url",
  "age_group": "中班",  // 小班/中班/大班
  "teaching_years": 5,
  "kindergarten_name": "阳光幼儿园",
  "preferences": {
    "default_age_group": "中班",
    "template_format": "表格式",  // 表格式/段落式
    "auto_save": true
  },
  "created_at": "2026-08-20T00:00:00Z",
  "last_login": "2026-08-23T14:30:00Z"
}
```

### 2.2 教案生成核心流程（主交互）

#### 2.2.1 流程概览
```
[初始想法输入] → [轮次 1：基础信息] → [轮次 2：活动设计] → [轮次 3：优化细化] → [成稿输出] → [可选：生成图片]
```

#### 2.2.2 第 0 步：初始想法
- **用户输入**：一句话描述活动主题（如"跷跷板的力学原理"）
- **系统反应**：立即显示推荐年龄班、教学目标初稿（不用等）
- **UI**：单输入框 + 推荐标签卡片（可点选/修改）

#### 2.2.3 第 1 轮：基础信息（提问 3–4 个）

系统生成如下问题，采用 **grill-me 风格**（编号 + 推荐答案卡片）：

```
❓ Q1 - 目标年龄班：
推荐：[中班] [大班] [小班]
用户可点选或自填

❓ Q2 - 教学重点是什么：
推荐：[理解杠杆原理] [体验力的平衡] [安全使用工具]
用户可点选或自填

❓ Q3 - 这次活动有多长时间：
推荐：[20 分钟] [30 分钟] [45 分钟]
用户可点选或自填

❓ Q4 - 你有什么场地/器材限制吗：
推荐：[室内教室，无特殊器材] [室外，有沙坑] [另外告诉我...]
用户可点选或自填
```

- **系统反应**：用户每答一题，AI 实时反馈（如 "好的，45 分钟足够做完整探究，推荐分三个阶段"）
- **数据保存**：每个回答实时存入 `conversations` 表

#### 2.2.4 第 2 轮：活动设计（提问 3–5 个，取决于第 1 轮答案）

依赖第 1 轮答案生成定制化问题：

```
❓ Q5 - 你的材料清单是什么（孩子用的）：
推荐：[小木板、支点、重物] [跷跷板套件] [生活废旧物品（纸板、瓶子等）]
用户可点选或自填

❓ Q6 - 活动流程设计（从开放探究到结构化引导）：
推荐流程卡片：
  [引入阶段：故事/演示] 
  → [自由探索：孩子试] 
  → [引导提问：重点发现] 
  → [总结规律：归纳原理]
用户可点选或自定义顺序

❓ Q7 - 关键提问有哪些（用来引导孩子思考）：
推荐：[为什么跷跷板能上下动？] [如何让两边平衡？] [改变什么位置能改变力的大小？]
用户可点选或自填

❓ Q8 - 安全事项（必答）：
推荐：[监管高度、防摔垫、器材检查] [不能推他人、规则约束]
用户可点选或自填
```

- **系统反应**：根据用户答案生成初版教案目录（自动更新，用户看得见）
- **用户可选**：点击"我觉得现在可以了，直接生成教案"跳过第 3 轮

#### 2.2.5 第 3 轮：优化细化（可选，2–3 题）

```
❓ Q9 - 评估方式（如何看孩子是否达成目标）：
推荐：[观察表现描述] [简单检查清单] [视频记录]

❓ Q10 - 有没有后续延伸活动：
推荐：[斜面的力学] [天平的设计] [搭建更复杂的结构]

❓ Q11 - 还有别的调整吗：
推荐：[无] [我有特殊要求，见下...]
```

#### 2.2.6 成稿生成

- **触发**：用户确认"生成教案"，后端调用 DeepSeek（带整个对话历史 + 系统提示词）
- **输出格式**：Markdown（移动端友好）或富文本（美化排版）
  ```
  # 教案：[跷跷板的力学探究]
  
  **年龄班**：中班
  **活动时长**：30 分钟
  **科学目标**：理解杠杆原理和力的平衡
  **所需材料**：...
  
  ## 活动流程
  
  ### 第一阶段：引入（5 分钟）
  ...
  
  ### 第二阶段：自由探索（10 分钟）
  ...
  
  ## 关键提问清单
  ...
  
  ## 安全事项
  ...
  
  ## 评估方式
  ...
  ```
- **显示位置**：全屏阅读，顶部显示"生成配图""下载 Word""分享"等操作按钮
- **自动保存**：教案自动存入 `lesson_plans` 表，时间戳记录

#### 2.2.7 可选：生成配图

- **触发**：用户点击"为这份教案生成配图"（不强制、不默认）
- **流程**：
  1. 用户选择要配图的章节（如"活动流程第一阶段的场景"）
  2. 系统使用 DeepSeek 生成图片描述提示词（中文 → 英文）
  3. 调用豆包 API 生成图片（异步，1–2 秒）
  4. 图片插入对应位置，显示生成时间和重新生成按钮
  5. 用户可下载图片到相册或保存到教案里

- **成本管理**：
  - 每份教案最多 2–3 张图
  - 显示"生成需要 3 秒，费用约 ¥0.02"提示
  - 如果手机流量限制，显示 WiFi 提示

### 2.3 用户记忆系统

#### 2.3.1 记忆类型
```
memory_type：
  - "教学习惯"：如"我偏好表格式教案，而不是段落"
  - "约束条件"：如"我园没有投影仪""室内场地有限"
  - "教学风格"：如"我喜欢探究式，避免灌输"
  - "年龄班专长"：如"我主要教中班，大班经验少"
  - "材料偏好"：如"我倾向用生活废旧物品，减少购买成本"
```

#### 2.3.2 记忆写入
- **时机**：教案生成完成后（不阻塞用户，异步进行）
- **机制**：后端额外调用 DeepSeek，提示词要求输出 JSON
  ```
  系统提示词模板：
  "从这次对话中，提取用户值得长期记忆的 3–5 条事实。
   输出 JSON 数组，每条包含 { fact, type, confidence }。
   只记忆明确说过、可验证的，避免推测。"
  ```
- **去重**：新记忆与已有记忆对比，如相同则增加 `frequency` 计数，不重复存储
- **存储**：写入 `user_memories` 表
  ```
  {
    "memory_id": "uuid",
    "teacher_id": "xxx",
    "fact": "我的班级是中班，孩子 4–5 岁",
    "type": "教学信息",
    "confidence": 0.99,
    "frequency": 3,  // 多少次对话中提到过
    "created_at": "2026-08-20T00:00:00Z",
    "updated_at": "2026-08-23T14:30:00Z"
  }
  ```

#### 2.3.3 记忆读取与使用
- **时机**：每次新对话开始
- **注入位置**：系统提示词的 `[用户档案]` 段
  ```
  你是一位有经验的幼儿园教学设计师。
  
  [用户档案]
  - 用户是来自杭州阳光幼儿园的老师
  - 教龄 5 年，主要教中班孩子（4–5 岁）
  - 偏好表格式教案，而不是段落
  - 园里没有投影仪，场地有限
  - 喜欢探究式教学，避免灌输
  - 倾向于使用生活废旧物品
  
  根据这些信息，个性化地设计引导问题和最终的教案。
  ```
- **隐私**：用户可在设置页随时查看、编辑、删除记忆

#### 2.3.4 记忆的自适应
- **早期**（第 1–2 个教案）：推荐答案泛化，没有个性化
- **积累**（第 3–5 个）：推荐答案开始反映用户历史（如已知教中班，推荐问题和例子都贴近中班）
- **成熟**（第 6+ 个）：智能跳过重复问题（如已多次说"没有投影仪"，不再每次都问），加速生成

### 2.4 历史与管理

> 2026-08-16 用户确认：**取消独立的"历史"页**。过往教案无论完成与否一律进教案库，首页不再承载任何历史入口。

#### 2.4.1 教案库（唯一的历史入口）
- **草稿条目**：显示教案标题、年龄班、进度（如"进行到第 1 轮第 2 题"）、时间；点击「接着写」恢复对话
- **已完成条目**：显示教案标题、年龄班、日期、是否有配图；点击打开成稿
- **筛选**：状态（全部 / 草稿 / 已完成）+ 年龄班（小班 / 中班 / 大班）
- **操作**：打开、编辑、导出 Word、分享、删除
- **分享**：生成只读链接，同事可预览但不能修改

#### 2.4.2 状态流转
```
首页输入想法 → 自动创建草稿 → 引导对话（随时可退出，进度保留在教案库）
            → 生成成稿 → 状态转为「已完成」→（可选）生成配图
```
未完成的对话**不需要用户手动保存**，每答一题即写库，避免中途被打断丢失进度。

## 3. 用户界面与交互设计

### 3.1 页面结构

```
微信小程序（标签栏导航）：

[首页]  [历史]  [我的]
  ↓
[首页]  ← 2026-08-16 用户确认：只是一个对话框
├─ 问候语
├─ 一句话输入框 + 开始按钮
├─ 一句轻提示（接下来会问两三个问题）
└─ （可选）主题灵感 chip，从属于输入框
    ※ 不放最近在写、不放已完成列表、不放进入教案库的入口

[教案库]  ← 承载全部历史，含未完成
├─ 草稿（可续写，带进度指示）
├─ 已完成（可打开/导出/分享）
└─ 筛选：状态（全部/草稿/已完成）+ 年龄班（小班/中班/大班）

[我的]
├─ 个人档案
├─ 我的记忆（可编辑、可删除）
├─ 帮助与反馈
└─ 关于
```

### 3.2 核心交互细节

#### 3.2.1 输入交互
- **手机友好**：优先卡片/按钮点选，输入框为辅（减少打字）
- **推荐答案**：每题至少 2 个推荐卡片，可右滑查看更多或自填
- **实时反馈**：用户点选后立即显示 AI 反应（"好的，我已记下..."），增强交互感

#### 3.2.2 加载与反馈
- **生成教案**：显示进度条或动画（"正在为你设计教案... 50%"）
- **生成图片**：显示"正在创作中..."，完成后自动刷新
- **错误处理**：网络错误时显示重试按钮；无 WiFi 提示节省流量

#### 3.2.3 排版与美学
- **字体**：移动端中等大小，段落间距 12px–16px
- **配色**：柔和色系（不刺眼），教案正文用护眼灰/蓝
- **深色模式**：支持系统深色模式

## 4. 技术架构（简略）

### 4.1 客户端
- 框架：uni-app
- 语言：Vue 3
- 状态管理：Pinia
- 网络：uni.request + 自定义拦截器（授权、错误处理）

### 4.2 后端
- 框架：Node.js + Express（或 Python + FastAPI）
- 数据库：PostgreSQL 或 MySQL
- 缓存：Redis（可选，第二版）
- API：RESTful 或 GraphQL
- 外部 API：DeepSeek、豆包、微信授权

### 4.3 存储
- 文件：阿里云 OSS 或腾讯云 COS（图片）
- 数据库：云 RDS（PostgreSQL/MySQL）

### 4.4 部署
- 服务器：腾讯云/阿里云轻量应用服务器（2核 4G）
- 域名：ICP 备案
- HTTPS：免费证书（Let's Encrypt）

## 6. 成功验收标准

### 6.1 功能完整性
- [ ] 老师能一键注册（微信授权）
- [ ] 老师能生成至少 1 份完整教案，用时 < 15 分钟
- [ ] 生成的教案格式符合幼儿园实际需求
- [ ] 用户记忆能准确提取和复用

### 6.2 质量标准
- [ ] 5 位内测老师中，至少 3 位给生成教案评分 ≥ 4/5
- [ ] 没有严重 bug（crash、数据丢失）
- [ ] 加载速度：首屏 < 2s，生成教案 < 30s

### 6.3 用户满意度
- [ ] 至少 2 位老师在实际班级用过生成的教案
- [ ] 老师反馈"节省时间"或"启发了我的设计思路"
- [ ] 愿意推荐给其他老师
