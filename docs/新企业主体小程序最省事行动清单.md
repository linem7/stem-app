# 新企业主体小程序最省事行动清单

> 适用情况：朋友的公司以前注册过其他小程序；这次是一个全新的小程序，不覆盖、不修改旧小程序。功能、Icon、用途和前端代码已经完成。目标是在尽量少打扰朋友的前提下完成注册、部署、体验和上线。  
> 更新日期：2026-08-26

## 一、采用的方案

本项目使用以下安排：

- 注册一个全新的企业主体小程序，获得新的 AppID；
- 朋友公司原有小程序保持不变，不会被覆盖；
- 由我新建一个“项目专用邮箱”，避免朋友寻找闲置邮箱；
- 新邮箱可以由我操作，但密码和找回方式同时交给朋友保存；
- 注册时优先把我填写为小程序管理员；平台若要求公司授权，由朋友一次性确认或盖章；
- 注册完成后，日常开发、CloudBase、上传、体验版和技术排错均由我完成；
- 朋友只在企业身份验证、小程序备案核验和最终上线确认这三个节点参与。

普通注册时，一个新小程序是一个独立公众平台账号，需要未注册过公众平台的新邮箱。公司以前提交过的工商资料可以继续使用，但新小程序会取得独立 AppID，并且需要单独办理小程序备案。

## 二、朋友最少只需要参与三次

| 次数 | 朋友做什么 | 预计形式 |
|---|---|---|
| 第一次：注册 | 确认允许公司作为主体；提供准确工商资料；完成法人/企业验证或盖章授权 | 一次视频/当面操作，或按官方页面扫码 |
| 第二次：备案 | 法人、主体负责人按平台要求完成人脸、电话或工信部短信核验 | 收到通知时操作，短信通常有时限 |
| 第三次：上线 | 确认公司同意隐私政策、AI 功能、类目和正式发布 | 一条书面确认；必要时管理员扫码 |

除此之外，不要求朋友提供微信密码、公众平台密码、腾讯云主账号密码或长期配合开发。
“三次”是按正常流程设计的最少协作次数；如果微信或公司注册地管局临时要求补材料、重新核验，仍需按官方通知增加一次配合，不能为了省事跳过真实性核验。

## 三、我现在先做，不需要联系朋友

### 1. 新建项目专用邮箱

不要使用已经绑定旧小程序的邮箱，也尽量不用自己的日常主邮箱。新建一个只用于本项目的邮箱，例如：

```text
stem.miniapp@outlook.com
```

要求：

- 从未注册或绑定过微信公众平台；
- 密码单独设置，不与其他账号相同；
- 开启二次验证；
- 保存恢复邮箱、手机号和恢复码；
- 把账号、密码和找回方式交一份给朋友，保证公司能够接管；
- 不在 Git、代码、项目文档或聊天截图中写密码。

### 2. 整理我已经准备好的产品材料

- 小程序名称候选 2—3 个；
- Icon 原图；
- 小程序简介；
- 功能说明；
- 页面截图；
- 服务类目候选；
- 隐私政策和用户协议草稿；
- 我的实名微信号、身份证、手机号和邮箱；
- CloudBase 环境 ID：`cloud1-d2gq6r8wb670ae313`。

服务类目先按“教师备课效率工具”判断，优先查看微信后台当前是否可选“工具 → 办公”。不要为了名称里有“幼儿园”就主动申报成培训或直接面向儿童的教育服务；最终以真实功能和平台审核意见为准。

### 3. 检查名称占用

如果我现有的个人主体小程序已经使用了准备给公司小程序的同名名称，新账号可能无法再次使用。先准备一个不冲突的名称，不要在公司新账号注册成功前注销旧个人小程序。

## 四、第一次找朋友：一次拿齐注册所需信息

请朋友提供或核对：

```text
公司营业执照完整名称：
统一社会信用代码：
注册地址：
实际通信地址：
法定代表人姓名：
公司公开联系邮箱：
公司公开联系电话/联系人：
公司是否有已认证公众号：有 / 没有 / 不清楚
```

需要营业执照原件图片、法人身份证或对公资料时，优先让朋友本人直接在微信官方页面上传/验证，不要求他把敏感文件长期发给我。

同时取得一条书面确认即可：

> 公司同意以本公司为主体注册并运营“幼儿园 STEAM 教案助手”小程序，同意由我负责注册填写、技术开发、云服务配置、版本上传和日常维护；涉及法人核验、备案及正式发布时由公司配合确认。

这不是微信规定的固定模板，但能把双方责任说清楚。平台要求正式授权书时，使用平台针对公司注册地提供的模板，不自行编造格式。

## 五、注册新的公司小程序

### 路径 A：公司有已认证公众号

请朋友查看已认证公众号后台是否有：

```text
小程序管理 → 快速注册并认证小程序
```

如果有，优先使用该入口复用公司主体和认证资质。朋友完成一次管理员扫码后，其余信息由我填写。

### 路径 B：只有旧小程序，没有已认证公众号

由我访问：

```text
https://mp.weixin.qq.com/
→ 立即注册
→ 小程序
```

操作：

1. 使用新建的项目专用邮箱注册；
2. 点击邮箱激活链接；
3. 主体类型选择“企业”；
4. 填写朋友公司的准确工商信息；
5. 管理员优先填写我本人的实名微信和手机号；
6. 如果平台允许外部受托人员任管理员，按提示继续；
7. 如果平台要求管理员必须经公司授权，让朋友完成扫码或提供盖章授权书；
8. 由朋友/法人完成企业身份验证；
9. 注册完成后保存新的 AppID。

若平台不接受我直接担任初始管理员，则改为朋友先做管理员；注册完成后让他在“用户身份/成员管理”添加我的微信并授予权限。只需要操作一次。

建议权限：

- 登录；
- 开发者；
- 体验者；
- 开发管理；
- 开发设置；
- 腾讯云/云开发管理。

旧小程序不会因为新注册而被删除、覆盖或更新；两个小程序拥有不同 AppID、版本和备案记录。

## 六、拿到新 AppID 后，全部由我完成

### 1. 先记录账号资产

```text
新小程序名称：
新 AppID：
注册邮箱：
管理员微信：
公司主体：
认证状态：
小程序备案状态：
```

AppSecret 生成后直接存进密码管理器和云端环境变量，不通过聊天发送。

### 2. 替换项目配置

- `frontend/src/manifest.json`：替换为新 AppID；
- 前端生产环境：关闭假登录；
- 后端 `WECHAT_APPID`：替换为新 AppID；
- 后端 `WECHAT_SECRET`：填新 AppSecret；
- 后端 `NODE_ENV=production`；
- 后端 `DEV_FAKE_LOGIN=false`；
- 后端 `CONTENT_CHECK_ENABLED=true`。

旧个人 AppID保留到新账号完成真机登录和体验版验证，不立即注销。

### 3. 核对 CloudBase 环境

登录 CloudBase 控制台，核对：

- 环境是否可以关联新公司 AppID；
- 环境当前关联的是否仍是个人 AppID；
- 云托管、PostgreSQL、云存储是否已经开通；
- 套餐、地域和到期日；
- 环境由谁的腾讯云账号持有。

如果这个环境已经永久关联个人小程序或不能转换，就创建一个与公司新 AppID对应的生产环境；原环境只做测试。正式教师数据不能放在归属不清楚、无法交接的环境中。

### 4. 优先采用少麻烦朋友的服务器路线

优先评估：

```text
微信小程序 → wx.cloud.callContainer → CloudBase 云托管
```

这条路线能减少让朋友配置公司域名和 DNS 的工作。但当前项目还需要我完成：

- 云托管 Dockerfile/部署配置；
- 把小程序请求适配到 `wx.cloud.callContainer`；
- 连接 PostgreSQL；
- 图片改存云存储/COS。

如果最终继续使用公网 `uni.request`，再请朋友为公司域名添加一次 `api.` 子域名解析；已有备案域名是否需要腾讯云接入备案，以域名当前接入商为准。

## 七、功能虽已完成，但这些上线收尾仍要做

当前仓库仍有以下上线阻塞项，不能因为界面和业务流程完成就跳过：

- 生产前端仍需从局域网地址换成正式云端访问方式；
- 前后端假登录必须关闭；
- 后端要填新 AppID/AppSecret；
- 微信内容安全要用新 AppID真机验证；
- `imageStore.js` 的云存储上传仍未实现；
- 当前隐私说明中“不把数据给任何第三方”与实际会调用微信、DeepSeek、图片模型和腾讯云不一致；
- AI 教案和图片需要生成标识及模型备案信息公示；
- 正式数据要有备份和账号注销/删除验证。

这些都由我处理，不需要朋友参与编码；朋友只需确认公司接受最终隐私政策和实际使用的第三方服务商。

## 八、上传体验版与异地审核

我完成：

1. 构建新 AppID 的生产包；
2. 用自己的微信登录开发者工具；
3. 上传开发版本；
4. 在版本管理中设为体验版；
5. 添加同事为体验成员；
6. 创建测试园、测试名单和兑换码；
7. 用异地网络完成微信登录、内容安全、生成、改稿、删除和注销测试。

如果我具有“开发管理”权限，这一阶段不需要朋友参与。

## 九、第二次找朋友：完成新小程序备案

新 AppID 必须单独备案；公司旧小程序的备案不能直接覆盖新小程序。

我先在微信公众平台填写：

- 公司主体信息；
- 新小程序名称、AppID、Icon、类目和服务说明；
- 腾讯云/CloudBase 网络资源信息；
- 小程序负责人信息；
- 所在省份要求的补充说明。

为了减少朋友参与，可在公司同意且平台/当地管局接受的情况下，把我填写为“小程序负责人”，并上传公司盖章授权书。若平台要求法定代表人或公司员工担任，则按平台要求调整。

朋友只需要：

- 确认工商信息；
- 在平台要求时完成法人/主体负责人核验；
- 接听备案核验电话；
- 收到工信部短信后在规定时间内完成核验；
- 必要时签字或盖章一次。

小程序备案通过后保存备案号。公司已有其他小程序备案并不能免除新 AppID 的备案。

## 十、第三次找朋友：正式发布前确认

给朋友看一页最终确认材料：

- 小程序名称、Icon、简介；
- 服务类目；
- 隐私政策；
- 收集的数据范围；
- 使用的微信、腾讯云、DeepSeek、MiniMax 等服务；
- AI 生成内容提示；
- 测试结果；
- 小程序备案号。

朋友回复“同意以上述内容正式发布”后，我提交审核并发布。若公司坚持由自己掌握最终发布按钮，则让管理员只在审核通过后扫码发布一次。

## 十一、全部流程的最短版本

```text
我新建专用邮箱
→ 一次找朋友拿工商信息并完成企业验证
→ 注册新的企业主体小程序
→ 获得新 AppID，我成为管理员/开发者
→ 我替换 AppID、部署 CloudBase、完成上线配置
→ 我上传体验版并让同事异地审核
→ 第二次找朋友完成备案核验
→ 第三次让朋友确认隐私和正式发布
```

## 十二、官方依据

- 微信官方开发文档说明 AppID 是每个小程序的唯一标识：[申请账号与 AppID](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/getstart)
- 微信开发者权限应在对应小程序的成员管理中授予：[成员管理说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/miniapp/handbook/web/workspace.html)
- 普通注册需要填写并激活新注册邮箱；已认证公众号可复用资质快速注册：[腾讯云小程序注册指引](https://cloud.tencent.com/document/product/1598/80508)
- 每一个新应用都需要独立备案，微信小程序在微信公众平台办理：[腾讯云最新备案说明](https://cloud.tencent.com/document/product/243/97691)
- 工信部备案表说明小程序无需填写普通 APP 的域名列表、公钥和 MD5：[互联网信息服务备案登记表](https://xzca.miit.gov.cn/bsfw/bszn/art/2024/art_5d3cc7f452c04fdd97b6881a20b656f9.html)
- 完整服务器、域名和提审细节继续参考：[微信小程序服务器部署、备案与异地内测手册](微信小程序服务器部署、备案与异地内测手册.md)
