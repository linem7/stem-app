## 1. 产品是什么

帮**中国大陆幼儿园老师**撰写 STEAM 教案的**手机网页应用**。

老师说一句话（「我想做个浮与沉的活动」），AI 一屏问 4 个问题、每题附可点选的推荐答案卡片，
最后生成结构完整的教案，可选配图；觉得哪里不对说一句就能让它重写。

**非商用**，作者带着 AI 独立开发，同时是一个研究项目。

### 1.1 它解决的那件事

老师写一份教案要 2–3 小时，格式规范要求高，新手容易漏掉教学目标或安全事项。
更具体的是：**这个产品解决的是「活动开始之前」**，不是活动做完之后的复盘。
所以教案里没有「教学省思（预期与实际的差异）」那一节 —— 活动还没做，那只能是编的。

### 1.2 三条不变的边界

| 边界 | 内容 |
|---|---|
| **不存幼儿的任何信息** | 姓名、生日、照片、家长联系方式、任何一个孩子的能力评价或行为记录，一律不存。判据：这条数据是关于孩子的，还是关于机构 / 老师的？关于某个孩子的一律不存 |
| **汇总规模不算个体信息** | 园所档案里的「在园幼儿人数」是机构规模，跟「在园教师人数」同类。但界线只到这儿：不许出现按班级、按年龄段、按任何维度拆到能定位到人的幼儿数据 |
| **老师的数据园长看不到** | 管理后台只有作者和（可能的）项目团队。协议里要加粗明示 —— 老师最怕的是园长看到她用 AI 写教案 |

### 1.3 目标用户

大陆幼儿园一线老师，22–45 岁，小 / 中 / 大班。可能是新手（急需指导），也可能是
经验老师（想提升质量）。她在幼儿园里**随时会被叫走**，这条前提决定了很多设计。

## 2. 身份与账号

### 2.1 三层身份，不许混

| 说的是 | 字段 | 含义 |
|---|---|---|
| **人** | `teacher_roster.teacher_ref` | 换班也不变。追这位老师按它归组 |
| **位置** | `teacher_roster.id` | 人 × 园 × 班 × 岗位。就是 `class_teacher_id`。追这个班按（园所 + 班级）归组 |
| **账号** | `teachers.id` | 她登录进来的那个东西 |

她换班了走岗位调整：新开一行、沿用同一个 `teacher_ref`、旧那一行标 `moved` **留着不删**
（研究要用它区分「她在小一班那半年」和「她在中二班这半年」）。她自己什么都不用做。

她注销之后，**位置放回「待激活」** —— 位置是园所的，不是她的；明年这个班还有主班，
只是换了人。但认领记录留着（出争议时要查）。

### 2.2 登录（web 端的新模型）

```
第一次       输兑换码 → 从名单里选自己是哪一位 → 设手机号 + 密码 → 发额度
日常         token 免登录（180 天，每次打开自动续期）
换设备/清缓存 手机号 + 密码
忘密码/号打错 找作者人工处理
```

**手机号在这个系统里只是用户名。** 不用于联系、不进 AI 提示词、不下发到页面、不进日志。

四条约束：

1. 🔴 **手机号输两遍核对。** 11 位打错一位是常事，而后果特别隐蔽 ——
   她下次登录输的是**正确的号**、库里存的是**打错的号**，进不去，
   且她完全不知道哪里出了问题
2. **不发短信验证码。** 理由是资质，不是成本，见 ADR-002
3. **密码存 scrypt 哈希**，复用管理员那套实现
4. **激活那一屏只问手机号和密码。** 园所、班级、岗位、姓氏在「从名单里选自己」那步已经有了

### 2.3 首次激活要两样

- **兑换码**证明「你是这批人里的」（问卷星在她提交答卷后当场发，不用人工私发）
- **从名单里选自己是哪一位**（园所 → 班级 → 岗位 · 姓氏）

⚠️ **拉名单必须先有一个有效的码**（`POST /auth/roster/options` 会先校验）。
不设这道门，任何人打开网页就能看到一整个园的老师名单。**姓名只给姓氏。**

🔴 **校验失败绝不能消耗那个码。** 顺序必须是「先全部校验，再全部落库」——
她进不来时只会说一句「用不了」，没有别的线索。

**要认下来的代价**：从列表里选是一个**表单字段，不是钥匙**，谁有码都能滚到任何一行。
可以接受，因为同事之间冒领没有收益（她自己填问卷也能拿到同样额度），
而真会发生的「手滑选错同班另一位」是**可查可改**的。

### 2.4 找回账号：人工，锁超管

她提供「园所 / 班级 / 岗位 / 姓氏」，作者在后台处理。密码存的是哈希、不可逆，
所以这是两种不同的故障、两个不同的动作：

- **重置登录密码** —— 生成临时密码给她，她登录后自己改
- **修改账号手机号** —— 她当初打错了

🔴 **两个动作只有超管能做，并且进 `admin_logs`。** 一般管理员现在看不到对话正文，
而能重置密码 = 能登进她的账号 = 绕过那道限制。

登录页要有一行**「登录不了？」**，点开显示联系方式。放在「我的」里没用 ——
她正是进不去的时候才需要它。

### 2.5 额度

**不存 `balance` 字段。** 用「台账 Σ 发放 − 事实表数消耗」算，避免两份事实对不上。

两种额度：**教案额度**（开会话、改稿各消耗）、**配图额度**。
额度闸门装在三处：开会话、改稿、配图。

**额度只走兑换码一条路。** 兑换码分两种：

| 类型 | 用途 | 代价 |
|---|---|---|
| **匿名码** | 后台批量建 N 个（默认 20 教案 / 10 配图），导出 CSV 灌问卷星或整批给园所 | 「问卷答卷 ↔ 账号」的对应关系不在库里，在问卷星那边；后台按码搜人 |
| **绑定码** | 单个建，可指定园所 | 整批交给某个园时「发了几个、兑了几个」是跟进依据 |

兑换码的职责只有两件：**证明「你是这批人里的」** + **发额度**。它**不是登录钥匙**，
所以整批交给园所仍然成立 —— 园长拿一叠码只能激活新账号，进不了任何一位已激活老师的账号。

### 2.6 注销

**留壳去身份**：删对话、教案、配图、记忆、手机号，留 `teachers.id`（用来拒绝再次登录）、
额度台账、已提交的建议评价。

真删行会让她再登录变成全新账号，等于「删完还能接着用」。

## 3. 核心流程：从一句话到一份教案

### 3.1 首页 —— 只是一个对话框

```
问候语
一句话输入框 + 开始按钮
一句轻提示
（可选）主题灵感 chip，从属于输入框
```

🔴 **首页不放任何历史入口。** 不放「最近在写」、不放已完成列表、
不放进入教案库的按钮。过往教案无论完成与否**全部进教案库**。

### 3.2 引导：一屏 4 题

判断标准只有一条：**只问模型猜不到的，不问模型本来就该会的。**

| # | 题 | 说明 |
|---|---|---|
| 1 | **年龄班** | 唯一必答。它一定，时长、环节数、指标数全都跟着定 |
| 2 | **教学重点** | |
| 3 | **场地** | 户外空地搭跷跷板 vs 教室区角做桌面游戏，活动形态完全是两回事，模型只看主题猜不出来 |
| 4 | **班上的情况** | |

**不问时长** —— 年龄班一定时长就定了（20 / 25 / 30），再问是让老师替代码做算术。

**不分轮** —— 老师看不到总量时，答完一题不知道还剩几题，心里没底就容易退出。
一屏摊开 + 一条进度更好。

交互细节：

- **一次性出题 ≠ 一次性提交。** 每选一项仍然调一次 answer 落库 ——
  🔴 **每答一题即落库**，她被叫走进度不丢
- 答题**不限顺序、可覆盖**
- **换了年龄班会重拉推荐答案**（`GET /conversations/:id/questions?age_group=`），已填的答案不动
- 每题下面有一句「为什么问这个」（学习模式下才有；不导出、不落库）

### 3.3 两种模式

| | 效率模式 | 学习模式 |
|---|---|---|
| 引导页每题的「为什么问这个」 | 无 | 有 |
| 成稿页的教案解读 | **连字段都不下发** | 各板块底下折叠一段「为什么这样设计」 |

🔴 前端判据只有一个：`content_json.commentary` 有没有内容。
**不许再判断一次「是不是学习模式」** —— 那等于把同一件事记在两个地方。

### 3.4 生成：异步 + 轮询 + 流式

生成一份教案要 15–30 秒。**必须异步**，而且**必须能离开** ——
老师在幼儿园随时被叫走，不能要求盯着屏幕等。

**等待那一屏摊的是正文本身，不是进度文案。** 模型流式吐字，
后端把半截 JSON 翻成人话，轮询带游标只回新增的那一段。实测第 1 秒就出第一个字。

三步清单是真的（phase → stepIndex 一一对应，不用正则猜文案）。

失败分两种，走两个按钮：

| 情况 | 按钮 | 行为 |
|---|---|---|
| 断网 | 「接着等」 | 只重新轮询。后端还在写，不花钱、可自动 |
| 真没写成 | 「再试一次」 | 一次真的模型调用，只能她自己按 |

原来这两条走同一个按钮 = 每次弱网抖一下就白花一次钱重写一遍。

生成完**自动跳成稿**，不让老师多点一下。

### 3.5 成稿

正文按大陆常见格式，八节：

```
设计意图 → 活动目标（三维各一条）→ 活动重点难点
→ 活动准备（经验 / 物质）→ 活动过程（导入 / 展开 / 结束）
→ 活动延伸 → 安全提示
```

之后是：**STEAM 五域标注** → **《指南》指标** → **教学实例（师幼对话）**。

页面上还有：版本条与回退、配图抽屉、评价。

🔴 **别把这三样东西混成一个词**（2026-08-21 已经因此来回改过一次）：

| 说的是 | 字段 | 在哪 | 导出吗 |
|---|---|---|---|
| **设计意图** | `content_json.intent` | 教案正文第一节，跟活动目标同级 | **一直都导出** |
| **教案解读** | `content_json.commentary` | 成稿页各板块**底下**那行折叠的「为什么这样设计」 | **不导出** |
| 「为什么问这个」 | 出题响应的 `why` | 引导页每题下面 | 不导出，也不落库 |

**老师不在成稿页手打改教案。** 改教案只有一条路：「改一改」那条 AI 重写。
手打改教案在手机上本来就难用，而 AI 重写是这个产品的核心 ——
多开一条手改的路，等于让最不好用的那条跟核心功能抢位置。

（局部编辑接口通着，只是页面上没有调用方。这是有意的，不是待补的缺口。）

### 3.6 改一改与版本回退

```
老师对成稿提意见 → AI 提 3 个新问题（不重复引导阶段问过的）
→ 整份重写、version + 1
```

历史反馈全存在会话里，每次重写都一并喂回模型 ——
否则它会把上次改好的地方按默认写法改回去。

**改稿必须能回退。** 改稿是覆盖式的，不留退路等于逼老师赌一把，
她会因此不敢提意见 —— 而「改一改」正是这个产品的核心。

- 回退**不新增版本号、不删任何版本**，可以来回切
- 回退**不消耗额度**（没退路本来就是我们造成的）

🔴 **图片永远不跟着版本走。** 改稿、回退都不动它。理由是老师的行为本身 ——
她只在觉得某样材料值得画的时候才点生成，那份判断不会因为教案改了一句话就失效。
技术上是天然的（图挂教案 id，那行 id 从不变），**但任何地方都不许按版本清理图片**。

### 3.7 配图

🔴 **配图是给老师打印出来用的**，不是拿来看的示意图 —— 这条决定了一切。

五种用途，构图完全不同：

| 用途 | 构图 |
|---|---|
| **材料图** | 单件占满画面。老师一句话里说了好几样就排成 **A4 竖版裁切网格**（列少行多，6 样 = 2 列 × 3 行，格间留白 + 细裁切线），印一张剪开就是几张材料卡 |
| **记录表** | 粗线大格子、格内留白、竖版 |
| **头饰** | 中间图案 + 左右两条长带，带子要画到画面边缘才够绕头。说了好几种就上下排开，封顶 4 条 |
| **展示图** | 网格分隔 |
| **环创背景** | 四周装饰、**中间大片留白**给孩子贴作品 |

- 老师可以从材料清单里挑，**也可以自己描述**（比如背景墙）。入口是底部抽屉，
  不是让她滚回页面顶部去点
- **一份教案最多 3 张。** 尺寸按打印定：长边 2048（A4 约 250 DPI），不是按屏幕
- **老师完全不碰模型**。用哪家是技术判断，老师没有判断依据，选错了还会怪自己

顺带把最难的风险消掉了：这些图里本来就不该有儿童，
**「不要画脸」那条压不住的约束现在根本不需要。**

### 3.8 教案库 —— 唯一的历史入口

- **草稿**：显示标题、年龄班、进度、时间；点进去接着写
- **已完成**：显示标题、年龄班、时间、有没有配图；点开成稿
- **筛选**：状态（全部 / 草稿 / 已完成）+ 年龄班（小 / 中 / 大班）
- **删除**：左滑露出红键 → **点它再确认一次**（删教案不可逆，
  而手指顺势往那块红色上一点太容易发生）
- **时间带上时刻**（「今天 14:05」）：她一天里常连着写两三份，
  三张卡片全写「今天」就分不出哪张是刚才那份

> web 端待定：左滑是触屏手势。桌面浏览器上要给等价入口（悬停出现删除键或右键菜单）。

### 3.9 我的

```
个人档案（在「我的记忆」底下当第一条，不参与编号）
我的记忆（可加、可改、可删）
任务入口
帮助与反馈
协议入口
```

**个人档案六项**：园所 / 年级 / 岗位 / 最高学历 / 职称 / 教龄。
归在记忆那一节，是因为那节的副标题就是「写教案时会自动带上」，而这六项正是每次都带上的。

- **不给它编号** —— 编号是给「一条条攒起来的记忆」的（她会说「第 3 条删掉」），
  档案只有一份、删不掉
- **那一行只写「个人档案」四个字**，不预览里面填了什么
- **那一行是开关**：点开、再点收起。展开区里**没有「取消」**（多一个取消等于给同一件事留两个入口）
- 🔴 **「未评定」是她主动选的值，跟 NULL（没填过）不是一回事**，
  任何地方不许把 NULL 显示成「未评定」。同理 `teaching_years: 0` 是有意义的（今年刚入职）

**学历和职称不是装饰性档案，是研究要用的自变量** ——
「AI 写的教案对新手和对一级教师，帮助是不是同一回事」，教龄答不了这个问题。

**记忆整行就是改**：一行只有一个动作，就让整行成为那个动作；不显示记忆类型
（「教学信息」之类是给数据库看的）。

**记忆抽取有合规红线**：不提取姓名、年龄、幼儿表现、家庭情况、**健康与过敏**。
⚠️ 没加关键词黑名单 —— 中文自由文本既会误伤（「材料要防误食过敏源」是合法的）
又绕得过，加了只会给人「已经防住了」的错觉。

### 3.10 任务

后台发定向任务（六维），老师端在首页条带 +「我的」一行 + 任务页看到。

🔴 **匹配逻辑只写一次**：管理端试算和老师端列表共用同一个谓词。
写两份分叉的表现是「后台说发给 12 个人，实际只有 8 个人看到」，而且不报错。

### 3.11 反馈

两类：**教案评价**（挂某一份教案，三档）和**产品建议**（分类）。

## 4. 教学内核 —— 这个产品真正的价值

### 4.1 年龄班规则必须真正生效，不能只写在提示词里

那本台湾教材的案例默认孩子会言语预测、会读量杯刻度、能小组分工 —— 这是中大班能力。
3–4 岁小班做不到。三层保障：

1. **只注入当前年龄班的规则**。三个班一起给，模型会挑最丰富的那套 ——
   这是给小班写出大班活动的根因
2. **时长选项由代码从参数表算**（选小班界面就没有 45 分钟这个选项）
3. **生成后代码硬校验**（小班出现量杯读数 / 预测 / 统计图表 / 缺误食风险 → 记违规）

参数表（2026-08-24 定死）：

| 年龄班 | 时长 | 环节数 | 《指南》指标数 |
|---|---|---|---|
| 小班 | 20 分钟 | 3 | 2 |
| 中班 | 25 分钟 | 4 | 3 |
| 大班 | 30 分钟 | 4 | 4 |

**大班 30 分钟仍写四环节**：那一段「换个法子再试」是探究循环的核心，
降三环节等于把大班最有价值的部分去掉。

### 4.2 小班的 STEAM 不必五域齐全

模型天然倾向凑满五个显得完整，会给小班写出「统计浮沉数量并绘制条形图」。
规则是 **S + A 为主、E 可缺席**，**宁可诚实标注缺席，不要虚假齐全**。

界面上用虚线框 +「刻意不做」胶囊 + 一句理由呈现。

⚠️ 但这条许可**只给小班**。给大班留同样的退路，等于**把违规包装成专业判断**，
老师没有线索去质疑。

### 4.3 《指南》指标必须可校验

不靠模型记忆。结构化的《指南》（5 领域 / 11 子领域 / 32 目标 / 97 条典型表现）在库里，
按年龄班只取该档的典型表现注入。

🔴 **引用的是「某一句典型表现」，不是「目标名」** —— 目标名三个年龄段共用，
输出里看不出这条对应哪一档。格式：

```
科学 （一）科学探究 目标1：喜欢接触新事物，经常问一些与新事物有关的问题。
```

带完整位置（子领域**保留「（一）」序号**），老师能在原书里精确翻到那一句。
年龄段错配自动被剔除 —— 句子只在它那一档的清单里，抄别档的匹配不上。

**硬校验：对不上清单的剔除**（同「宁可诚实标注缺席」那条纪律）。

### 4.4 教案解读（学习模式第 3 阶段）

挂 `content_json.commentary`，9 个键的白名单，**第三次模型调用**，默认折叠，**不进导出**。

**宁可缺一条，不要凑一条**：模型答不上来的板块就不写那个键。

### 4.5 自检不在主链路上

8 维度打分的产出**老师一个字都看不到**，却实测占 3 秒。它跟教案解读并行跑，
存完库后事后回填。

`model_pending: true` 是必须有的：没它，「自检还在跑」和「自检失败了」在库里长得一模一样，
而「有多少比例的自检真的成了」正要用这个字段回答。

### 4.6 模型管理

文本和配图**都在管理后台「模型管理」里**，一张表，`kind` 分 text / image。

- **加一家不用改代码**：后台填**三样** —— 接口地址、API key、模型 id
- **接口格式不让人选，靠推断**。🔴 **先看模型 id，再看地址**。都认不出退通用档，**绝不猜**
- **文本模型的「思考模式」「联网」是真实生效的调用参数，不是标签**
- 🔴 **开关只作用于声明了 `applyToggles` 的调用**（生成教案、教案解读、后台模型测试）。
  管理员开思考的本意是「教案写得更好」，不是「每句寒暄都思考」
- 🔴 **最后一个启用的文本模型不许删、不许停用**（「没文本模型不启动」×
  「加模型唯一入口是后台」= 死锁）

## 5. 数据传输逻辑

### 5.1 统一信封

所有接口返回同一个形状：

```json
{ "ok": true,  "data": { ... } }
{ "ok": false, "error": { "code": "QUOTA_EXCEEDED", "message": "...", "retryable": false } }
```

调用方只要 try/catch，不用每次判断 `res.ok`。错误码表见 `docs/design/api-spec.md`。

### 5.2 鉴权

`Authorization: Bearer <token>`。JWT 带 `token_version` ——
重置密码、注销时版本 +1，旧 token 当场失效。

**老师的 token 打不开后台，管理员 token 也调不了业务接口。**

### 5.3 异步生成的增量协议

```
POST /conversations/:id/generate          → 立即返回，进队列
GET  /conversations/:id/generate/status   → 轮询，带 epoch + from 游标
```

🔴 **`epoch` 和 `from` 缺一不可。** 模型被截断会重打一遍 ——
只有 `from` 的话她会看到两份教案首尾相接，而 **HTTP 200、日志干净、教案照样生成成功**。
对不上就 `restart: true` + 全量，前端清屏。

🔴 **只增不减是整套增量协议的地基。** 两条纪律：
**键名没收全一个字都不发**、**结尾绝不 trim**。

> web 端沿用轮询（已有 33 条回归覆盖）。改 SSE / EventSource 是可选优化，不是需求。

### 5.4 前端必须处理的四态

空 / 加载 / 失败 / 无网。

**「无网」的判据是两个条件同时成立**：请求没到后端 **且** 系统报告断网 ——
只看前者会把「网络正常、后端连不上」画成无网。**网一回来自动重来一次**，
她不用记得回来点。

失败绝不能伪装成空（「现在没有可以做的事」）；失败后也不许显示假的 `0/0 次教案`。

### 5.5 内容安全与限流

- **老师输入和 AI 输出都要过内容安全**。web 端走**腾讯云文本内容安全（TMS）**
- **API key 只在服务端**，任何情况不下发到浏览器
- **日志不记录对话正文**

### 5.6 web 端相较小程序的传输层差别

| | 小程序 | web |
|---|---|---|
| 请求 | `wx.request` / `wx.cloud.callContainer` | `fetch` |
| PATCH | **发不出来**，要 POST 别名 | 能发。三个 POST 别名**留着不删**（无害，已有回归覆盖） |
| token 存哪 | `wx.setStorageSync` | `localStorage` |
| 图片 | 临时磁盘 → 必须换对象存储 | COS 对象存储 |

## 6. 数据模型（要点）

六张核心表 + 运营表。完整设计见 `docs/design/db-schema.md`。

```
teachers ──┬── conversations ── messages
           │        └──────────── lesson_plans ──┬── lesson_plan_versions
           │                                     └── lesson_images
           ├── teacher_memories
           └── teacher_roster（名单：人 / 位置）

kindergartens · redemption_codes · code_batches · quota_grants · feedback
tasks · ai_models · app_settings · admins · admin_logs · model_calls
```

**web 端 schema 的三处差异**：

1. `teachers` 去掉 `openid`，改 `phone`（唯一）+ `password_hash`
2. `teacher_roster` 去掉 `claimed_openid`（它存在的唯一理由是 openid）
3. `account_rebinds` 整张表作废（换绑改人工找回）

**新建空库，不在旧库上加迁移。** 只有 `ai_models` 里的 API key 从旧库带过来，
而且必须连同**接口地址**、**模型 id**、**识别出的接口格式**一起带 ——
一把 key 光有自己没用。

## 7. 管理后台（web，原样保留）

电脑浏览器打开 `/admin`。跟老师端**完全隔离**。

页面：概览、园所、教师、兑换码、反馈、任务、模型管理 + 超管专属的管理员账号与操作记录。

**两级权限**：一般管理员能做全部运营（发额度、建码、看反馈），
但**看不到手机号全号和对话正文**，也**不能重置老师的密码**。

理由不是技术洁癖：老师同意的协议原话是「只有开发者本人可见」，
加了同事账号之后那句就不准确了，所以协议改成「项目团队」，
同时把最敏感的几项锁在超管手里。**每多一个人能读老师写的东西，那句承诺就少一分是真的。**

仍然**没有**「园所管理员」这种角色。要是哪天加了园长只读账号，
那句承诺就作废，必须先跟老师们重新讲清楚。

### 7.1 后台的界面规矩

- **一律用规范术语，不用口语**（「停止」不是「收了」，「岗位调整」不是「她换班了」）。
  ⚠️ 这条**只管后台**。老师端保持口语化 —— 她不是运营人员
- **筛选挪到列标题上**，且**一律纯文本**（不靠底色）+ 常驻的「清除筛选」按钮
- **列宽固定**（`table-layout: fixed` + `scrollbar-gutter: stable`），
  **每一列都要写 width** —— 漏掉的会平分余量
- **页面主标题底下不写汇总小字**

## 8. 平台自己的账

手录充值 + 支出自动算。**「充了多少 / 还剩多少」这个概念已经撤掉** ——
余额那个数永远不准而且看起来很准（充值靠手录，漏录一笔就虚高，
而真实余额在各家厂商自己的后台里）。

支出侧留着 —— 它是每次调用当场落库的事实，不靠人记得录。

## 9. 界面原则

设计方向：**方向 B（Typeform 标杆迁移）**。单一焦点列、选项配 A/B/C/D 字母 + 打勾、
拇指位常驻操作条。**这些是核心资产，不要改。**

配色：奶油白底 + 暖阳黄（主行动）+ 薄荷绿（次级 / 已完成）+ 天空蓝与珊瑚粉（点缀）。
唯一来源是 `docs/design/design-tokens.md`，组件里禁止裸 hex。

四条会反复犯的：

1. 🔴 **界面上不要写解释性小字。** 写每一句副标题、每一段 note 之前先问：
   **她不看这句话会做错什么吗？** 答不出来就删掉。
   只有两种留得住：**边界说明**（「超管可见全号」，不说她会以为是 bug）
   和**不可逆动作的后果**（「不可逆」三个字必须出现在她按下去之前）
2. **亮色只做底，深色只做字。** 需要彩色文字时用对应的 `-deep` 档 ——
   但「用 deep 档」本身不等于达标，逐对算过比值才算
3. **颜色不做状态的唯一载体。** 草稿 / 已完成必须同时有文字；
   **选中态也算** —— 选中胶囊一律多一个打勾
4. **字号只有八级，必须走令牌**，下限 12px

## 10. 明确不做的

| 不做 | 理由 |
|---|---|
| 微信小程序 | 见 ADR-002 |
| 原生 APP | 同上，且个人主体上不了 iOS |
| 短信验证码 | 个人主体报备不了签名 |
| 手打改教案 | 手机上难用，且会跟核心功能抢位置 |
| 全文 RAG | 规避版权。只做框架提炼，原书 PDF 不入库 |
| 老师端的模型选择 | 老师没有判断依据，选错了还会怪自己 |
| 园所管理员角色 | 那句「园长看不到」的承诺会作废 |
| 界面语言切换 | 全程简体中文已定死。做一个切了没反应的开关比没有更糟 |
| TypeScript / ORM / Docker 编排 / 微服务 / 消息队列 | ADR-001 |
| PWA（现阶段） | 它要 HTTPS，而 HTTPS 要等域名和备案 |

## 11. 验收标准

### 11.1 功能

- [ ] 老师能用兑换码激活、设手机号密码、换设备后登得回来
- [ ] 老师能生成至少 1 份完整教案，从打开到成稿 < 15 分钟
- [ ] 三个年龄班出三档梯度（时长 / 环节数 / 指标数 / STEAM 缺席）
- [ ] 改稿与版本回退能来回切，且不消耗额度
- [ ] 配图五种用途各出一张，打印出来能用
- [ ] 记忆能准确提取和复用，且不含幼儿个体信息

### 11.2 质量

- [ ] 首屏 < 2s；生成教案 < 30s
- [ ] 没有数据丢失（每答一题即落库）
- [ ] 对比度逐对达标；字号三档可调
- [ ] 回归脚本全绿

### 11.3 用户

- [ ] 5 位内测老师中至少 3 位给教案评分 ≥ 4/5
- [ ] 至少 2 位在实际班级用过生成的教案
- [ ] 老师反馈「节省时间」或「启发了我的设计思路」

## 12. 待验证的假设

- **产品最大的未知数：AI 生成的教案是否真的适龄可用。** 三个班三档梯度稳定，
  从 11 题一路砍到 4 题、质量没有下降 —— 但样本只有三份，
  且**没经过真实幼儿园老师复核**
- `age-band-adaptation.md` 里的**小班时长上限和循环次数**是依据发展常识推的，
  需要真实小班老师复核
- 《指南》指标的条目选得准不准，没有真实老师复核过
- 推荐答案的个性化质量依赖模型，需内测验证
- **配图采用率是成本的主要变量**，上线后要盯这个数
- **积分转让**（老师把额度给别人）还没想清楚。它会动额度台账的模型，
  而且转让一旦可行，「一个码只能兑一次」就不再是额度的唯一入口
