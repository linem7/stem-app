# ADR 002: 从微信小程序转向 web 端

## 状态

已采纳 (2026-08-30)。取代 ADR-001 中「客户端：微信小程序 + uni-app」那一节。

## 背景

2026-08-25 到 08-26，项目卡在上线的最后一段路上：

- 真 AppID 已经拿到（`wxd7ae717c264d181e`），体验版能编能传
- 后端已按微信云托管改造完毕（`Dockerfile`、`callContainer` 分流、`X-WX-OPENID` 登录）
- 但小程序要正式发布，需要一个**企业主体**。作者是个人，走的是「借朋友公司的营业执照
  做主体变更」这条路 —— 08-26 那两份文档（`新企业主体小程序最省事行动清单.md`、
  `小程序主体变更申请函.doc`）写的就是这件事，全程需要朋友配合三次、盖章、寄件

转向 web 端，是为了把这条依赖别人的路砍掉。

## 决策

**放弃微信小程序，产品改为手机浏览器优先的 web 应用。管理后台原样保留（它一直是 web）。**

### 🔴 真实理由是「甩掉企业主体」，不是「免备案」

这条必须写死，因为它很容易被记反，而记反之后会有人把这个决定推翻回来。

事实是：**转向 web 端不但没有省掉备案，反而主动放弃了全项目唯一一条免备案的路。**
`docs/design/deployment-wxcloudrun.md` 开头写着 08-25 选云托管的唯一理由 ——
小程序经 `wx.cloud.callContainer` 走微信内部通道，**不需要 https 域名、也不需要网站 ICP 备案**。

| | 小程序（云托管） | web 端 |
|---|---|---|
| 网站 ICP 备案 | **不需要** | **需要**（大陆服务器 + 域名，7–20 个工作日） |
| 小程序备案 | 需要（微信公众平台办，比 ICP 容易） | 不适用 |
| 主体 | **必须企业**（借朋友的营业执照） | **个人即可**（非经营性网站个人可备案） |
| 要别人配合 | 是，三次 | 否 |

web 端赢的是最后两行，输的是第一行。这笔交易是划算的 —— **依赖别人的事情没有工期，
而备案有**。但它不是「省掉了麻烦」，是「换了一种麻烦」。

## 被这次转向推翻的旧决策

| 旧决策 | 定于 | 现状 |
|---|---|---|
| 平台是微信小程序，需 ICP 备案 | ADR-001 | **推翻**。改 web，仍需 ICP 备案 |
| 老师不登录，身份就是 openid | 2026-08-19 | **推翻**。web 端没有 `wx.login`，见下「身份」 |
| 换绑码 `account_rebinds`（014 迁移） | 2026-08-19 | **作废**。它存在的理由是「换微信 = 新 openid」，改后端人工找回 |
| 016 迁移把手机号彻底删掉 | 2026-08-19 | **部分推翻**。手机号回来了，但**只当登录名**，见下 |
| 内容安全走微信 `msgSecCheck` | 建项时 | **替换**为腾讯云文本内容安全（TMS） |
| 微信云托管部署（免备案路线） | 2026-08-25 | **作废**。改腾讯云轻量应用服务器 |
| 前端用 uni-app | ADR-001 | **推翻**。改纯 Vue 3 + Vite + vue-router |
| 小程序发不出 PATCH，要加 POST 别名 | 2026-08-18 | **作废**。浏览器能发 PATCH。三个 POST 别名**留着不删**（无害，且已有回归覆盖） |
| `test:mp` 那套编译产物 lint | 2026-08-25 | **作废**。事件名 `tap`、`<block>` 上的 `wx:key`、v-for key 跨兄弟唯一、handler key 哈希撞桶，web 端一条都不适用 |
| 字号档必须内联在 `s-page` 根节点 | 2026-08-20 | **作废**。它的成因是微信自定义组件 `styleIsolation: 'isolated'`，浏览器没有这回事 |
| `.env` 按平台分流 + 条件编译 | 2026-08-25 | **作废**。只剩一个平台 |

**没有被推翻的**（这些是产品资产，跨端全部成立）：年龄班三层保障、教案的大陆格式、
STEAM 五域可以诚实缺席、《指南》指标引用原文典型表现、模型管理与开关、
配图五种打印用途与三条实测教训、改稿与版本回退、学习模式与教案解读、
额度台账、任务定向、名单与三层身份（人 / 位置 / 账号）、
设计方向 B 与全套设计令牌、界面上不写解释性小字、亮色只做底、不存幼儿任何信息。

## 新的技术决策

### 客户端：Vue 3 + Vite + vue-router，手机浏览器优先

不保留 uni-app 只编 H5。理由是残骸：留着 uni 就要一直带着 `rpx`、`pages.json`、
`uni.navigateTo`、条件编译和一整套只为小程序存在的知识负担，而它们在 web 上一条都不适用。

`src/api/`（6 个文件）、`src/stores/`（4 个）、SCSS 设计令牌、字号梯子（`utils/typography.js`）
**原样搬过去**，真正要重写的是 10 个页面（约 6500 行）的模板和尺寸单位。

**尺寸单位：`rpx ÷ 2 → px`，页面套 `max-width` 居中**（2026-08-30 定）。
宽度和布局照样弹性，只有字号和间距固定。**不做等比缩放**（根字号跟视口宽走）——
它会跟字号三档可调打架，也会盖掉用户自己调过的浏览器字号。

**不做 PWA / 添加到主屏幕**（现阶段）：它需要 HTTPS，而 HTTPS 要等域名和备案。

### 身份：兑换码激活 → 手机号 + 密码

```
第一次       输兑换码 → 从名单里选自己是哪一位 → 设手机号 + 密码 → 发额度
日常         token 免登录（180 天，每次打开自动续期）
换手机/清缓存 手机号 + 密码
忘密码/号打错 找作者人工处理
```

四条设计约束：

1. **手机号输两遍核对**。11 位打错一位是常事（这正是 016 迁移当初删掉手机号的理由），
   而后果特别隐蔽 —— 她下次登录输的是**正确的号**、库里存的是**打错的号**，
   进不去，且她完全不知道哪里出了问题
2. **不发短信验证码**。国内短信签名要报备资质，而腾讯云自 2025-09-18 起
   **不再支持个人自用资质**，个人只能走「他用资质」并要签名归属公司出具授权委托书、
   加盖双方公章 —— 那等于把「借企业主体」原样请回来
3. **密码存 scrypt 哈希**，复用 `services/admins.js` 里管理员那套实现
4. **激活那一屏只问手机号和密码**。园所、班级、岗位、姓氏在「从名单里选自己」那步已经有了，
   再问一遍她会以为自己填错了什么

**手机号在这个系统里只是用户名。** 不用于联系、不进 AI 提示词、不下发到页面、不进日志。
协议里那段要按这个措辞重写（这是它第三次改）。

### 账号找回：人工，且锁在超管

她提供「园所 / 班级 / 岗位 / 姓氏」，作者在后台处理。后台要两个动作
（密码存的是哈希、不可逆，所以这是两种不同的故障）：

- **重置登录密码** —— 生成临时密码给她，她登录后自己改
- **修改账号手机号** —— 她当初打错了

🔴 **这两个动作只有超管能做，并且进 `admin_logs`。** 理由不是洁癖：一般管理员现在
看不到对话正文，而**能重置密码 = 能登进她的账号 = 绕过那道限制**，
那句写在协议里的承诺就作废了。

登录页要有一行「登录不了？」，点开显示联系方式。放在「我的」里没用 ——
她正是进不去的时候才需要它。这属于**边界说明**，是允许留在界面上的两种小字之一。

### 兑换码：职责收窄

只剩两件事：**证明「你是这批人里的」** + **发额度**。它不再是登录钥匙。

由此，「批量建码整批交给园所」这个功能**继续成立** —— 园长拿一叠码只能激活新账号，
进不了任何一位已激活老师的账号（那需要她的手机号和密码）。

### 内容安全：腾讯云文本内容安全（TMS）

`msgSecCheck` 随小程序作废。TMS 个人实名认证即可开通，官方接入前提只有
「注册 + 实名 + 账户余额大于 0」，没有短信那种资质审核。

新建 `services/contentSafety.js`，`wechat.js` 整个归档。

### 部署：腾讯云轻量应用服务器

| 项 | 选择 | 理由 |
|---|---|---|
| 服务器 | 腾讯云轻量应用服务器（大陆） | 自带公网 IP，可办备案 |
| 数据库 | **服务器上自装 PostgreSQL** | 研究项目，日备份到 COS 足够；不买云数据库 |
| 图片 | **COS 对象存储** | 顺带消掉「云对象存储」这个从建项挂到现在的 TODO |
| 管理后台 | 同域名同端口 `/admin` | 现在就是这样，不为拆而拆 |

**内测期用裸公网 IP，不办域名。** 备案检测盯的是「域名解析到国内 IP」，不是 IP 本身；
腾讯云自己也把「备案期间先用公网 IP 访问」写成推荐的过渡做法。

### 数据库：新建空库

不在现有 `stem_app` 上加迁移。理由是 `teachers.openid` 是唯一键而 web 端没有 openid，
围绕它的 016 / 014 / 015 三次迁移也都要回改 —— 把 21 次迁移的历史掰弯，
不如按新模型重写一份干净的 schema。

**只有一样东西从旧库带过去：`ai_models` 里的 API key。** 而且必须连同
**接口地址**、**模型 id**、**识别出的接口格式**一起带 —— 一把 key 光有自己没用，
`nanobanana` 和 `gpt-image-2` 挂在同一个中转地址下，靠模型 id 才分得开。
其余（单价、开关、默认值、停用状态、名单、园所、演示数据）全部重建。

## 认下的代价

1. **备案回来了。** 要给真实老师用之前必须办域名 + 个人 ICP 备案，7–20 个工作日
2. **冒领可查不可防。** 人工找回的凭据是「园所 + 班级 + 岗位 + 姓氏」，
   而这四样同事和园长都知道。它证明的是「她是名单上那一行的人」，不是「她是那个账号的主人」。
   在这个产品里两者恰好等同（一行名单 = 一个位置 = 一个账号），所以够用；
   真会发生的冒领是**可查的** —— 同一行名单短时间内被处理两次，后台看得见
3. **微信生态的获客与传播没有了。** ADR-001 把「大陆用户获客成本低、微信生态传播力强」
   列为选小程序的第一条理由。web 端要靠链接分享，而链接在微信里的打开体验不如小程序
4. **一份可工作的小程序被放弃。** 10 个页面、四态、字号档、流式撰写全部跑通过，
   只差一个企业主体。归档在 `Archive/mini-program/`
5. **伦理审查批号没有作为闸门。** 见下

### 关于伦理审查批号（作者 2026-08-30 决定）

`CLAUDE.md` 原来写死的是「真要收手机号，先有伦理审查批号 + 协议里那段单独同意」。
作者决定：**不把批号设为上线闸门**，改为在收集信息前向老师说明用途。

如实记录代价，供投稿那天的作者参考：

- **知情同意**（PIPL 的告知同意）和**伦理审查批号**（机构 / 期刊的要求）是两件事，
  做了前者不等于有了后者
- 批号**事后补不上**。数据收完了再去申请，委员会通常不受理
- 这道风险在加手机号之前就已经存在 —— 只要用真实老师名单
  （园所 + 班级 + 岗位 + 姓氏就已经可识别到人）。加手机号是把要声明的数据
  从三项变成四项，**不是从零到一**

## 三道闸门（写成条件，不是备注）

一个过渡方案不写死退出条件，就会变成永久方案。

| # | 闸门 | 触发条件 | 为什么 |
|---|---|---|---|
| 1 | **HTTPS** | 给真实老师用之前必须完成：域名 + 个人 ICP 备案 + 证书 | 登录要传密码。裸 `http://` 是明文，幼儿园的 WiFi 是共用的。Let's Encrypt 不给 IP 签证书，自签会让浏览器红屏 —— **没有「不要域名也能有 HTTPS」这条路** |
| 2 | **知情同意** | 收集手机号之前，界面上明确告知用途、去向、不下发前端 | 见上一节 |
| 3 | **超管锁** | 「重置密码」「修改手机号」两个动作上线时，必须同时具备超管限制和 `admin_logs` 记录 | 不锁死，一般管理员就绕过了「看不到对话正文」那道限制 |

## 明确不做的

- **不做微信公众号 / 服务号网页授权**：它要已认证的服务号，等于「借企业主体」再来一次
- **不接短信验证码**：个人主体报备不了签名，见上
- **不挂靠朋友公司的域名**：子域名复用备案的前提是主办者主体一致，挂上去法律上是
  他公司在提供这项服务；而且接入商不一致时要为他那个一级域名办「新增接入」，
  又要他在腾讯云买服务器。这条路把「找朋友」原样请回来了
- **不用境外服务器绕开备案**：大陆访问慢，且要发论文的项目不适合踩合规灰区
- **不保留 uni-app 只编 H5**：见上「客户端」
- **不做 PWA**（现阶段）：它要 HTTPS
