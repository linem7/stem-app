# ADR 003: 云厂商从腾讯云换到阿里云

## 状态

已采纳 (2026-09-01)。取代 ADR-002 中「部署：腾讯云轻量应用服务器」「内容安全：腾讯云文本内容安全（TMS）」两节。

## 背景

ADR-002（2026-08-30）转向 web 端时，顺手把云厂商定成了腾讯云。那个选择**没有经过比价** ——
它是从小程序时代继承下来的惯性：微信云托管是腾讯的，所以服务器、对象存储、内容安全
一路都按腾讯云写。

到 2026-09-01 为止，腾讯云那边**一样东西都还没买**：服务器没开、备案没办、TMS 没开通。
换厂商的成本因此只有文档，没有迁移。

## 决策

**服务器、对象存储、内容安全三项全部改用阿里云。**

### 真实理由（两条，都不是技术理由）

1. **价格 / 活动优惠** —— 阿里云这边拿到的服务器价格更合适
2. **已经有阿里云账号** —— 账号和实名都办好了，腾讯云那边要从头开始

诚实地记下来：**这不是一个技术选型，是一个成本和手续的选择。**
两家在这个项目用得到的能力上没有差别 —— 一台能装 PostgreSQL 的国内 Linux 服务器、
一个对象存储桶、一个文本审核接口，两家都有，都够用。
所以**不要**事后给它编一套技术理由，也不要因为「阿里云更专业」这类说法把它推翻回来。

## 被推翻的旧决策

| 旧决策 | 定于 | 现状 |
|---|---|---|
| 服务器：腾讯云轻量应用服务器 | ADR-002 | **推翻**。改阿里云 |
| 图片：腾讯云 COS 对象存储 | ADR-002 | **推翻**。改阿里云 OSS |
| 内容安全：腾讯云文本内容安全（TMS） | ADR-002 | **推翻**。改阿里云内容安全 |

**没有被推翻的**（这些跟厂商无关，一条都不动）：

- 服务器上**自装 PostgreSQL**，不买云数据库
- 管理后台 `/admin` **同域名同端口**
- 内测用**裸公网 IP 不办域名**；上线前必须补域名 + 个人 ICP 备案 + HTTPS（三道闸门原样成立）
- 数据库**新建空库**，只从旧库带 `ai_models` 的 key + 地址 + 模型 id + 格式
- 文本模型和配图模型**仍然走各自的厂商**（DeepSeek、12ai 中转、MiniMax）——
  换的是基础设施，不是 AI 供应商

## 新的技术决策

### 部署：阿里云服务器

| 项 | 选择 | 理由 |
|---|---|---|
| 服务器 | 阿里云（ECS 或轻量应用服务器，**按实际买到的优惠定**） | 自带公网 IP，可办备案 |
| 数据库 | **服务器上自装 PostgreSQL** | 不变。研究项目，日备份到 OSS 足够 |
| 图片 | **OSS 对象存储** | 替掉 COS，用途不变 |
| 管理后台 | 同域名同端口 `/admin` | 不变 |

**实际买的**（2026-08-31 开，2026-09-01 用 OpenAPI 核过）：
杭州 `ecs.e-c1m1.large`，2 核 2G，Ubuntu 22.04，有公网 IP。

🔴 **它是按量付费，不是包年包月，所以现在备案过不了**（四条缺第一条）。
作者 2026-09-01 决定：**内测期先不转**，理由是内测走裸 IP 本来就不需要备案。

⚠️ **这个决定把备案推成了上线前的关键路径。** 备案要 7–20 个工作日，
而它现在一天都没开始走。**内测一结束，第一件事是转包年包月 ≥3 个月然后立刻提备案**，
不是等前端都做完了再想起来。转换在控制台就能做，不重装、不换 IP。

### 内容安全：阿里云内容安全（Green）

替掉腾讯云 TMS。仍然是老师输入和 AI 输出都要过，仍然新建 `services/contentSafety.js`。

**这次换厂商换出了一个意外的好处**：阿里云的文本审核有两个**专门给大模型场景**的 service，
跟这个项目的两个调用点正好一一对应 ——

| 调用点 | service | 单次上限 |
|---|---|---|
| 老师输入 | `llm_query_moderation` | 2000 字 |
| AI 输出（教案正文） | `llm_response_moderation` | 5000 字 |

接入要点（已核过官方文档）：

- 接口：`POST TextModerationPlus`，API 版本 `2022-03-02`
- 端点：`green-cip.{region}.aliyuncs.com`（上海 / 北京 / 杭州 / 深圳 / 成都）
- 认证：`AccessKeyId` + 签名，走标准 OpenAPI 那套
- QPS：单用户 20/秒（`TextModerationPlus` 文档口径），这个项目远够
- 计费按**成功请求**（HTTP 200）算

🔴 **一份教案正文超过 5000 字怎么办，还没想。** 现在的教案两千多字，够用；
但改稿几版之后可能顶上去。真顶上去要分段送审，**不能静默截断** ——
截断等于「后半截没审」，而它看起来跟审过完全一样。

✅ **2026-09-01 实测调通了，个人实名账号可以开通。** 这条原来是 ADR 里挂着的未知数，现在销掉。

用真 key 调 `TextModerationPlus`（`llm_query_moderation`，送「我想做个浮与沉的科学活动」），
回 `Code=200`、`RiskLevel=none`、标签 `nonLabel`。**这套链路是通的。**

⚠️ 但**免费额度和单价还没看**，上线前要确认 —— 每条老师输入和每份教案都要过一次，
它是按成功请求计费的，量不小。

**踩过的两个坑，别再踩**：

1. 🔴 **权限给了不等于能调。** 商品要单独开通，没开通时报的是
   `Code=408 · you haven't activated the commodity:lvwang_cip_public_cn`。
   这句话跟权限无关，**别去 RAM 里找问题**
2. 🔴 **必须用 POST。** 用 GET 调会回 `UnsupportedHTTPMethod` ——
   那个报错跟权限、跟开通都无关，2026-09-01 被它误导过一次

⚠️ 顺带一条给排错用的：这个接口**必须用 POST**。用 GET 调会回
`UnsupportedHTTPMethod`，那个报错跟权限、跟开通都无关 —— 2026-09-01 被它误导过一次。

### 凭证：RAM 用户 AccessKey，不用云账号 AccessKey

阿里云控制台在创建云账号（主账号）AccessKey 时会弹一段风险确认，那段提示是对的：
**云账号 AccessKey 有账号的全部权限，且没法收窄。**

所以这个项目用 **RAM 用户 AccessKey**，只授部署和运行要用到的权限。

- 存在 `backend/.env`，变量名 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
  —— 这是阿里云 SDK 默认读取的名字，别改
- `.env` 被根目录和 `backend/` 两层 `.gitignore` 挡着，且从未被 git 跟踪
- `.env.example` 里只留空值和申请入口

### 🔴 一个账号，不许跨账号

**服务器、OSS、内容安全、备案，四样全部落在同一个阿里云账号里** ——
作者本人的个人实名账号。

这不是整洁癖，是备案的硬约束：**买服务器的账号必须就是办备案的账号**。
两个账号不同就要走「服务码授权」，而**个人认证账号没有授权能力**（要企业认证）。
真去办企业认证，等于把 ADR-002 拼命甩掉的「借企业主体」原样请回来。

⚠️ **2026-09-01 真踩了一次**：先在 A 账号建了 RAM 用户、授了权、配进 `.env`，
之后才发现服务器买在 B 账号里。跨账号的 key 管不到那台机器，那一轮全作废。
**A 账号那个 RAM 用户已整个删除**（它的 key 还明文出现过在开发对话记录里，
删掉是一举两得）。现在的 key 建在 B 账号 —— 也就是有服务器的那个。

**教训写成一句**：动手建 RAM 用户之前，先确认服务器在哪个账号。

## 要注意的坑

1. 🔴 **ICP 备案跟着服务器走。** 备案要在**服务器所在的那家云**办。
   换到阿里云 = 备案在阿里云办，腾讯云那边的任何准备都作废（目前是零，所以无损失）
2. 🔴 **备案对服务器有硬门槛**（2026-09-01 核过官方文档）。阿里云要「备案服务码」，
   拿到它的条件是四条**同时**成立：

   | 条件 | 要求 |
   |---|---|
   | 计费方式 | **包年包月**。按量付费和抢占式实例**都不行** |
   | 时长 | **≥3 个月**（ECS 和轻量应用服务器同此。弹性 Web 托管要 ≥6 个月） |
   | 公网带宽 | 必须有。没有公网 IP 要先买带宽 |
   | 地域 | **中国大陆**。香港地域不行 |

   **买一个月的促销机器办不了备案** —— 这正是「便宜」和「能上线」打架的地方。
   已经买了一个月的话，**续费到累计满 3 个月**即可，不用退。
   服务码本身**免费**，一个 ECS 实例可申请 5 个。
   ⚠️ **备案成功后那个服务码就作废**，注销或取消接入之后也不能重复使用
3. 🔴 **备案账号必须就是买服务器的那个账号。** 两个账号不同时要「授权服务码」，
   而**个人认证账号没有授权能力**（要企业认证才行）。
   对这个项目就是一句话：**用同一个账号买服务器和办备案**
4. ⚠️ **ADR-002 里「不发短信验证码」那条的理由是腾讯云的资质政策**，
   引的是腾讯云 2025-09-18 那次调整。换到阿里云之后**那条理由的引证过期了**。
   ⚠️ **决定本身不变**（不发短信验证码），但 `CLAUDE.md`「身份与账号」那节里那句话
   现在是拿 A 家的政策解释 B 家的选择。真要发短信之前得重新核阿里云的口径。
   这一轮**没有改它** —— 决定没变，只是理由的出处要更新，不值得在这一轮顺手动
5. ⚠️ **`OBJECT_STORAGE_*` 那五个环境变量没有改名。** 它们是厂商中立的命名
   （`BASE_URL` / `BUCKET` / `REGION` / `KEY_ID` / `KEY_SECRET`），OSS 照样填得进去。
   **不为换厂商改一遍变量名**

## 认下的代价

1. **ADR-002 写了不到 48 小时就被改了一部分。** 这说明当时那个厂商选择是惯性不是决策 ——
   下次做基础设施选型，先花十分钟比价再写进「已定死的决策」
2. **腾讯云 TMS 那份接入调研白做了。** 损失很小（只是读了文档，没写代码）
3. **阿里云内容安全的开通条件是未知数。** 万一个人主体开通不了，
   这一项要退回腾讯云 TMS，变成两家混用 —— 那正是这次换厂商想避免的
4. **文档里「腾讯云」三个字还散落在几处历史文件里**（`ADR-002`、几份 handoff、
   `Archive/mini-program/`）。**这些是历史记录，故意不改** ——
   改掉就看不出决定是怎么变的了。当前有效的决策只看 `CLAUDE.md` 和这份 ADR
